# 全局常驻片段（可粘贴进项目的 CLAUDE.md / AGENTS.md）

> 用法：把下面代码块整段粘贴到你的 Agent 项目指令文件（CLAUDE.md / AGENTS.md）的末尾。
> 它是**常驻**的——不属于任何单个模块，不需要按会话粘贴。
> 注意：常驻片段不复制任何模块的规则正文（每条规则只有一个归属模块，避免重复与漂移）。

```text
## Agent 开发的五条常驻设计模式

- 提议者—审核者：产出与评判由不共享上下文的角色分别承担，评判方看产物本身
  （渲染结果、测试输出、结构化参数），不看产出方的推理过程；前提是自审不可靠。
- 渐进式披露：不把全部信息一次性塞进上下文，先给可检索目录、按需加载细节。
- 只增不改：状态以追加方式演进，已写下的内容不回头修改——换来可缓存、可重放、可审计；
  越靠前的改动作废的缓存越多。
- 边界集 + 保留集：任何一次修改都要同时在"应当改变的那批样本"和"不应影响的那批样本"上
  验证——只测前者会把过拟合当进步，只测后者会把无效修改当安全。
- 最小 diff + 可回滚：每次修改尽量小、带来源、可单独回滚，让归因成为可能
  （出了问题能定位到具体哪一次改动）。

## 安全组织口径（横切，不按模块划分）

- 安全关注点按三层护栏组织：上下文层 / 执行层 / 数据层。
- 护栏评估双向：既测"该拒的被拒"，也测"该放的能完成"。
- 先给 Agent 清晰目标、必要上下文与可组合工具；程序只固化必须始终成立的边界
  （权限、不得覆盖原始材料、原子发布）。只有业务约束本身要求、或评估反复暴露
  某类稳定失败时，才把该步骤升级为验证器、独立 Agent 或确定性流程。
```
