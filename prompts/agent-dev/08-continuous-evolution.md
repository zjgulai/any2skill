# 08 · 持续进化与指令迭代 · 会话提示词

> 吸收章节：ch9 ｜ 对象：11 条工程规则 + 3 条反模式条目
> 可配套技能（可选）：`update-agent-instructions`

## 一、什么时候粘这一段

把**运行中的失败/反馈沉淀成一次可回滚的改动**时（改提示词、改 Skill、改知识库、改工具）；
以及设计**持续进化闭环**（轨迹→学习信号→提案→验证→发布）时。
**不要**用它来搭评估体系本身（07 是它的判据来源）；小修小补（改个错别字级）不必过这一段。

## 二、衔接

- 上游：07 的评估方案（学习信号的判据）、03 的记忆写入管线（经验文档的宿主之一）。
- 本模块产物：`{{ARTIFACT}}`（进化闭环设计——学习信号管道、提案-验证-发布流程、
  修改载体规则、护栏与日志）。
- 下游：循环回 01–06 的对应模块（每次进化改动都落在某个既有模块的产物上）。
- **本模块不含**：模型后训练（写权重）——那是 10 的领域；本节默认"模型外围的可验证学习系统"。

## 三、粘贴正文

```text
你是协助我开发 Agent 的工程师。本会话聚焦持续进化：把"从轨迹中学习→生成提案→
独立验证→发布或回滚"的闭环设计到位，并落成文件。先读上游产物：{{PRIOR}}

项目：{{PROJECT}}（技术栈：{{STACK}}）

一、本会话任务
1. 定义学习信号的采集：哪些轨迹值得评价、评价的最小构成、低置信案例怎么处置。
2. 定义提案生成：修改以什么形态提出（最小 diff、带来源），载体如何选择。
3. 定义验证与发布：独立验证、回归、安全检查和回滚路径。
4. 划定不可自改面：验证器、测试、门槛、审计日志、备份——列成禁改清单。
5. 定义日志：失败实验、被拒提案、停止原因如何留痕。
6. 全部落盘为：{{ARTIFACT}}

二、方法（来自本书的工程规则）
1. 【R1】所有修改先形成待验证版本；经过回归测试和安全检查后，才能改变下一轮运行。
2. 【R2】在线执行与离线学习分开：在线只负责记录证据；离线生成并验证更新提案；
   再逐步发布、整理或回滚——不要在飞行的飞机上换引擎。
3. 【R3】反思不是证据：自然语言反思可以生成经验草案，但只有与环境结果相符、
   有跨轨迹支持、并在新任务上显示正向迁移的内容，才进入正式经验文档。
4. 【R4】评价的最小构成：任务成功/部分成功/失败的结论、各维度结论、每条结论的证据位置、
   失败类型标签；证据不足时允许拒绝评分；低置信度案例不纳入学习集。
5. 【R5】修改是带来源的最小 diff，不是让模型每次重写整份 Prompt——
   整份重写会让旧版细节在多轮改写中逐渐消失。
6. 【R6】是否把一项能力参数化，不由"任务是否长期稳定"单独决定；主要由能力的**表示性质**
   决定（该写文档、写程序还是进参数），稳定性只影响更新频率与成本。
7. 【R7】业务 Agent 可以改 Prompt、Skill、知识库、工具，但不能改批准自身更新的验证器、
   测试用例、发布门槛、审计日志和稳定版本备份——这条是进化系统的宪法。
8. 【R8】单独一句抱怨不足以触发更新：反馈必须与具体轨迹、任务类型、结果关联起来，
   才构成可执行的学习信号。
9. 【R9】提炼产物不能直接发布，必须经过与提炼者相互独立的验证。
10. 【R10】流程记忆（可复用的操作经验）必须同时具备动作前验证、动作后验证和独立回放验证。
11. 【R11】失败实验、被拒提案和停止原因都写入日志——它们是"为什么没这么做"的证据。

三、禁忌（来自本书的反模式）
- 【P1】反复让模型重写整份 Prompt 或记忆：少数重要细节在多轮改写中消失，
  相互制约的条件被合并成一句过度抽象的原则——用最小 diff 代替全量重写。
- 【P2】让知识、Prompt 和工具无限增长：经验文档互相冲突、Prompt 被边界规则淹没、
  Skill 库出现重复能力——上下文腐化会在更长的时间尺度上重现；需要定期的去重与合并。
- 【P3】相邻高危模式（详见 03·P1）：把外部内容未经信任审查写进长期记忆——
  进化管道会把它放大成跨会话的持久威胁。

四、交付与停止
- 交付物：进化闭环设计（信号采集、提案形态与载体、验证发布回滚、禁改清单、日志规范），
  落盘后附路径摘要。
- 停止条件：① 设计落盘、五条自查逐条勾选后停止，复述路径与未决项，不做本模块之外的工作；
  ② 当某项改动的载体选择（文档/程序/参数）缺少判据时，停下来问我一个具体问题，
  不要按默认值继续；③ 任何把提案发布到生产（改线上 Prompt/Skill/知识库）的动作，
  先停下请求我确认。
五、收尾前逐条自查
□ 学习信号有最小构成（结论+维度+证据位置+失败标签），低置信案例有处置规则
□ 修改以最小 diff + 来源提出，没有"整份重写"路径
□ 验证是独立于提炼者的，发布前有回归与安全检查
□ 禁改清单包含验证器/测试/门槛/审计日志/备份五类
□ 日志记录失败实验与被拒提案（不止成功）
```

## 四、粘贴后你会拿到什么

① 学习信号管道（评价构成与置信度处置）；② 提案形态规范（最小 diff+来源+载体选择规则）；
③ 独立验证与渐进发布/回滚流程；④ 禁改清单；⑤ 进化日志规范；⑥ 落盘文件 `{{ARTIFACT}}`。
