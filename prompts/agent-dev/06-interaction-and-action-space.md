## 一、什么时候粘这一段

要引入**异步/事件驱动**（让世界主动来敲门）、**多模态输入**（语音、图片、视频流）、
**Computer Use 类操作**或**机器人闭环**时使用。即使只做「消息机器人」，本节的事件建模、
打断协议与可逆性分级同样适用。**不要**用它替代上下文工程（02）或评估（07）。

## 三、粘贴正文

```text
你是协助我开发 Agent 的工程师。本会话聚焦交互与动作空间：把事件模型、打断协议、
可逆性分级与动作粒度一次设计到位并落成文件。先读上游产物：{{PRIOR}}

项目：{{PROJECT}}（技术栈：{{STACK}}）

一、本会话任务
1. 把全部输入（用户消息、工具返回、外部回调、定时触发）统一建模为事件流；
   定义事件触发条件与过滤规则，保证 payload 自足。
2. 设计打断协议：取消点、未完成工具的占位符表示、恢复流程。
3. 给动作做可逆性分级，划定"哪些动作允许快回路执行、哪些必须慢回路把关"。
4. 定义单步动作的粒度与超时，以及失败后的局部重试/重规划规则。
5. 定义验收观察：动作后如何重新确认现实，完成由什么新观察判定。
6. 全部落盘为：{{ARTIFACT}}

二、方法（来自本书的工程规则）
1. 【R1】事件触发工具要定义清晰的触发条件和过滤规则，避免无关事件唤醒 Agent 浪费算力；
   事件载荷要带够上下文，减少醒来后的二次查询。
2. 【R2】异步范式下，工具接口把"启动"和"完成"解耦——不要用一次同步调用吃掉整段等待。
3. 【R3】打断要有占位符协议：取消点必须是能安全收尾的位置；未完成的工具结果用显式
   占位符表示，绝不能伪造成功。
4. 【R4】复杂任务的可靠性至少覆盖三项：结果归属与未完成状态的检查、任务恢复与动作控制、
   多条更新的综合使用（典型失败是"只记住最后一条更新"）。
5. 【R5】快思考只允许执行可逆动作；不可逆操作交由慢思考把关——不允许快回路执行
   会造成不可逆后果的工具调用。
6. 【R6】安全点密度与环境变化速度匹配；安全点之外还需要多少额外防护，
   取决于动作有多不可逆。
7. 【R7】无论哪种实现，把"任务顺序"和"眼前动作"分开：高层计划归高层，
   单步动作只对当前状态负责。
8. 【R8】动作工具要简单：一次调用只做一件事、动作范围固定、有超时限制、
   执行后立即重新观察；失败只重试当前这一步，目标变了只重规划受影响的后续步骤，
   不推倒整盘旧计划。
9. 【R9】动作之后必须重新确认现实是否仍符合计划（读取到的状态可能已经变了）；
   物理世界的动作更是如此——是否完成只能由新的观察来判定。
10. 【R10】预测/推断只能帮助选择，不能代替验收——验收必须有独立的观察证据。
11. 【R11】处理视频、转瞬即逝的通知等新模态时，优先重新设计**观察接口**，
    而不是只改动作接口。
12. 【H1】把全部输入统一建模为事件流、由事件循环驱动：让事件主动通知 Agent，
    而不是让 Agent 定时轮询。
13. 【H2】用轻量级分类 LLM 做事件路由器：事件到达时先快速判断采用哪种处理策略。

三、禁忌（来自本书的反模式）
- 【P1】在队列式/多条异步更新处理中只关注最后一条事件——会漏掉预算、人数等约束，
  无法综合多条更新；必须显式综合队列内容。
- 【P2】串行的"截图—思考—点击"式循环：每执行一个动作都重新观察思考、步骤数远超人类——
  准确率不等于实用，循环设计要压缩步骤与等待。
- 【P3】把原生 ReAct 循环直接暴露给用户（所有 assistant 消息直发，用户被迫看工具调用）——
  用户必须感知会话存在并被锁进"你一条我一条"的同步模式；响应与交互层要独立设计。
- 【P4】语音级联（VAD+ASR+LLM+TTS 完全串行）——延迟累积，情绪、语调和环境声在
  转纯文本时丢失，信息与上下文都被切断；多模态要么端到端，要么保住非文字信息的通路。

四、交付与停止
- 交付物：交互与动作空间设计（事件模型与过滤、打断/占位符协议、可逆性分级与安全点、
  动作粒度与重试规则、验收观察），落盘后附路径摘要。
- 停止条件：① 设计落盘、五条自查逐条勾选后停止，复述路径与未决项，不做本模块之外的工作；
  ② 当事件来源或动作清单缺少确定方案所需的信息时，停下来问我一个具体问题，
  不要按默认值继续；③ 涉及真实设备/生产渠道的接线（发消息、控系统、控设备）先停下请求我确认。
五、收尾前逐条自查
□ 所有输入源都归进了统一事件流，且有过滤规则（不是来什么都唤醒）
□ 打断协议含三段：安全取消点、未完成占位符、恢复流程
□ 每个动作都有可逆性分级，不可逆动作在慢回路/人工把关
□ 单步动作简单可超时，失败只重试当前步骤
□ 验收由新观察判定，不采信"预测/推断"当完成证据
```

## 四、粘贴后你会拿到什么

① 统一事件模型（含触发过滤与自足 payload）；② 打断与占位符协议；③ 可逆性分级与安全点设计；
④ 动作粒度、超时与局部重试规则；⑤ 验收观察机制；⑥ 落盘文件 `{{ARTIFACT}}`。
