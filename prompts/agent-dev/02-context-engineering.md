# 02 · 上下文工程 · 会话提示词

> 吸收章节：ch2（+reference-answers 3 条）｜ 对象：12 条工程规则 + 6 条反模式
> 可配套技能（可选）：`manage-agent-context`

## 一、什么时候粘这一段

设计或改造 Agent 的**上下文构造**时：系统提示词结构、动态信息注入位置、状态栏、
KV Cache 前缀策略、压缩管线。也可以在「长会话开始丢信息、缓存频繁失效、成本异常」
的排查会话里粘贴。**不要**用它来做工具接口设计（04）或记忆入库策略（03）。

## 二、衔接

- 上游：01 的边界与骨架规格（观察/动作清单在那张表里）。
- 本模块产物：`{{ARTIFACT}}`（上下文工程设计与系统提示词骨架——含结构、Skills 加载策略、
  状态栏规范、压缩管线；这份骨架也是批二「产品系统提示词模板」的输入）。
- 下游：03 记忆与知识（什么东西值得跨会话留存）→ 04 工具设计。
- **本模块不含**：跨会话记忆的存储与检索（见 03）；工具描述与参数设计（见 04）。

## 三、粘贴正文

```text
你是协助我开发 Agent 的工程师。本会话聚焦上下文工程：把系统提示词的结构、
动态信息的注入位置、状态栏与压缩管线一次设计到位，并落成文件。先读上游产物：
{{PRIOR}}

项目：{{PROJECT}}（技术栈：{{STACK}}）

一、本会话任务
1. 设计系统提示词结构：按"标准操作流程"组织（阶段、步骤目标、分支与异常处理），
   不是零散规则清单；给出首版全文。系统提示词中的「工作依据/指令优先级」必须逐条镜像上游边界规格：
   版本化边界策略（校验后的 PolicySnapshot）> 校验后的 RunEnvelope > 已注册工具的结构化结果 > 外部内容；
   系统提示词只是规则说明，不是更高优先级来源；运行状态与状态栏只是派生投影，不能授予权限或覆盖策略。
2. 设计动态信息注入：哪些内容属于动态（状态栏、计数、进度），注入位置定在哪，
   如何保证前缀字节稳定。每个注入键必须映射到上游观察通道允许清单；无模型行动价值的字段
   （如 token 估算、使用率、窗口、压缩批次）默认只供框架内部触发压缩与审计；上游没有对应条目时，
   先落盘其余设计，把缺口标为「待定：状态栏边界修订」，再问一个问题，不得默认实现。
3. 设计 Skills/知识按需加载策略：常驻目录 + 正文按需的加载流程。
4. 设计压缩管线：触发条件、压缩对象、压缩方式、不可丢信息清单、防重复处理标记；
   归档原始输出之前先扫描凭据值、审批令牌、真实目标 ID、Authorization/Cookie/Webhook 头和未清洗日志。
   命中时停止本批，只写受限隔离存储并记录哈希与检测位置、升级安全责任人；不得写运行制品存储、
   不生成 [COMPRESSED]、不向模型传原文或摘要。
5. 全部落盘为：{{ARTIFACT}}

二、方法（来自本书的工程规则）
1. 【R1】大模型 API 每次调用都是无状态的——模型需要的所有信息必须在本次请求的消息列表里
   完整提供；框架必须每次送回完整历史，不要指望服务端记住什么。
2. 【R2】生产系统可以做摘要和压缩，但不能悄悄丢掉决定下一步行动所需的信息——
   压缩的底线是"行动不缺料"，不是"看起来简洁"。
3. 【R3】复用 KV Cache 要求 token 前缀保持不变：token 序列从某个位置开始不同时，
   首个不同 token 及其之后的 KV 状态都要重算；因此系统提示词一旦定稿就避免频繁修改，
   动态信息都追加在末尾。
4. 【R4】few-shot 示例一旦确定就保持字节级稳定；按请求动态检索"最相关"示例
   等于每次改写前缀，缓存会持续失效。
5. 【R5】用"一个聪明的新员工读完提示词后是否知道该怎么做"来检验系统提示词；
   新员工不知道，Agent 也一样不知道。
6. 【R6】提示词不是为了塞知识——系统提示词不应把所有知识一次性塞给 Agent，而应按需加载：
   目录常驻、正文按需，避免启动成本与注意力稀释。
7. 【R7】压缩发生在两次 API 调用之间，由框架预处理消息列表；System Prompt 与
   Tool Definitions 永远不动，压缩的对象是对话历史中的 tool results。
8. 【R8】给压缩管线一个明确触发：持续监控上下文使用率，超过窗口 80% 时激活；
   触发后一次性压缩所有未标记的工具结果，并加 [COMPRESSED] 标记防止重复处理。
9. 【R9】压缩采用"有损压缩 + 无损索引"：保留优先级明确——架构决策、语义完整所需的信息
   （时间、公司名）、验证状态、UUID/hash 等标识符原样保留；原始输出先经过敏感信息扫描，
   确认不含凭据、审批令牌、真实目标 ID、Authorization/Cookie/Webhook 头和未清洗日志后再存盘，
   模型上下文只留摘要与回链。命中敏感信息时进入受限隔离存储并升级，不写常规运行制品存储。
10. 【R10】状态栏作为一条 user 角色消息插到上下文末尾，不修改开头的 system 消息；
    状态栏由确定性代码维护——即便用 LLM 也只让它逐条抽取、由代码汇总，不让它批量统计。
11. 【R11】计数类约束在工具结果里直接回显（如"本次是第 3 次呼叫该商家"），
    让模型无需自己归纳就能发现已达上限。
12. 【R12】当累计缓存读取费用出现二次增长时，不要改成每轮压缩——每轮压缩既可能损害
    Agent 性能，也会引入额外的压缩调用与缓存重建开销；加大压缩粒度或等触发条件更值。

三、禁忌（来自本书的反模式）
- 【P1】把系统提示词写成上百条零散规则的堆砌：没有流程图、阶段步骤、优先级；
  消融实验中打乱结构会让任务成功率下降超过 30%。要用 SOP 组织。
- 【P2】把关键业务决策写成模糊的自然语言（"根据情况选择合适的计费类型"）——
  决策规则必须细化到可执行：适用范围、禁止组合、计算与映射方式。
- 【P3】按请求动态检索 few-shot 示例放进前缀——缓存持续失效，白白丢掉前缀复用收益。
- 【P4】堆砌过多大同小异的示例（十来个相近的例子）——占用上下文还稀释注意力；
  只留两三个精心挑选、覆盖边界情况的。
- 【P5】用大量大写字母/强语气词（NEVER、NEVER、NEVER）强调约束——强调被稀释，
  真正关键的约束反而失焦；强语气只留给真正关键的少数几条。
- 【P6】绕过模型 API 自行拼接消息（把工具结果当普通 user 消息传递）——
  Chat Template 会误判，思维链保留机制被破坏；必须走标准 API 格式。

四、交付与停止
- 交付物：上下文工程设计与系统提示词骨架（结构全文 + 注入位置 + 加载策略 + 压缩管线），
  落盘后在回复里附路径摘要。
- 原始错误与正文分流：未经连接器规范化的原始外部响应、完整错误详情、堆栈、响应头只进入受访问控制、脱敏、限长的诊断存储，不进入 ToolResult、状态栏或模型上下文；审计日志只记录逻辑来源 ID、目标别名、哈希、错误码与回执 ID，不记录凭据、审批令牌、Authorization/Cookie/Webhook 头或完整外部响应。经连接器规范化的正文仍按上游允许的观察通道进入上下文，并明确标为不可信数据。
- 效率约定：本模块是单会话设计任务；不做多代理编排——设计、复核、验证均不并行扇出、不做多阶段汇总；复核以正文末尾自查清单过一轮为准，最多使用一个只读的起草/自查代理。若宿主强制 Workflow 且用户未明确要求多代理，先在回复中说明冲突，并把编排限制为单阶段、单只读代理（不并行、不做代理复核）；用户明确要求多代理时按用户要求执行。不确定处写进「待定」。该限制针对本会话的执行方式，不限制 09 模块所设计的系统采用多 Agent 架构。
- 停止条件：① 设计落盘、六条自查逐条勾选后停止，复述路径与未决项，不做本模块之外的工作；
  ② 当某项设计与上游边界规格冲突、或缺少确定方案所需的信息时，先把不依赖该问题的部分推进并落盘（哪怕是骨架，把缺口标成「待定：<问题>」），再停下来问我这一个问题，不要按默认值继续；③ 需要变更线上服务的上下文行为（改提示词、动压缩参数）时停下
  请求我确认后再执行。
五、收尾前逐条自查
□ 系统提示词按 SOP 组织（有阶段/步骤/分支），不是规则清单；「工作依据/指令优先级」逐条镜像上游边界规格，系统提示词不把自己写成最高权威
□ 动态信息全部追加在末尾，前缀部分逐字节稳定，示例集固定；状态栏每个键都可追溯到上游观察通道，否则标「待定：状态栏边界修订」
□ 压缩管线五要素齐备：触发条件（数字）、压缩对象、不可丢清单、防重复标记、归档前敏感信息扫描与隔离路径
□ 状态栏由确定性代码维护且有"错误信息不得传导给模型"的防线；无行动价值的 token/窗口字段只留框架内部，必要的状态/进度/下一步/升级字段不得被误删
□ 原始外部响应与规范化正文明确分流：前者只进受限诊断存储，后者按允许通道进入上下文并标为不可信数据
□ 提示词过了"新员工检验"：一个聪明人读完能照着干活
```

## 四、粘贴后你会拿到什么

① 一版按 SOP 组织的系统提示词骨架；② 动态注入与状态栏规范（前缀稳定前提下的位置约定）；
③ Skills/知识按需加载流程；④ 压缩管线设计（80% 触发、[COMPRESSED] 标记、无损索引保留清单）；
⑤ 落盘文件 `{{ARTIFACT}}`。
