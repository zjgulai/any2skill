# 32：Agent 开发全程提示词包（从书萃取会话提示词）

**要构建什么：**把《AI Agent 书》的知识对象（604 条，含 14 条跨章合成反模式）
再萃取一层为**开发会话提示词**——用户开发自己 Agent 项目时，各阶段开工前直接粘贴的
单段完整提示词（角色→任务→书·硬约束→书·禁忌→交付/停止→自查清单）。

**状态：**完成（2026-10-16）。产物：`prompts/agent-dev/`（10 模块 + 00 使用说明 +
常驻片段 + 覆盖表 + 未入选清单 + 分桶文件）。

## 决策（与用户对齐）

1. **两者都要**：批一=开发会话提示词（本卡）；批二=产品 Agent 系统提示词模板（待细化）。
2. **模块口径**：生命周期重组 10 模块，每模块标注吸收的书章节。
3. **形态**：单段完整、可直接粘贴；正文硬上限 3200 字。
4. **生成方式**：会话内撰写、**零外部模型调用**；条目附来源对象 id。

## 方法（轻流程四步）

1. 分桶：`chapter→module` 映射 + AP-SYNTH 单一归属 + reference-answers 显式分配
   （`prompts/agent-dev/buckets.v1.json`）。
2. 撰写：按对象字段映射（appliesWhen→何时用；statement→硬约束；violation/pattern+harm→禁忌；
   corrective→正确做法）；`appliesWhen` <15 字的对象限定词**编辑补写**并标注。
3. 核对：逐模块覆盖表（`COVERAGE.md`）+ 引用 id 全量可解析 + 占位符出现次数=1。
4. 收尾：README/playbook 指路 + 一次提交。

## 试用记录与 v1.1（2026-10-16，headless 实测）

三场真实会话试用（`claude -p`，模拟项目「竞品情报日报 Agent」，fill 全部占位符）：

| 场次 | 模块 | 结果 | 成本 | 关键观察 |
|---|---|---|---|---|
| T1 | 01（v1.0） | **零产物**，问 1 个决策问题（审批机制 CLI vs 卡片回调，附推荐） | $3.43 / 30.5min | 遵守了「不确定型停止条件」；自我保护性地跑了 1 个复核工作流 |
| T2 | 02（v1.0） | **零产物**，要求整包「采集器输入合同」才继续 | $12.13 / 39.4min | 工作流结果未回传→重复启动→TaskStop 补锅（平台交付打嗝推高成本）；空夹具仓无采集器代码，其诉求部分正当 |
| T3 | 01（v1.1） | 未闭环（止损） | 未结算 | 工作流子代理 20:24 已完成且结果在 journal，但**平台未回传给主会话**，主代理空等 1 小时 |

**v1.1 修订（试用驱动）**：① 停止条件②改为「先落盘 + 待定」协议（两场零产物暂停的直接对策）；
② 新增「效率约定」行（限制自发多代理验证编队——两场 50–70% 成本在此）。

**混杂因素（如实标注）**：三场都自动加载了用户全局 `brainstorming` skill——其硬门禁
（设计未批准前不落盘）与 v1.0 措辞叠加，是「先问后写」的复合成因；T3 的 v1.1 效果因平台
交付故障未能取得直接证据。**结论：v1.1 有据可依、效果待交互式会话复验**（交互场景下用户
可即时回答，且工作流回传不涉及本次 headless 故障面）。可选后续：若仍希望会话先产草稿，
可在模块措辞中显式声明「本模块落盘物为设计文档、无需等待批准」——暂未加入，避免过度修正。
