# 08：回执的聚合、计数与拒绝理由码

**要构建什么：**把回执做成**可据以决策**的制品：拒绝理由能按类别计数，内容问题与工程问题能分开统计，全量对象可一次查询。

这一卡的判据不是「回执里有这个字段」，而是**它能不能回答具体问题**：「这批拒绝里有多少是提示词问题、多少是我把原文切错了？」做不到就只能靠通读判断，方案 R6（验证过严、误杀有效对象）也就无法被检出。

**被谁阻塞：**05（判定者判据的拒绝需先有理由码）、07

**状态：**ready-for-agent

- [ ] 回执含运行标识、源文件哈希、三段产物指针与计数、逐对象判定明细、拒绝项及理由码、判定者实例标识、第 2 层调用与 token 用量
- [ ] 拒绝理由码可区分**至少五类**：schema 不合规 / 标识符或锚点不可解析 / 源版本已变更 / 引文未逐字命中 / 判定者判为不支撑
- [ ] 五类理由码**互不混淆**：同一拒绝只归一类；每类有测试钉住其归类
- [ ] 按理由码可统计数量，且统计口径与逐条明细一致（复算一致，不靠人工核对）
- [ ] 回执可区分「有对象被拒」与「运行失败」两种非零退出，且两者各自可计数
- [ ] 全量对象可**一次查询**取到，不必打开每个中间文件
- [ ] 回执本身**体量可控**：不把全部对象正文复制进回执（避免回执变成第二个全文副本）
- [ ] 测试：对每一类理由码各注入一个 fixture，断言被归入正确类别且计数正确
- [ ] 测试：同时注入内容问题与工程问题，断言回执中两者可区分且互不污染
- [ ] 测试：复算统计口径，断言「按理由码统计的总数 = 逐条明细中该类的条数」
