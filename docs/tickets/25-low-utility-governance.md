# 25：低效用治理——降级动作的定义与「头差」实验

**要构建什么（目标）：**四波之后发布区 30 个 skill 里 **18 个 low-utility**
（第一源 3 + rust 15）。ADR-006 写下「标记低效用（不拒绝，但**降级**）」，
但**降级动作从未被定义**（第一源 backlog 原话）。本卡：把口径钉死，或立出第二个选择。

**本卡的三件事：**① 把 low-utility 的任务形状摊开（已做，见下）；② 用一个小实验检验
「无头差」的解释（v2 更难任务生成，2-3 个 skill）；③ 据结果定治理策略（选项见文末，需拍板）。

**状态：**进行中（2026-10-15）。

## 已做的分析（数据都在盘上）

**第二源 15 个 low-utility（90 个任务）**：0 改进；**≈77 个任务双过**（基座模型无 skill
也过）、13 个无效（双败）。**第一源 3 个 low-utility 同形**（无效 0–1）。
对照：8 个 passed 每个恰好靠 **1–2 个**「无臂败、有臂过」任务区分——**头差是稀缺品**。

**任务文本采样（ch10-03 生命周期，low-utility 典型）：** 6 个任务里 5 个双过——
写 `longest` 函数（书里的经典例子）、标注 `ImportantExcerpt`、诊断 dangling 引用、
**列出生命周期省略三条规则**（基座模型直接背出书的内容）、`'static` 字符串；
第 6 个（复杂签名的 `longest_with_announcement`）双败。

**两个互相竞争的解释：**

- **H1「训练数据重合」**：Rust 书内容在强模型训练分布内——从书上生成的常规任务，
  基座模型自己就会做，skill 没有可测的增量空间。若成立，「在这类源上测效用增量」
  本身是个低产出的测量设计；skill 的价值可能在其他轴（一致性/确定性引导/边界情形），
  而门禁三只测了「能力提升」一轴。
- **H2「任务生成器太温和」**：K=6 的任务以「自包含可验证」为先，天然偏向教科书式
  的干净场景；不含**易错细节**（而 skill 的陷阱段/规则段恰是为易错细节写的）。
  若成立，v2 任务生成（要求构造含易错细节的任务 + 检查单验证技能建议的具体做法）
  应能把头差推出来。

**两个解释的区分实验（本卡要跑的小实验）：** 选 2–3 个 low-utility（如 ch10-03 生命周期、
ch16-03 共享状态、ch05-03 方法语法），用 **v2 任务生成提示词**（唯一变量：要求任务包含
易错细节并让检查单锚定技能建议的具体做法）重跑 A/B（K=6）——
- 若 v2 下出现改进/退化不退化：H2 成立 → 治理策略 = 升级任务生成器 v2 + 重测存量；
- 若 v2 下仍全双过：H1 成立 → 治理策略 = 定义「降级」为如实披露 + 记录在案，
  并把「效用增量」从本项目对这类源的目标函数里**显式移除**（写进报告，不让它假装存在）。

**纪律声明：** v2 提示词会改变任务生成器指纹——实验用**单 skill 模式**（不写正式产物），
不改正式任务文件；实验数据（两臂结果逐条）进卡。v2 若转正，须按 ADR 先例立提示词版本并
为存量重测（那是转正后的独立工作，不在本实验内承诺）。

## 治理选项（实验后拍板用，预登记）

- **A. 降级=如实披露**：registry 增加 tier 记录（`low-utility` 清单）+ README 披露；
  skill 留在发布区，描述与正文不动。最小动作，诚实。
- **B. 降级=移出主区**：low-utility 迁往 `skills-provisional/`（或 registry/provisional/），
  主发布区只留 passed。动作大，影响既有引用与冻结面；但"发布区"的语义变强。
- **C. 重测机制**：定义 low-utility 的**重测资格与协议**（多大样本、几次、什么条件下
  改判）——若实验显示 K=6 的 n 不足以定论，这是第一条。
- （三者可组合；A 是底线，B/C 是加权项。）
