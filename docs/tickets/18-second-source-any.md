# 18：第二信息源验证「any」

**要构建什么：**把流水线从「只认这本书」改造为**认源键**，并用第二个信息源
（[`rust-lang-cn/book-cn`](https://github.com/rust-lang-cn/book-cn)，《Rust 程序设计语言》中文，
mdBook 结构）**分段实跑**，回答项目名的另一半：**any 是否成立**。
三类隐藏假设会被一次性打出来：**路径写死**（实测见下）、**结构粒度**（文件=章的假设）、
**领域迁移**（9 类对象与反模式在编程语言领域是否还有量）。

**为什么非独立不可（实测）：**

- 源路径写死清单（本轮侦察）：`build-skill.mjs` ×4（两个入口的 `sourceRel` 与 `codeRootRel`）、
  `anchor-index.mjs` 的 `DEFAULT_SOURCE_ROOT`、`propose-clusters.mjs` 的 `SOURCE_ROOT_REL`——
  全部指向 `sources/ai-agent-book-zh/`。第二个源在这些点上**必然撞墙**，而不是「可能撞墙」。
- 选 rust-cn 的刻意性：它是**节级粒度**（~100 个 .md，一个文件≈一小节，而第一源一个文件=一章）。
  「文件=章」的假设散布在回执身份、环 3 的章级聚类、环 4 的 code 镜像路径等环节——
  这套结构在第一源上从未被质疑过。
- 候选源侦察记录：`progit2-zh` 的正文是 **AsciiDoc**（`.asc`），解析器只认 markdown，**排除**；
  `hello-algo` 结构更接近第一源（章目录+md），作备选。

**被谁阻塞：**无（MVP 已收尾；上游仓库可达已验证）。

**状态：**三段全部完成（2026-10-14，记录在文末）。「any」实测结论：环 1–4 机制成立；发布门径对该源待配套素材（陷阱抽取/代码镜像）。

### 隔离（含两条方法错误自查与一次实测踩坑的完整留痕）

证据链修了三次，每步都如实记下：

1. **首轮账本 0 条**：ad-hoc 循环里四个子进程与外层共用同一 `DSH_FS_LEDGER` 路径，
   外层退出时覆盖了子进程账本 → **0 条不是证据、是方法错误**（本仓纪律原话）。
2. **重取时踩中 README 已记录在案的坑**：循环里漏了 `--layer2 deepseek`，缺省走 **stub 路径**
   ——stub 不检查已有产出，把 4 个真实对象文件覆写成了替身对象（README「运行」章警告过，
   本轮成为第二个实测案例）。**处置照 README 的恢复流程**：从 `knowledge/history/` 按内容
   恢复（恢复前核对归档版对象数与 deepseek 回执一致：29/17/3/6 全部对上），stub 版留档
   （`.stub-<sha8>.objects.json`）不删除；与回执一致性抽查通过（ch04-01 回执 17 verdicts ↔ 17 对象）。
3. **第三次用正确 flags**（带 `--layer2 deepseek`）：**真回放**——对象文件前后 sha 一致、
   stderr 有「产出固化」提示（回执输出的 `model.calls` 是产出它的那次运行的数字，不是本次的）；
   逐文件独立账本合并：**4 份 / 265 条 / benchmark 内容访问 0**，证据成立。

两条教训入陷阱清单：**绝不共用账本路径做循环运行**；**复核/重取运行必须显式带
`--layer2 deepseek`——stub 是缺省且会覆写真实产物**。

### 段③ 全链切片（ownership 章，**隔离仓库根**）

**为什么隔离**：环 3 的产物（`clusters.json`/`skill-candidates.json`）是**单源路径**——
在真实仓库里跑 rust 切片会覆写第一源的划分产物与冻结基线。切片整体跑在
`/tmp/rust-slice`（只放入 4 个切片文件 + 对应产物），第一源零接触。
**「产物按源命名空间」是本次实测出的后续卡议题，不是可以绕过的细节。**
