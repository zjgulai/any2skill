# 10：环 4 首版 + 门禁一 skill 侧（tracer bullet）

**要构建什么：**让链路第一次从对象走到 skill 成品——哪怕只走一次、只走一个簇。
本卡的目标**不是产出好 skill**，而是把项目最大的未验证假设变成可证伪的：
**「类型化知识对象能装配成可执行 skill」到底成不成立。**

**为什么这一卡非独立不可（实测）：**建仓至此，盘上 **0 个 SKILL.md**
（`find . -path ./node_modules -prune -o -name "SKILL.md" -print | wc -l` → 0）。
`benchmark/` 空目录、`skills/` 不存在、`clusters.json` / `skill-candidates.json` /
`promotions.json` 全缺。而 MVP 验收标准的**第 1 条**就是「一个 skill 从 `sources/`
正文到 `skills/` 成品」——它是 0%。环 1–2 与门禁一的内部精度被反复打磨，而被它们
服务的那件东西从未存在过一次。

**被谁阻塞：**04（要有对象）、07（要有一整章的对象）

**状态：**已交付（机制）；**产物被门禁拦下，未发布**

### 验收

- [x] 簇派生根植于文档结构（`level` + 文档顺序），不靠行号猜测
- [x] 装配是**纯函数**：同样输入产出逐字节相同的 markdown
- [x] **不编内容**：没有来源的段落留空，缺口写进契约的 `gaps`，正文里不得出现替代性文字
- [x] 只消费门禁一判过「通过」的对象；跨章反模式走**它自己那次运行**的判定表
- [x] 无判定回执时**拒绝装配**（「没有记录」≠「都通过了」）
- [x] 装配产物落暂存区 `pipeline/registry/build/`，**通过门禁才拷进 `skills/`**（ADR-002 平面隔离）
- [x] 门禁一 skill 侧 6 项：frontmatter 硬限 / 6 段骨架 / 段非空 / 段顺序 / 体积 ≤12 KB / 溯源可解析
- [x] 段条目数的**解释歧义**双口径实现（strict 与 presence-only），使「拒绝取决于口径还是内容」可分辨
- [x] 两类「静默空结果」改为抛错：对象文件形状不可识别、函数收到非数组
- [x] 测试 39 项，全部离线、零模型调用（全套 369 项通过）
- [x] **被测结论本身进测试**：断该产物在两种口径下都被拒，且拒因是「配套代码段为空」
- [ ] **发布**——未达成。门禁不通过，`skills/` 保持为空。

### 实测产出

簇 `chapter4#h2-2`（4 锚点 / 8 对象），产物 3,155 / 12,288 字节：

| 段 | 条目数 | 门禁 |
|---|---:|---|
| 何时使用 | 5 | 过（另记 1 条可疑条目） |
| 核心原则 | 3 | 过 |
| 实践模式 | 2 | 过（**语义不符**，计数查不出） |
| 常见陷阱 | 1 | **拒**：< 6 |
| 配套代码 | 0 | **拒**：空段 |
| 深度阅读 | 4 | 过 |

缺口 11 条（1 段无来源 + 7 个契约字段无来源 + 3 条语义/启发式）。
**替换成宽松口径仍不通过**——配套代码那一条与条目数无关。
