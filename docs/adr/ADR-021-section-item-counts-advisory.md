# ADR-021 · 骨架条目数降为建议值，低覆盖改为高风险路由

- 状态：已接受
- 日期：2026-10-09
- 决策者：用户（在三个方案中拍板「修订 ADR-004：把条目数降为建议值，并新写一条下限」）
- 关联：ADR-004（骨架）、ADR-006（三道门禁）、ADR-019（环 4 首版）、ADR-020（信息源扩充）

## 背景

ADR-019 的 tracer bullet 把门禁结论逼到只剩一条拒因：`SECTION_COUNT_OUT_OF_RANGE`——
`## 常见陷阱` 段实际 1 条，而 ADR-004 记的骨架形状是「6–8 条」。

这处判据来自哪里，值得说清楚。ADR-006 把门禁一第 5 项写作「6 段骨架**完整性**（ADR-004）」，
而 ADR-004 的「必须遵守的约束」一节**只**列了三项：frontmatter 硬限、6 段顺序与名称、
深度阅读回链。「何时使用 5–8 条」「常见陷阱 6–8 条」这两句出现在**形状描述**里。

把它当硬判据，是 ADR-019 实现时的解释（文件头当时也写明了「属于本文件的解释」），
不是契约原文。

实测把这个解释推翻了。对 chapter4 每个二级锚点簇与整章统计「可用反模式数」
（簇内 `AntiPattern` + 引用了本簇锚点且门禁通过了的跨章 `AntiPattern`）：

| 簇 | 对象数 | 簇内 AP | 跨章 AP（通过） | 合计 | ≥6？ |
|---|---:|---:|---:|---:|---|
| h2-1 工具的分类 | 2 | 0 | 0 | 0 | 否 |
| h2-2 工具设计的通用原则 | 8 | 1 | 0 | 1 | 否 |
| h2-3 工具生态 | 2 | 0 | 0 | 0 | 否 |
| h2-4 工具太多怎么办 | 8 | 1 | 0 | 1 | 否 |
| h2-5 感知工具 | 9 | 0 | 0 | 0 | 否 |
| h2-6 执行工具 | 2 | 0 | 2 | 2 | 否 |
| h2-7 协作工具 | 2 | 0 | 0 | 0 | 否 |
| h2-8 本章小结 | 2 | 0 | 0 | 0 | 否 |
| h2-9 思考题 | 2 | 1 | 0 | 1 | 否 |
| **整章 chapter4** | **39** | **3** | **2** | **5** | **否** |

**没有任何簇能到 6，整章也只有 5。** 而 6–8 这个数字出自原书作者的人工写作——
他每章约 2.2 个 skill、且可跨章取用，这是自动提取达不到的量级。
换言之，把 6–8 当硬判据，等于要求流水线做到作者人工综合的水平，
而那个水平恰恰是本项目**尚待证明能达到**的东西。

## 决策

**1. 骨架记录的建议值降为**建议值**，不再作为门禁一的判据。**

`SKELETON_SECTIONS` 的字段由 `minItems`/`maxItems` 更名为 `advisoryMin`/`advisoryMax`。
低于建议值会被记成缺口（`SECTION_ITEM_COUNT_BELOW_ADVISORY`）并推出风险标记，
**不产生任何拒因**。

**2. 硬下限只有一个：「非空」，且不新设数字阈值。**

常量 `SECTION_HARD_LOWER_BOUND = 1`，由门禁的 `SECTION_EMPTY` 承担。
**刻意不填一个更大的数字**——除原书的人工样本外，没有任何独立证据支持某个具体下限
（2 条还是 3 条都不能说清理由），硬填一个数字只是为了让它看起来严谨。

**3. 覆盖不足改走 ADR-006 门禁三的高风险路由。**

ADR-006 门禁三原文写着：「范围：MVP 阶段对每个高风险 skill 抽样，**不要求全量**。
高风险定义为门禁二出现误触发、**或 `AntiPattern` 覆盖率低的 skill**。」

这条定义**早就存在**，但从没接上：覆盖率不足此前被门禁一硬拒，于是门禁三的
「高风险标记」这一环永远收不到东西。本次把两处接上——装配器由缺口推出
`riskFlags`（`PITFALL_COVERAGE_BELOW_ADVISORY`），写进契约侧车，
按 ADR-006 路由到门禁三的抽样重点。**这不是新造的机制，是让一条既有决策第一次生效。**

**4. 与条目数无关的那条判据保留。**

契约侧车记录的条目数必须与正文实际一致，不一致即拒。
它防的是「契约说 6 条、正文写 1 条」——与条目数够不够是两回事。

**5. 双口径开关作废。**

ADR-019 为实现「拒绝是否取决于条目数解释」而加的 `SECTION_COUNT_POLICIES`
（strict / presence-only）随本次定夺一并移除。留一个不再改变任何结论的开关，
只会让后来者以为它还有用。

## 后果

**正面**

- 门禁一第一次**全部通过**，`skills/chapter4-tool-design-principles/SKILL.md`
  成为本仓第一个发布的 skill（此前全盘 SKILL.md 计数为 0）。
- 覆盖不足不再消失、也不再堵死链路，而是变成一条**有去向**的记录——
  它指向门禁三，正是能真正判断「这个 skill 有没有用」的地方。
- 判据与建议值分了家：「该做到什么」（建议）与「不做到就不许发布」（判据）
  此前混在一个字段里，是实现把它们当成同一件事才导致的。

**负面 / 代价**

- 一个 1 条反模式的 skill 现在可以发布。它的披露方式从「被拒」变成
  「契约里带风险标记」，因此**读契约的人有责任看 `riskFlags`**。
  门禁三尚未构建，在那之前这条风险标记实际上**没有下游消费者**——
  这是本次修订留下的真实暴露面，不该被「门禁通过了」这句话掩盖。
- 「常见陷阱 6–8 条」这个来自 22/22 实测的形状描述，在自动产出上被证明达不到。
  它现在只作为建议值保留，意味着**本项目与原书 skill 在这一段长度上会有可见差距**，
  而这个差距不能靠调提示词解决（见「未决」）。

**必须遵守的约束**

- 不得因为「改了会让门禁通过」而调整建议值——建议值取自 ADR-004 的实测记录，
  不随产出波动。
- 风险标记必须随契约落盘、进回执，不得只打在日志里。

## 未决

- **反模式产出量本身**：本主题（工具设计）在跨章池里可用 0 条——引用了本簇的
  `AP-SYNTH-T02-03` 与 `AP-SYNTH-T02-04` **两条都被判 `JUDGE_INSUFFICIENT`**。
  这说明瓶颈可能不在「够不够」而在**跨章综合的引文充分性**，属提示词或判据问题，
  本次未处理。
- **门禁三未构建**，故风险标记当前无下游消费者（见「负面」）。
- 其余各章未做同类统计，本表的边界是 **chapter4 与跨章反模式池**，不是全书。
