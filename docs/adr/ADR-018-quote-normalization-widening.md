# ADR-018 · 引文判据的归一化扩到「渲染后不可见的标记 + 空白」

- 状态：已采纳（2026-10-09）
- 触发：卡 07 之后用**当前提示词**重产 chapter4，暴露出 2 条 `QUOTE_MISMATCH`
- 影响面：`pipeline/tools/verifier.mjs` 的 `normalizeForQuoteComparison` 与新增的
  `quoteHitsRegion`；`PIPELINE_VERSION` 6 → 7；`QUOTE_NORMALIZATION` 的取值
  （它进回执，因此旧回执的口径与新回执可区分）

---

## 决策

**归一化从「忽略 markdown 强调标记 + 折叠空白」扩到「忽略渲染后不可见的四类标记 + 空白整体忽略」：**

| 类 | 源（markdown） | 模型复述（渲染后） | 实测条数 |
|---|---|---|---|
| 强调标记 | `**破坏 KV Cache**` | `破坏 KV Cache` | 9（票据 04） |
| 引用块标记 | `> **实验组**：` | `实验组：` | 1 |
| 行内代码标记 | `` `tool_search` `` | `tool_search` | 2 |
| 反斜杠转义 | `\u201c` | `\\u201c` | 1 |
| 空白 | 空行分段 / 强调标记后的空格 | 直接接上 | 9 |

**空白是整体忽略的，不区分换行与行内空格。** 用户从三个候选口径里选了这一条，
理由是「换行处的空白可省、行内空白不可省」这条界线在中文正文里无法辩护。

**有意不放宽的一类：中文弯引号 ↔ ASCII 直引号。** 那是字符替换而非零宽差异，
风险与「剥下划线」同类（verifier 早已明确拒绝后者）。同一批测量里有 2 条属于此类，
**至今仍被拒**——这是保留的判据强度，不是漏网。

---

## 依据：一份可复算的全量归因，而不是一章的样本

票据 04 当年放宽 `**` 时，样本是「两轮 chapter4 的 9 条拒绝」。这次不再重复那个做法——
一章、两轮、9 条，不足以支撑第二次放宽。改成的口径是：

> 取**盘上已有的全部对象产出**，对每一条被拒的引文**穷举补丁子集**，取能救回它的
> **最小子集**作为成因；救不回的，才叫「改写或编造」。

规模与结论（`node analysis/quote-gate-measure.mjs`）：

| 项 | 值 |
|---|---|
| 语料 | 12 份对象集（11 份 chapter4，来自 11 次真实运行 + 1 份跨章的 `antipatterns`） |
| 对象总数 | 398 |
| 原样命中（strict） | 360 |
| 旧归一化放过 | 23 |
| **被门禁拒绝** | **15（3.8%）** |
| **其中能用排版差异解释** | **15（全部）** |
| **救不回（真正的改写 / 编造）** | **0** |

成因分档：

| 成因（最小补丁子集） | 条数 | 只忽略空白能否救 | 只看换行能否救 |
|---|---|---|---|
| 空白 / 段落边界 | 9 | ✅ 9 | 8 |
| 行内代码标记 | 2 | — | — |
| 引用块标记 | 1 | — | — |
| 反斜杠转义 | 1 | — | — |
| 中文弯引号 → ASCII | 2 | — | — |

**改动后，现行判据在同一语料上的残留拒绝是 2 条**，正是有意不放宽的那一类。

### 语料边界（写清楚，免得读者高估这份测量）

1. **独立单位是运行，不是对象。** 同一对象 id 会在多份对象集里重复出现，
   398 个对象不等于 398 个独立样本；有效样本量是 12 次运行。
2. **盘上有产出的只有 chapter4 与 `antipatterns`**（后者跨 chapter1/2/4/6/7/9）。
   其余章在盘上只有索引、没有对象，因此未被覆盖。这不是「全书都验过了」。
3. **只测主引文**（`evidenceQuote` 对 `sourceRefs[0]`）。AntiPattern 的次级引文
   （`sourceRefs[n].quote`，verifier 走另一条 `refQuoteComparisons` 分支）不在本测量内。

---

## 为什么「0 条救不回」这个结果值得单独说

它意味着：**在这批语料上，这道门禁从来没有拦下过一条真正的改写或编造。**
这不等于门禁没用——它挡的是「出处对不上」，而那件事在本批语料里确实没有发生过；
但它让人无法再用「门禁会拦住改写」来为过严的归一化辩护。

因此本 ADR 的决策不是「放宽一点没关系」，而是：**在一个我们看不见质量损失的维度上
收紧，是有代价的；而代价已经量化成 15 条有效对象。**

## 放宽幅度的上界（实测钉住，不是承诺）

`pipeline/tools/test/verifier-quote.test.mjs` 逐条钉住以下行为，改判据会立刻变红：

- 下划线不碰：`web_search` 与 `websearch` 不得被视为同一段文字；
- 内部删掉任何一个非空白字 → 必被拒（扫描式验证，逐字符遍历）；
- 同义改写 → 必被拒；凭空编造 → 必被拒；
- 只有空白的引文 → 必被拒（见下）；
- 中文弯引号被替换成直引号 → 仍被拒。

## 一处必须在代码里堵住的坑：空串恒真

归一化会抹掉空白，于是「只有空白的引文」归一化后是 `''`，而 `haystack.includes('')`
**恒为真**——一条空白引文会被判成命中。这是往**放松**方向跑偏的静默失效，
因此在 verifier 里单列 `quoteHitsRegion`，显式要求归一化后的引文非空，
并由测试钉住。旧实现因为先判 `quote !== ''` 而未暴露，但它不是设计，是巧合。

## 复算口径（可复核，不必信任本文）

```
node analysis/quote-gate-measure.mjs          # 人读版
node analysis/quote-gate-measure.mjs --json   # 机器可读版（含逐条 failing 明细）
npm test                                       # 326 项，含放宽幅度上界的逐条钉板
node pipeline/run.mjs sources/ai-agent-book-zh/book/chapter4.md --layer2 deepseek \
  --llm-model deepseek-v4-pro --llm-base-url https://api.deepseek.com   # 零调用重判
```

判据逐条对齐 `verifier.mjs` 的 `checkDeterministic`，含一条容易被忽略的：
**对照文本取索引区间的正文，不采信对象自带行号**（`verifier.mjs:522–534`）。

`analysis/quote-gate-measure.mjs` 内留有一份**冻结的旧归一化**（`LEGACY_N0`）。
它必须冻结：本文件的用途是「这条判据当初误杀了多少」，直接 import 现行判据会让同一份
语料每次复算得到不同数字，证据就不可复核了。

## 更正记录（写在这里，而不是从正文里删掉）

本 ADR 的形成过程中，同一类错误出现了三次，都属「名字与实际不符」，且每次都直接
导致向上汇报的数字出错：

1. **`pureLineJoinOnly` 函数名撒谎**：实现是 `whitespace` 补丁（去掉**全部**空白），
   名字说的是「只把换行视为可删」。我据此告诉用户「9 条只需换行口径即可救回」，
   **实测只有 8 条**。已改名 `blankOnlySaves`，并另写一个真正只做换行口径的
   `lineBreakOnlySaves`。
2. **`lineBreakOnlySaves` 第一版又混入了引用块剥除**，于是把「`>` 标记」的功劳
   算到「换行」头上，仍报 9。已去掉该步骤。
3. **`quote-gate-measure.mjs` 的重复份数**因字段名写成 `duplicatedOf`（实际是
   `duplicateOf`）而被报成 0，实际是 5。计数本身没错（重复项未进统计），错的是那行摘要。

三处都是**我自己的工具**的缺陷，不是被测代码的缺陷；共同教训是：**给测量结果起名字时，
名字就是结论的一部分。** 因此本 ADR 里每个数字都附了它的判据定义，而不是只给结论。
