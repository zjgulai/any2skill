# ADR-025 · 段条目按种类计：`## 实践模式` 的一条 = 一个加粗小节头

- 状态：已接受（2026-10-12）
- 决策者：实现（就地修正一处判据解释；判据的目的与强度未变，证据如下可复算）
- 关联：ADR-004（骨架）、ADR-019（装配）、ADR-021（条目数不是判据）、ADR-024（环 3）、卡 11

## 背景

门禁一有一条**与条目数无关**的检查：契约记录的条目数必须与正文实际一致——
防的是「契约说 6 条、正文写 1 条」这类不一致（ADR-021 决策 4 明文保留）。
要执行它，双方必须对「一条」的定义一致。

旧口径是**通配**的：`itemCount = max(顶格 - 列表项数, 加粗行数)`。
这个口径在两段上各自成立（「核心原则」只有加粗头、「常见陷阱」只有列表项），
但在 `## 实践模式` 上失效——它的条目是**加粗小节头**（每个概念一个），
示例 `- ` 列表项是概念的**子行**。概念带多个示例时，列表项数量会盖过概念数。

2026-10-12 环 3 端到端（卡 11）第一次真实暴露：

```
node pipeline/build-skill.mjs --cluster chapter4-s1 --dry-run
→ 门禁 不通过(SECTION_COUNT_OUT_OF_RANGE)
   契约记录的条目数（3）与正文实际（10）不一致：## 实践模式
```

逐项实测：契约 3（概念数）/ 段内顶格列表项 10（示例总数）/ 加粗小节头 3。
**10 是示例，不是条目。** 已发布的 `chapter4-tool-design-principles` 之所以没踩到，
只是因为它那个簇恰好每个概念只有一个示例（2 概念 → 2 个列表项 → max 凑巧等于 2）。
换言之：这是一处**被更大的簇暴露出来的既有缺陷**，不是环 3 引入的新问题。

## 决策

**1. 每段的「条目种类」写进骨架：`SKELETON_SECTIONS[].itemKind`。**

| 段 | itemKind | 依据 |
|---|---|---|
| `## 何时使用` | `bullet` | 渲染为每条场景一个顶格 `- ` 行 |
| `## 核心原则` | `bold` | 渲染为每条规则一个 `**…**` 行 |
| `## 实践模式` | `bold` | 每个概念一个加粗小节头，示例是其子行 |
| `## 常见陷阱` | `bullet` | 每条反模式一个顶格 `- ` 行（后果/纠正是缩进子行） |
| `## 配套代码` | `bullet` | 每条指针一个顶格 `- ` 行 |
| `## 深度阅读` | `bullet` | 每条回链一个顶格 `- ` 行 |

**2. 校验器按 `itemKind` 计数；认不出种类的段落退回旧的 `max` 兜底。**

**3. 检查本身一字未动**：契约记录数仍必须与正文一致，不一致仍拒。
改的只是「一条」的定义——把通配口径换成显式口径。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 改渲染：把示例缩进成子行，让顶格列表项 = 概念数 | 用**排版**去迁就一个计数实现；且会改写全部未来产物的字节、已发布 skill 的复现也是另一串哈希。排版不该是判据的输入 |
| 让装配器按 `max` 口径记 `sectionCounts` | 契约数字变成渲染细节的因变量——契约不再是独立一侧，这条检查退化为恒真（自己和自己比） |
| 把 `## 实践模式` 从这条检查里豁免 | 丢掉「契约说 3 个概念、正文只渲染了 1 个」的检出能力——而那正是这条检查存在的理由 |

## 后果

**正面**

- 误报源移除（环 3 的簇第一次能通过门禁一）。
- 条目种类显式化：新增段落时，「一条是什么」必须写清楚，不能再靠 `max` 蒙。

**负面 / 代价**

- 若某段**天然混用**两种条目（既有加粗头、又有各自成条的列表），`itemKind` 表达不了，
  届时要再立判据——本 ADR 不为不存在的形状预先抽象。

**必须遵守的约束**

- 不得借本次修改放宽 `SECTION_EMPTY` 或建议值（`advisoryMin/Max`）的任何口径。
- 改动必须有**前后对照测试**：多示例不误报（新增）+ 丢一个概念仍被抓住（新增），
  见 `pipeline/tools/test/skill-gate.test.mjs`。

## 核实方式

```bash
cd /Users/lute/Project/any2skills

# 修复前：报 SECTION_COUNT_OUT_OF_RANGE（契约 3 / 正文实际 10）；修复后：不报

  const { splitSections } = await import("./pipeline/tools/verify-skill.mjs")
  const md = require("fs").readFileSync("skills/chapter4-tool-design-principles/SKILL.md","utf8")
  for (const s of splitSections(md)) if (s.heading === "## 实践模式") console.log("bullets", s.bullets, "bolds", s.bolds, "max", s.itemCount)
})'
# 已发布 skill：契约 2 / bullets 2 / bolds 2 —— 修复前后都通过（只是凑巧）
```
