# ADR-026 · 门禁二首版：场景生成与盲测分离、列表式回答、全量首跑

- 状态：已接受（2026-10-12）
- 决策者：用户（三处拍板；推荐出自卡 12 的设计，候选与被否决理由见下）
- 关联：ADR-006（门禁二定义与三条硬约束）、ADR-007（修正表）、ADR-004（粒度判据）、ADR-013/014（身份）、ADR-021（不设数字阈值）、ADR-024（未决 3 的 `promotionState` 状态机）、卡 12

## 背景

40 个技能候选已落盘（卡 11），但「它们找得到吗」至今没有任何机制回答。
`verify-skill.mjs` 明文划界：「合不合规」是门禁一；「有没有用」是门禁二/三。本 ADR 定**门禁二**的实现形态。

ADR-006 给门禁二三条硬约束，本 ADR 的设计必须**在机制上**满足，而不是靠约定：

1. 盲测者只给 `name` + `description`，**不提供正文、不提供技能清单**；
2. 盲测者必须是独立实例（构建者不得自评）；
3. 抽样必过（本 ADR 把首跑的「抽样」定为**全量**，理由见决策 3——争抢判定需要全场）。

## 决策

**1. 场景生成与盲测是两次分离的交互；场景集落盘并进身份。**

- **生成侧**（允许看到内容）：对每个候选，用它的对象内容（`sourceObjects`）生成
  **K=3** 个真实用户任务场景（应当触发该候选）；另生成 **20** 个无关场景（不应触发任何候选）。
- **盲测侧**（不得看到内容）：只见场景 + `name` + `description`。
- 场景集**落盘 + 哈希进身份**（同 theme-proposer 的立场：清单落盘是承重件）。
  生成模型与盲测模型**同为 deepseek-v4-pro**——同一个模型不同上下文，如实记录；
  论文的 extractor/consumer 不相关性指向的是不同**能力**配置，本轮不做跨模型对照。
- 拿候选自己的 `trigger` 当场景是**被否决的循环**：trigger 是题面（description）的一部分，
  等于用答案出题。

**2. 盲测者回答「哪些 skill 会被触发」——列表，可以为空。**

- 候选在题面中**乱序 + 不透出处的代号**（`k01…k40`），映射表留在盲测者之外：
  `chapter4-s1` 这种代号本身会泄露来源。
- 三类判定直读：
  - **命中** = 该候选的应触发场景里，它出现在列表里；
  - **零命中** = 它在自己全部应触发场景中都未被选中；
  - **争抢** = 同一场景列表长度 ≥2（或应触发者落选而场景被别的候选认领）。
- 单选 + `none` 的回答形态被否决：争抢只能跨题推断，不如列表直读。

**3. 首跑全量 40 个候选（40×3 + 20 = 140 次调用）。**

ADR-006 的「抽样」是对 MVP 成本的控制手段；但争抢判定的观测单位是**全场**——
抽样看不见「谁抢谁」。140 次调用的题面共享同一段候选目录前缀，走服务端提示缓存；
dry-run 先印真实字符数与预估，确认后再跑。

**4. 判定不设数字阈值；动作停在「清单」为止。**

- 命中率 / 误触发率**只报数字**（承 ADR-021：没有独立证据支持某个具体阈值，
  硬填一个数字只是让它看起来严谨）。
- ADR-007 修正表执行到**产出动作清单**为止：争抢组 → 建议合并哪些候选；
  零命中 → 建议并入哪家或降级为 `references/`；description 盖不住应触发场景 → 建议拆分。
  **本卡不自动改划分**——改划分是环 3 的动作（「退回环 3」），单独立卡执行。
- `promotionState` 增三态（命名可议）：`trigger-passed` / `trigger-conflict` / `trigger-miss`，
  补齐 ADR-024 未决 3 里门禁二那一段；误触发场景无条件给相关候选记入**高风险抽样清单**
  （ADR-021 的风险标记由此第一次有了下游：门禁二/三的抽样重点）。

**5. 盲测题面里的 `description` 由装配器离线生成（`buildDescription`），不另起炉灶。**

盲测看到的描述必须与发布产物携带的描述同源；手写一份「给盲测看的描述」会让两者漂移，
而漂移的方向总是对被测者有利。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 人工编写场景集 | 覆盖 40 个候选的工作量大，且难以避免无意中贴合若干 description——贴合本身就是泄漏 |
| 每候选只生成 1 个场景先跑 | 机制先行是对的，但 n=1 看不到争抢模式——而争抢正是本卡要交的三件事之一 |
| 单选 + 可答 `none` 的回答形态 | 争抢只能跨题推断；列表直读且不增加判据解释 |
| 抽样 15–20 个候选 | 争抢是**关系**判定，抽掉一半声部就听不到合唱；成本靠提示缓存压，不靠丢观测面 |
| 用候选 `trigger` 当场景 | 循环：trigger 是 description 的一部分，用答案出题 |
| 允许自动执行合并/降级 | 改划分是环 3 的动作（ADR-007 明文「退回环 3」）；门禁二报告与划分修改是两张卡 |
| 把门禁二做进装配器（`build-skill` 里顺手验证） | 违反 ADR-006 的独立执行者约束；且装配是逐候选触发，天然看不到全场争抢 |

## 后果

**正面**

- ADR-007 的修正回路第一次闭合：环 3 切 → 门禁二观测 → 动作清单 → （下一卡）重切。
- ADR-021 的风险标记第一次有真实下游。
- 「找不到」这一类缺陷（触发漏、触发冲突）从不可测变为可测、可留痕。

**负面 / 代价**

- 140 次调用的一次性成本；场景集质量直接决定报告质量（K=3 是 v1 的折中）。
- 生成侧与盲测侧同模型不同上下文——「独立性」是**上下文与信息**的独立，
  不是模型家族的独立；本轮如实记录，不作更强声明。

**必须遵守的约束**

- 盲测题面**只允许**包含：场景文本 + 乱序代号 + `name` + `description`。
  任何正文、对象、units、来源、编组信息的注入都使该次盲测作废——且必须有**可失败的反证测试**。
- 场景集与盲测报告的身份纪律照 ADR-013/014：同输入复用不重买；场景或描述变化 → 身份必变。
- 门禁二全程**不得读 `benchmark/`**（承 ADR-001/007）；账本检查照卡 09 的工具跑。
- 不设数字阈值；报告只报数字与清单。

## 未决

1. **三态命名**（`trigger-passed` / `trigger-conflict` / `trigger-miss`）与晋升回执
   （`promotions.json`）的写入时点——随门禁三落地一并定。
2. **K 与无关场景数的敏感性**：K=3/20 是 v1 的预算折中；首跑后按报告噪声情况再评估。
3. **跨模型独立性对照**（换一个模型当盲测者，看结论是否稳定）——本轮不做，记为后续。
4. **s4 类划分修正的执行**：门禁二报告出来后，「合并/降级」的执行清单另立卡。
