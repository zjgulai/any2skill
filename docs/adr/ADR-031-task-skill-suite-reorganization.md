# ADR-031 · 岗位技能套件重组：30→19、任务骨架与来源/编排分离、零继承迁移

- 状态：已接受（2026-10-15）
- 决策者：用户（拍板「重组为岗位技能体系」「多语言，按任务组织」「批准，直接全量」）
- 关联：ADR-004（原书六段骨架——**本 ADR 对**新套件**换骨架，旧套件归档保留原样**）、
  ADR-016（跨章反模式池）、ADR-030（重测协议与证据边界——本 ADR 沿用其精神）、
  ADR-002（发布/工作两平面）、`docs/tickets/26-task-skill-suite.md`（构建记录）、
  `pipeline/curation/task-skill-suite.v1.json`（套件清单：全部边界决策的落点）

## 背景

用户是 Agent 全栈工程师，对章节编号式的技能名与「概念+规则」式正文提出改进要求，并明确
选择**按岗位任务重组**（允许合并/拆分）。三个可核实的事实在卡 26 的探索阶段落定：

1. **两个 ch4 技能重复**：`chapter4-tool-design-principles` 的 8 个源对象全部包含于
   `chapter4-single-tool-design` 的 20 个之内，触发条件与陷阱也逐字重复——同触发词双技能
   是路由事故源；两技能另有 skillId 不同源的历史例外（`chapter4-s1` vs `CHAPTER4-H2-2-SKILL-01`）。
2. **大技能名不副实 / 一技能多主题**：chapter10-s3（协作编排名义，内含失败模式/理解债/
   文件系统）、chapter1-s1（边界名义，内含护栏）等，按名义检索找不到其内涵。
3. **机器契约全空**：7 个第一源发布物的 input/output/steps/tests 均为空——正文没有执行
   脚手架（输入/步骤/交付物/检查），"任务技能"无从谈起。

## 决策

**一、发布面从 30 个章节技能切换为 19 个任务技能**（8 个语言中立的 Agent 工程工作流 +
11 个显式标注 Rust 的实现工作流），外加一份不触发路由的岗位导航文档
（`docs/guides/agent-full-stack-skill-suite.md`）。数量由任务边界决定；每个旧发布物有
署名的去向（lineage 清单）。

**二、任务骨架六段**（新套件专用；旧六段骨架的发布物全部归档，两套骨架不互相迁移）：

```
## 何时使用 → ## 输入与前置条件 → ## 执行步骤 → ## 交付物 → ## 检查、停止与回滚 → ## 依据与边界
```

前五段来自 `pipeline/curation/workflows/<slug>.json`（**作者编写的编排**，文件层面与
来源分离）；第六段来自来源对象（**规则原文 + 陷阱原文 + 出处回链**）。Concept 对象不进
正文（留契约溯源）；正文面向执行，术语表会稀释步骤。该骨架的校验复用
`verify-skill.mjs`（骨架作参数）——两个套件共用一套校验器实现。

**三、来源对象的所有权 = 清单**。`pipeline/curation/task-skill-suite.v1.json` 为每个成员
声明**精确 owned 对象与跨章反模式**；测试钉住：主对象**两两不相交**、并集**等于**旧 30
契约去重并集（两源分别验：164/164、254/254）、每个 ID 可解析且过门禁一、两个 rejected
绝不出现。跨章反模式**允许跨成员共享**（旧版语义即如此，强制独占会删掉既有陷阱覆盖）——
与主对象的严格不相交刻意不同，写入测试注释。

**四、迁移 = 归档 + 零继承 + 无别名**：

- 旧 30 个目录**逐字节移入** `pipeline/registry/legacy-published/chapter-suite-v1/skills/`
  （移动后逐文件哈希复验）；旧契约、回执、门禁报告、tiers.json、历史冻结文件**一律不动**。
- `task-suite-lineage.v1.json`：30→19 的映射、逐文件哈希、每成员的对象/工作流哈希。
- `task-suite-status.v1.json`：`structuralGate: passed`；
  `triggerAssessment/utilityAssessment: unassessed-after-recomposition`——
  **不聚合、不继承**旧 passed/low-utility（门禁二/三的身份含名称/描述/正文哈希，重组
  使一切旧证据失效；沿用 ADR-030 的重测协议与「不允许把未测的轴写得像测过」）。
- **旧 slug 不留触发桩、不设别名**——旧路径不再可寻址是本次重组的目的；需要寻址旧物时
  走 lineage 清单。
- 付费重测（门禁二套件目录模式、门禁三对 19 个新发布物）**不由本 ADR 启动**，由用户
  显式发起；发起时须先立评估口径 ADR（任务骨架下的盲测与效用判定口径需要重新确认）。

**五、旧冻结的语义**：旧冻结文件保留在 registry（历史证据）；迁移后其对 `skills/**` 的
条目会显示 32 处漂移（30 个 SKILL.md + 2 个 references 文件**恰为被迁移的文件**，逐条核对），
这是**预期**且由 lineage 的归档哈希接管可证性。新冻结（250 文件）覆盖新发布面、curation
清单/工作流、lineage/status 与归档面。

## 追加记录（2026-10-16，卡 27/ADR-032 评测产出）

**本 ADR 正文一字未动，此处记录评测对套件边界的修订。**

1. **19 → 17（评测合并，用户拍板「两对都合，联名重写」）**：
   `define-agent-boundaries-and-safeguards` ← define + secure（strict 3/3 最强稳定边）；
   `coordinate-agent-work-and-verification` ← coordinate + verify（strict 2/1）。
   被并者逐字节归档 `legacy-published/task-suite-v1-premerge/`；两合并体的标题/描述
   按并集重写（编辑层修订，所有权来自机械配对）。
2. **17 → 15（两个确认负迁移下架）**：`implement-rust-state-pattern`、
   `match-rust-variants`（各 t6 复跑复现，ADR-006）→ `registry/rejected/`，
   所有权记录移入清单 `rejected` 段（并集/不相交校验覆盖全量，测试已更新）。
3. **最终发布面 15 个**：6 passed / 9 low-utility。触发面收敛数据与两源判定见
   `pipeline/registry/task-suite-assessment.v1.json` 与
   [`卡 27`](../tickets/27-task-suite-assessment.md)。
4. 「技能词汇覆盖任务字面」失效族在四个拒绝例上复现——修订方向记录在首个
   REJECTION.md（必读），修订与复评另立卡。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 只改名不重组（30 个一对一换标签） | 两个 ch4 技能同触发词的问题改名解决不了；一技能多主题的名字只会把不准确继续带着 |
| 保留旧六段骨架仅补 description | 输入/步骤/交付物无处安放（契约字段空转是实测事实）；"完善"落不了地 |
| 为旧 slug 生成跳转桩 | 会保留重复触发面，重组的意义（检索面收敛）被抵消 |
| 重组后聚合旧判定为「部分 passed」 | 违反 ADR-030 证据边界：新正文未测过，聚合即造假 |

## 后果

**正面**

- 发布面 30→19（−37%），同触发词重复与名不副实从名字与边界两侧同时解决；
  每个技能有输入/步骤/交付物/检查与显式边界，还有一份岗位导航文档按工作阶段分组。
- 零内容丢失**可机器验证**（并集相等 + 不相交 + 门禁可解析 + rejected 隔离），
  旧物可寻址可还原（逐字节归档 + lineage 哈希）。
- 「测试即规格」：`task-suite.test.mjs` 把边界决策钉成可执行断言；
  发布面校验改为**通用断言**（哈希一致 + 各自骨架过门禁一），比原先单 slug 断言更强。

**代价 / 限制**

- 19 个新发布物当前是「结构合规、效用未评」——**这是如实状态，不是缺陷**；重测前，
  它们与旧套件在此意义上同等：旧 passed 也不迁移。
- 任务骨架依赖**作者编写的步骤**（工作流文件）——它们是显式的编辑层，评审入口在
  curation 清单与工作流文件，不必读渲染产物猜边界。
- 门禁二对任务套件的目录模式实现与重测评估口径，推迟到重测发起时一并设计
  （卡 26 如实记录该缺口）。
