# ADR-024 · 环 3 首版：章内语义聚类、显式簇记录、环 4 按簇装配

- 状态：已接受（2026-10-12）
- 决策者：用户（三处拍板；推荐出自本轮设计，候选出自卡 11「构建前需拍板」）
- 关联：ADR-004（三层粒度）、ADR-007（划分原则）、ADR-013/014（身份与复用）、ADR-017（输入预算）、ADR-019（环 4 接口现状）、ADR-021（数字是建议值）、卡 11

## 背景

环 3 是链路里唯一没有实现的中段（环 5 除外）。实测地基（2026-10-12）：

- `clusters.json` 与 `skill-candidates.json` 在盘上**不存在**；环 4 的装配入口只认
  `--root-anchor`（一个文档子树），全盘唯一发布的 skill 是手工挑的 `chapter4#h2-2`——
  **「切哪里」这个决策至今没有机制产出**。
- 原料齐备：全书 604 个对象（通过 593），逐文件 5–82 条；
  单章全量序列化可到 **72,016 B**（chapter7，82 条；对象 p50 约 860 B）。
- ADR-007 已定**划分原则**（纯语义派生、数量是结果不是配额、门禁反向修正划分、
  必须记录聚类依据）；本 ADR 定的是**实现形态**。ADR-019 决策 2 声明过
  「环 4 的子树派生是机械近似，真正的语义聚类属环 3」——本 ADR 把那个「属环 3」兑现。

## 决策

**1. 聚类策略：章内 LLM + 章节骨架确定性。**

按章切分（上界 **13 个模型调用**），章内把对象压成「id + 类型 + 一句话主张 + 锚点」
喂给模型，产出「内容单元的合并/拆分 + 每单元的聚类依据」。
**跨章合并 v1 不做**——它是 ADR-007 留给门禁二「争抢」判定的修正对象，
没有样测反馈就预先合并，等于用猜测替代观察。

> **追加记录（2026-10-13，卡 13）**：本决策里「跨章合并 v1 不做、留给门禁二的样测反馈」
> 的**反馈已到、且已执行**——门禁二两读数的 87 个稳定对里含跨章对，用户拍板全量执行；
> 环 4 相应扩到多章候选（`loadClusterAssemblyInputs`；单章是长度为 1 的特例），
> 重切执行器与计划见 [`卡 13`](../../docs/tickets/13-ring3-resplit-from-gate2.md) 与
> `pipeline/registry/resplit-plan.json`。本 ADR 正文不改写，仅在此标注差异。
> 结果（门禁一判决）：合并候选 11 个中 1 通过（chapter4-s1，已重新发布）、
> 10 被拒（8 个体积超限、9 个缺配套代码来源）——合并在更大粒度上的两条既有约束
> 见卡 13 的判决表。

**2. 簇记录用显式锚点集与对象集；环 4 增「按簇装配」入口。**

环 3 的簇不保证与文档子树重合，因此**不要求簇向子树靠拢**（那会把划分捆在文档结构上，
与 ADR-007 的语义初衷相抵）。环 4 增一个按簇装配的入口（读 `clusters.json` 的簇定义），
**复用现有装配管线与门禁一**——「门禁一全量必过」的约束不因入口不同而改变。
本扩展在卡 11 内实现：没有它，「对象 → skill」的链路本轮仍然断着。

**3. 跨章综合物：v1 算结论落盘，不急于发布。**

14 条跨章 AntiPattern（含 7 条跨章）按 ADR-007 的既有约定处置：能被 **≥3 个独立场景**
触发且不属任何单章 → 独立成候选；否则分发进各 skill 的「常见陷阱」段。
v1 的交付物是**结论与依据落盘**；独立成候选那一支的「触发场景从哪来」与门禁二一起想清楚，
不抢在它前面发布。

**4. 身份与复用来照既有纪律，不另立一套。**

输入身份 = 对象集哈希 + 提示词指纹 + 模型（照 ADR-013/014）；提示词改动身份必变；
同输入复用不重买；单章超预算时的切分/降级策略照 ADR-017 的预算纪律实现并有测试。

**5. 数字一律是诊断量，不设阈值。**

内容单元 5–15 条、skill 3–8 个内容单元、2.2 skill/章——三个数字全部只出现在
**事后对照与偏差分析**里，不作为拒绝或停止条件（承 ADR-021 对 ADR-004 的修订立场：
形状描述里的数字不是判据）。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 全书一次调用完成聚类 | 输入大（59 万字节量级）、单点失败代价高；而 v1 用不上跨章合并——为一个用不上的能力付出集中式风险 |
| 纯确定性划分（先按文档子树/章节机械切） | 零模型成本，但 ADR-007 的核心能力（语义判断「是否回答同一类问题」）未被验证，等于把环 3 的问题推到下一轮 |
| 环 3 只出数据，环 4 接口扩展另立卡 | 优点是本卡更小；代价是「对象 → skill」的端到端在本轮仍不可证伪——而链路可证伪正是本项目反复用来定序的原则 |
| 要求簇必须与文档子树重合（不改环 4） | 实现最简，但把划分捆死在文档结构上，与 ADR-007 的语义初衷相抵；且子树边界由节标题决定，不是「问题空间」的自然边界 |
| 跨章物直接独立成候选发布 | 「触发场景从哪来」未验证，容易被门禁二判零命中；ADR-007 的约定里有前置条件（≥3 个独立场景），跳不过去 |
| 全部 14 条直接分发进陷阱段 | 丢掉了「跨章知识独立成包」这一支的可能性，而它正是 ADR-007 写明要按约定判一次的东西 |

## 后果

**正面**

- 链路中段补上后，门禁二第一次有**真实的划分**作被检验对象；ADR-007 的
  「门禁反向修正划分」从原则变成可执行回路。
- 簇记录显式化（锚点集 + 对象集 + 聚类依据）使划分**可复核**——ADR-007 的硬约束落地。
- 环 4 的入口从「人工挑子树」变为「消费划分产物」，tracer bullet 的手工性被消掉一次。

**负面 / 代价**

- 引入环 3 自己的模型调用（上界 13 次/轮），多一处花钱与失败模式；
  章内压缩会丢弃对象细节，聚类质量受摘要保真度限制。
- 两套入口（`--root-anchor` / 按簇）并存，环 4 表面积变大；
  但保留旧入口是刻意的——它是已知能过门禁一的参照路径。

**必须遵守的约束**

- 环 3 全程**不得读 `benchmark/`**（承 ADR-001/007）；隔离检查沿用卡 09 的账本工具跑一遍。
- 划分结果**必须记录聚类依据**（哪些对象、因何聚在一起），ADR-007 明文要求。
- **零静默丢弃**：每个门禁一通过的对象恰属于一个内容单元；未归类者进显式清单并带理由
  （口径同卡 09「一个都不静默跳过」）。
- `SkillCandidate` 字段名照 MVP 计划 §4.2（`skillId` / `sourceObjects[]` / `trigger` /
  `chapterRefs[]` / `promotionState`），不加私有别名。
- 数字不进任何判据（决策 5）。

## 未决

1. **跨章候选的触发场景来源**：与门禁二一起定（零命中判据先于发布）。
2. **簇记录的具体 schema 字段**：实现时定，卡 11 的验收负责钉住字段名与含义。
3. **`promotionState` 的状态机**：门禁二/三未建，v1 只定义字段与初值，
   状态迁移随环 5 落地时补。
4. **章内压缩的保真度**：一句话摘要会损失哪些信息、对聚类质量影响多大——
   本 ADR 不做预估，等首次真实运行的实测（若有明显误合，再评估是否加长摘要）。
