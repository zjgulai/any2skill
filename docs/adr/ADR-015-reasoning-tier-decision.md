# ADR-015 · 推理档位定档：两层都不拨档；以及一次被噪声带救回的错结论

- 状态：已接受（决策者：用户，2026-10-08）
- 日期：2026-10-08
- 关联：ADR-009（本 ADR 是它的到访点）、ADR-010（判定者设计）、ADR-005（三段式）、ADR-006（三道门禁）
- 兑现：ADR-009 写明的硬约束「卡 09 开工前必须先回到本 ADR 定档」——**已到访，本 ADR 即结论**

## 背景

ADR-009 把推理档位的定档推到卡 05 之后，理由是：降档最危险的失败形式是**少抽**，而能看见少抽的判据正是卡 05 要建的语义判定者。卡 05 已完成，且 ADR-009 明文要求定档时**必须同时评估生产者与判定者两层**。

本轮补齐了缺的两件事：

1. **旋钮本身**。ADR-009 期间明令「`llm-client.mjs` 不新增对应参数」。本轮接上：`--llm-reasoning-effort` / `--judge-reasoning-effort`，两层可分别拨，缺省**不发该字段**（与「显式选了某档」在回执里可区分）。非法取值抛错，不静默回落。
2. **判定者层的测量仪器**。生产者层可以跑两次比回执；判定者层不能——它的「区分力」只有在**同一批带已知标签的对象**上才量得出来。新增 `pipeline/tools/tier-probe.mjs`：固定一批对象，只拨档位，逐对象比对判决**及其方向**。

### 方法论：没有噪声带的对照不构成对照

本 ADR 与 ADR-009 最重要的差别是每组实验都带**同档多臂**的对照臂。这不是谨慎，是必需——本轮**两次**得出了错误结论，两次都是被噪声带挡回来的（见「本轮修掉的缺陷」与「一次被噪声带救回的错结论」）。

## 决策

**两层都不拨档，维持默认口径**（不指定 `reasoning_effort`，请求体不发该字段）。

### 理由

**ADR-009 设的门槛按构造无法满足，而这不是测出来的结论。**

核对 ADR-009 的门槛原文：「定档时不得只依据『引文保真度未下降』；必须以卡 05 的语义判定者判据为主证据」。本轮实测表明这条主证据**在这个问题上没有分辨力**，原因有二，且互相独立：

1. **判定者看不见少抽。** ADR-009 自己的判断——「少抽的对象根本不存在，没有任何判据会为缺席者报警」——在本轮从推理升级为**观测**（见「发现一」：零产出锚点在默认档同样发生，且回执对此零信号）。因此「以判定者为主证据证明不掉质」这件事，**不是没测，是测不了**。
2. **判定者自身的噪声带大于它要测的效应。** 同档两臂 13.5% 的判决翻转（见「发现二」），而跨档差异只有 2/37 = 5.4%。

**5 个臂的产出指标重叠是「证据不足」，不是「无效应」。** 噪声带 12.8% 的含义是：**低档若真少抽 10%，本实验看不见。** 把「没测出来」当成「不存在」，正是 ADR-009 写来防的那个错误——而本轮已经犯过一次并被挡回（见「一次被噪声带救回的错结论」）。

因此：**可测的只有省 42.2%；质量影响测不出，且是结构性测不出。** 在这种状态下把档位往下拨，等于在一个我们看不见的维度上做不可逆的成本交换。

### 分层的账

| 层 | 档位效应 | 同档噪声带 | 可分辨 | 实测代价 | 省钱占比 |
|---|---|---|---|---|---|
| 判定者 | 推理 **−58.0%** | 5.1% | ✅ | 未检出（2/37 < 噪声带 13.5%） | 约 **3%**（判定者 output 7,479 vs 生产者 137,151） |
| 生产者 | 推理 **−42.2%** | 12.8% | ✅ | **测不出**（同样也是结构性测不出） | 主要成本 |

判定者层即使降档，也只占总成本约 3%——**为 3% 引入一个未解决的失效模式（13.5% 不重复性），不值。**

### 这个结论是可推翻的，路径要说清楚

重开本 ADR 的条件**不是**「又跑了几次，还是测不出差异」——那只会重复同一个功效不足的实验。重开的条件是下面之一：

1. **判定者获得了对「少抽」的分辨力**（例如回执能报出零产出锚点，且有一条判据会对它报警）。此时 ADR-009 的门槛才第一次变得可以满足。
2. **样本量提升到有统计功效**。噪声按 `1/√n` 收缩：要把 12.8% 的带宽压到足以分辨 10% 的效应，需要约 4 倍样本（≈80 个锚点），即 3–4 章、两档各跑一遍。
3. **成本权重变化**。若推理开销因为设计变化（判定者改多轮、多模型互审）而占比大幅上升，42.2% 就变成一笔大钱。

在这三条之一成立之前，**不降是默认口径**。

## 一次被噪声带救回的错结论（留痕）

**本 ADR 的第一版给出了一个错误结论，而且它有完整的数据支撑、看起来无可指摘。**

低档只有 **1 个**样本时（低档#2 = 30 个对象，默认档 = 34 / 34 / 33），第一版写下：

> 对象数 30 vs 33.67 ⇒ **−10.9%**，**落在同档区间（33–34）之外**

并据此**逐条复核**了四个锚点上的差异，判定「四分之三是可复核的真实内容损失」：`h3-3` 丢了 EngineeringRule 的条件从句、`h4-2` 丢了「优先提取为文本以节约 token」的取舍建议、`h4-3` 丢了 Case 对象、`h2-4` 的内容被 `corrective` 吸收。

**第二个低档样本（低档#3 = 33 个对象）把它整体推翻**：

- 对象数区间**重叠**了（默认 33–34，低档 30–33）；
- `h4-2` 的那条 Heuristic：低档#3 **有**，而默认#3 **没有**；
- `h4-3` 的那个 Case：默认#1 与默认#3 **都没有**，只有默认#2 有；
- `h3-3` 的产出：默认#1 = 1（与低档#2 相同），默认#3 = 2（与低档#3 相同）；
- Heuristic 条数：默认 **3 / 3 / 3**，低档 **1 / 7**（低档#3 比任何默认臂都多）。

那些对象差异**真实存在**（逐条读原文核对过），但**把它们归因给档位是错的**——同一档位内部的差异有同样大。

**这个错误的形态值得记下来**：它不是「没查」，是**查得过于仔细**。逐条复核对象内容、逐条读原文，做的每一件事都是对的，唯独漏了一步——**先确认这个差异超出了同档噪声带**。差异越大、复核越细，结论看起来越扎实，而它错得越隐蔽。

## 附带发现（比档位结论更重要）

### 发现一 · 漏抽已经在默认档发生，而门禁对它零信号

`chapter4` 的 20 个锚点中，**每次运行都有锚点产出 0 个对象**，且每次漏的**不是同一个**：

| 运行 | 零产出锚点 | 该锚点是什么 |
|---|---|---|
| `run-7afb98d262b5`（旧提示词） | `h2-9` | 思考题 |
| `run-470138ece6a3` | `h2-9` | 思考题 |
| 默认#2 | `h2-8` | 本章小结 |
| 默认#3 | `h2-9` | 思考题 |
| 低档#2 | `h2-8` | 本章小结 |
| 低档#3 | `h3-7`、`h2-9`（**2 个**） | 多模态感知、思考题 |

「本章小结」（`h2-8`）在默认#1 与默认#3 里各产出 2 个对象，在默认#2 与低档#2 里**直接为空**。

**流水线对此完全无信号**（实测，读 `pipeline/registry/tier-probe/producer-default.receipt.json`）：

- 回执全文提及该锚点**仅 1 次**——在 `layer2.perAnchor` 数组里的一条 `objectCount: 0`；
- 没有任何 warning / note / anomaly 字段；
- `reasonCodes` 只记了 4 条拒绝（`QUOTE_MISMATCH` 2 + `JUDGE_INSUFFICIENT` 2），**全部关于已存在的对象**；
- `counts` 是 `{anchors:20, objects:34, passed:30, rejected:4}`——**「20 个锚点只产出了 19 个锚点的东西」这件事在这个计数里不出现**。

ADR-009 当初写：「逐字引用判据对『漏抽』完全无感——少抽的对象根本不存在，没有任何判据会为缺席者报警。」当时这是**推理**，现在是**观测**。而且比推理更强：**漏抽不需要降档就会发生，默认档也一样。**

**直接后果**：`docs/tickets/07-single-chapter-batch.md` 原有的验收「断言『已处理锚点数 = 索引中的锚点数』」**抓不到它**——锚点**被处理了**（调用发出了），只是产出为空。该条测的是「有没有调用」，而失效模式是「调用了但没产出」。已要求卡 07 增加两条验收。

### 发现二 · 判定者自身的不重复性，重设了卡 05 证据的精度

同一批对象、同一提示词指纹、`temperature = 0`，**同档两臂仍有 5/37（13.5%）判决翻转**。

- **单次运行的拒绝数不是稳定量**：同一批对象在三臂间检出 13 / 10 / 10。
- **卡 05 记录的「12 条不充分」是一个单次运行的数字**，其不确定性远大于此前任何文档的表述。卡 05 的**结论**（判定者能抓出系统性问题）不受影响——12 条里的一致模式是真的；**但任何以「N 条」为单位的精细推断都应带上这个带宽。**
- **不要在单次运行上做精细比较。**

### 发现三 · 两层的代价结构完全不同（但效应都可分辨）

ADR-009 要求两层分别评估因此不是形式主义的双份检查：判定者省的是小钱且无实测代价，生产者省的是大钱但质量面测不出。**同一个旋钮，两层要回答的是两个不同的问题。**

这也**推翻了 ADR-009 的一处论证**：ADR-009 曾以「推理更像每锚点的固定开销」（锚点间横截面相关 `r = 0.506`）支持「降档很可能省得下来」。控制变量实验显示降档**确实省**（−42.2%）——**结论对、证据错**：横截面相关与档位效应无关，当初是碰巧猜对。

## 对 ADR-009 原文的三处更正（原文保留，此处留痕）

1. **「字段只有 model / messages / max_tokens / temperature」**（ADR-009 第 17 行引用 `llm-client.mjs` 的请求体）。**已失效**：本轮新增 `reasoning_effort`（仅在该字段非 null 时发出）。ADR-009 的核实命令 `grep -n "model: config.modelId" -A6 pipeline/tools/llm-client.mjs` 现在返回 **7** 行而非 6 行（实测）。
2. **「推理更像每锚点的固定开销」**（ADR-009「附带实测支持」段）。**结论对、证据错**，见「发现三」。
3. **「维持现状（思考模式默认开、effort 默认 high、不显式设置参数）」**（ADR-009 决策段）。**被本 ADR 维持，但理由不同**：ADR-009 维持它是因为「还不能定」，本 ADR 维持它是因为「**证明不了它安全，而能证明的收益不足以买这个风险**」。

## 本轮修掉的四个缺陷

### 缺陷一 · 探针的臂会互相覆盖（仪器）

最初用档位名作对齐矩阵的键，于是 `--tiers high,high`（量噪声带的标准做法）会让第二个臂覆盖第一个臂的判决，**显示两臂完全一致**——恰好把噪声带报成 0，而零噪声带会让任何档位结论都显得成立。修法：臂标签唯一化（`high` / `high#2`），由 `pipeline/tools/test/tier-probe.test.mjs` 的 11 个用例钉住。

### 缺陷二 · 方向标签必须区分两个相反的信号（仪器）

「A 检出、B 放过」与「B 检出、A 放过」在原始差异计数里是同一个数，含义相反——只有前者能支持「不该降档」。探针把两者分成 `<A>-only` / `<B>-only`，并把「两臂都检出但判得不同」单列。

### 缺陷三 · 生产者的推理档位根本没接上（流水线）——**它伪装成了一次成功的实验**

`--llm-reasoning-effort` 加进了 CLI，判定者那条链也正确继承了它，**但生产者自己的 `resolveLlmConfig` 调用点没有被加上该覆盖**。后果：

- 第一版「低档臂」名义上跑低档，**实际发出的是「不带 `reasoning_effort`」的请求**——20 次真实调用全部跑在默认档；
- 回执**看起来完全正常**：`judge.reasoningEffort = "low"` 赫然在目（判定者走的是另一份 opts）；
- 唯一能揭穿它的 `model.configSource.reasoningEffort` 当时**根本不在回执的 `model` 块里**（该键只写在 `layer2` 上）。

于是第一版生产者对照的**三个臂全在默认档**，测出的 12% 被误读成档位效应——它其实是同档噪声。**证据保留在** `pipeline/registry/tier-probe/INVALID-producer-low.*`（前缀是刻意的，见该目录的 `README-INVALID.md`）。

**修法不是补一行**，因为这是同一个缺陷的第二次发作：卡 05 修了 `flags → input` 那一跳，没修 `input → resolveLlmConfig` 这一跳。因此改为**表驱动**：`PRODUCER_OVERRIDE_KEYS` / `JUDGE_OVERRIDE_KEYS` 两张映射表 + `buildProducerOverrides` / `buildJudgeOverrides`，由 `pipeline/tools/test/route-overrides.test.mjs` 的 9 个用例钉住四条性质：

1. 每一个**路由类**的 CLI 开关都必须出现在某张表的值里；
2. 「非路由」豁免名单里的开关都不得是取值型（缺省不是字符串）；
3. 程序化专用键（`llmApiKey`——**凭据不许上命令行**）必须确实不是 CLI 开关；
4. **缺省时不得产出该键**——否则 `resolveLlmConfig` 会把它读成「调用方显式传了 `null`」，回执于是写 `override(reasoningEffort)` 而其实**没人拨过档**。

同时把 `model.reasoningEffort` 冒到回执的 `model` 块——**「生效值」与「来源」必须并排可见**，这正是缺陷三能潜伏的原因。

### 缺陷四 · 回执的来源标注会撒谎（流水线）

`overridesFrom` 最初无条件把所有键填成 `null`。`resolveLlmConfig` 判定来源时读的是「该键在不在、是不是非空串」，于是**没人拨档的运行也会被记成 `override(reasoningEffort)`**。值是对的（`null` → 不发字段），**来源是假的**——而来源字段存在的全部意义，就是让人事后能问「这次到底是谁把它设成这样的」。

实测症状：`pipeline/registry/tier-probe/producer-default-3.receipt.json` 里
`model.reasoningEffort = null` 与 `model.configSource.reasoningEffort = "override(reasoningEffort)"` 并排出现，**互相矛盾**。修法：`overridesFrom` 只放取值确实为非空字符串的键，缺省则**不产出该键**。

## 后果

**正面**
- ADR-009 的定档义务**已了结**，卡 09 的全书跑批不再被它阻塞。
- 旋钮已就位、两层可分别拨、生效值与来源都进回执，将来的对照不必再改代码。
- 探针是一把**可复用**的尺：任何「换模型 / 换提示词 / 换档位会不会掉质」的问题，现在都能带噪声带地回答。
- 「漏抽零信号」从推理升级为观测，且已落到卡 07 的验收面。

**负面 / 代价**
- **42.2% 的推理开销留在桌上**。本 ADR 最实在的代价。它不是因为「降档不安全」而放弃，而是因为**结构上无法证明它安全**。
- 判定者的 13.5% 不重复性**被量化但未修复**。
- 「漏抽」**被发现但未修复**，本 ADR 只做到把它写进卡 07 的验收。
- 低档的一次空内容失败（n=1）**未能归因**。

**必须遵守的约束**
- **卡 07 必须增加两条验收**：回执须能报出「被处理但产出 0 个对象」的锚点（计数 + 清单），且该数字在**复用路径**上同样存在（实测该路径的 `perAnchor` 当前是空数组，等于该信号整体消失）。
- 引用本 ADR 的任何用量数字时，**同档噪声带必须与效应值成对出现**。单独引用「低档省 42%」而不给 12.8% 的同档带宽，会把噪声读成效应。
- 引用任何**逐对象**的差异时，**必须先给出同档内部的对照**。本 ADR 的错结论就是漏了这一步。
- **不得引用 `INVALID-producer-low.*` 作为低档数据**。
