# ADR-016 · 反模式的跨章综合：按主题组织输入、每条出处各带引文；以及一个被第三次采样救回的结论

- 状态：已接受（决策者：用户，2026-10-09）
- 日期：2026-10-09
- 关联：ADR-005（三段式的跨章综合归属）、ADR-011（引文的两个用途，本 ADR 是它的续篇）、ADR-009 / ADR-015（成本与噪声带）、ADR-010（判定者设计）
- 兑现：卡 06 的机制部分；卡 09 用它产出全书真实分布

## 背景

卡 06 的立项理由是一条实测：全书「常见陷阱」字面 **0 命中**，显式失败小节仅 **13 处**且高度集中在 chapter10，而目标量级是 22 个 skill × 6–8 条 ≈ **130–176 条**。差一个数量级——不是抽得不够努力，是**原文里不存在**。

因此反模式必须**综合**，且输入的**组织方式本身是设计决策**（规格 `01-pipeline-spec.md` 第 294 行把这条单列出来，第 341 行又把「按主题组织输入的提示词工程细节」明确划到实现层、不在规格层锁定）。卡 06 同时明令：**不预设「什么算同一主题」与「跨章占比到什么水平算够」这两个阈值**——先产出、从真实分布取数、再定阈值。

本轮把这条链路建起来，并用 **2 个主题 / 16 条对象**做机制验证（用户在「2 主题 / 13 主题 / 仅夹具」三个范围里选了这个）。

## 决策

### 决策 1 · 主题由模型提案，清单落盘供人工核可

三个候选里选第三个（用户拍板）：

| 候选 | 为什么不选 |
|---|---|
| 阈值聚类 | 等于凭空设一个数字，会反过来逼着实现者去凑阈值——正是卡 06 明令避免的 |
| 人工写死清单 | 只能覆盖我事先想到的主题，漏掉的恰恰是这一卡存在的理由 |
| **模型提案 + 清单落盘** | 主题边界来自一次**可复核的判断**，判断的结果是一份**文件**（`pipeline/knowledge/themes.json`），可打开、可改、可重跑后对比；全程不引入任何阈值 |

提案只给**锚点目录**（标题 + 首行摘录，不含正文），因此它是目录级调用而非全文级调用。目录里 `catalogHash` 是可复算的，清单里记了它。

### 决策 2 · 每条 `sourceRef` 自带引文，各验各的锚点区间

`sourceRef` 增加可选字段 `quote`（`common.schema.json` 的 `$defs.sourceRef`）。第 3 层对**每一条**带 `quote` 的出处，拿它与**那一条出处自己的锚点区间**做逐字比对。

**为什么不只验第一条**：一条跨章反模式引用「第 5 章 + 第 7 章」时，只比 `sourceRefs[0]` 等于**对第二、三条引文完全不设防**。多写一条出处不花成本，所以「引用了几章」若不自述之外另有验证，它就只是一个自述——这正是「抄取冒充综合」在数据层的形态。

**理由码不新增**（`QUOTE_MISMATCH`，用 `at = sourceRefs/i` 区分顶层引文与逐条引文）。拆成两个码会把一个缺陷记成两笔，而两者的**修复方与修复动作完全相同**（第 2 层归纳时改写了原文）。

### 决策 3 · 判定者的输入契约**不动**

> **⚠ 本条已被 [`ADR-022`](ADR-022-judge-vision-all-anchors.md) 取代（2026-10-10）**，原文保留不改。
> 取代的依据正是本条自己写下的重评条件：本轮「预判得不到支持」的原因是**那次样本里没有一条
> 多锚点对象把主张压到了第二条锚点上**，而这在后续一轮里出现了——
> `AP-SYNTH-T02-01` 被拒的理由要的那句话**逐字就在该对象第二条锚点里**，旧契约让它按结构看不到。
> ADR-022 据此把 `JUDGE_INPUT_KEYS` 的 `anchorText` 扩成 `anchors`（**仍是三个键**），
> 即本条当年主张过、又被实测否掉的那个方案。

综合提示词要求「**主张收窄到主引文能承载的粒度**，其余章节作佐证」。这是对判定者当前契约（`JUDGE_INPUT_KEYS = ['claim','quote','anchorText']`，即「主张 + 一条引文 + **那一个**锚点原文」）的**适配**，不是让步。

本轮开始时我预判会出问题：跨章主张若把两章的结论合并成一个更大的断言，主引文一个人扛不住，判定者会（正确地）判不充分——ADR-011 记录的 AntiPattern 100% 不充分就是这条路的终点。因此我当时主张**预先把判定者输入扩成「主张 + 全部证据」**。

**先测再说，所以没改。** 实测结果（见下）里，三次判定给出的**全部拒绝理由中没有任何一条**是「你引用了多章、而我只看到一章」这种形态。该预判**在本轮样本里得不到支持**。契约维持不变，并在「未决项」里写明它在什么条件下需要重新评估。

## 实测数据

### 一 · 主题提案（1 次调用）

| 项 | 值（实测） |
|---|---|
| 目录 | 13 个源文件 / **336** 个锚点，`catalogHash sha256:8359f907…78d5` |
| 提案输入 | 系统提示词 887 字符 + 用户提示词 **38,451** 字符（UTF-8 84,037 字节） |
| 产出 | **13 个主题**，其中 **12 个跨 ≥2 章**；悬空锚点 **0**、空主题 **0**、重复 id **0** |
| 用量 | input 19,988 / output 21,260（含推理 16,788）= 41,248 token，1 次调用 |
| 章节跨度 | T12 安全与信任跨 **6** 章；T03 工具设计与生态跨 **5** 章；T13 代码生成与元能力跨 **1** 章 |
| 目录覆盖 | 336 个锚点被引用 **296** 个，未引用 **40** 个；`introduction` **0/5**、`reference-answers` **0/11** 整份未被引用 |

**「悬空锚点 0」不是一句好消息，是一条该被检验的性质**：模型完全可以给出一个像模像样的 `chapter5#h3-9`。真出现时若静默丢弃，「模型杜撰了三个锚点」会表现为「这个主题恰好只有两个锚点」——一个内容问题伪装成一次正常产出。故 `validateThemeProposal` 逐条记录 `unresolvedAnchors` 并在 CLI 上告警。

**T13 是本轮最值得记的一条负面观察**：它是 13 个主题里唯一的单章主题，而提示词要求「若某主题只在一章出现，必须在 rationale 里说明为什么它是独立主题、而不是某章的一节」。它给的 rationale 是「第五章完整阐述了 Coding Agent 的构建与代码作为元能力的多种角色，这些锚点共同展示代码生成在 Agent 系统中的核心地位」——**复述了内容，没有回答问题**。形式上合规、实质上没答。这类「照着格式填空」的通过无法用现有判据区分。

### 四 · 判定者（同一批 16 个对象、同一模型、同一提示词，三次）

| 判定 | 通过 | 拒绝 | 不支撑 | 不充分 | 跨章对象通过 |
|---|---|---|---|---|---|

**逐条对比（第 2 次 vs 第 3 次，16 条全部可比）：翻转 2/16 = 12.5%。**

| 对象 | 第 2 次 | 第 3 次 |
|---|---|---|
| `AP-SYNTH-T02-01` | reject/insufficient | reject/insufficient |
| `AP-SYNTH-T02-02` | pass/supported | **reject/insufficient** ⟵ 翻转 |
| `AP-SYNTH-T02-03`（**跨章**） | pass/supported | **reject/insufficient** ⟵ 翻转 |

| `AP-SYNTH-T12-06` | reject/unsupported | reject/unsupported |
| 其余 11 条 | pass/supported | pass/supported |

**稳定核心**：14/16 在三次判定中一致。**稳定被拒的 3 条**：

| 对象 | 判定值 | 判定者给出的理由（节选） | 真实根因 |
|---|---|---|---|
| `AP-SYNTH-T02-01` | insufficient | 「引文仅通过类比说明…，未断言系统提示词实际以规则堆砌而非 SOP」 | 主张宽于引文 |
| `AP-SYNTH-T02-04` | insufficient | 「引文仅支撑静默输入转换导致偏离意图，但未提及反复尝试失败、无法诊断」 | 主张宽于引文 |
| `AP-SYNTH-T12-06` | **unsupported** | 「引文明确说…**不能**修改…，而主张却说**允许**修改，方向相反」 | **主张方向与引文相反** |

前两条是「模型没有遵守『主张收窄到主引文能承载的粒度』」；第三条是**生成物里的一个真实内容错误**——它把书里的**纠正做法**（禁止 Agent 改自己的验证器）反向写成了**反模式**（允许它改）。判定者抓到它是对的。

### 五 · 跨章分布（卡 06 要求输出的四项）

只统计**通过**的对象：

| 项 | 第 2 次 | 第 3 次 |
|---|---|---|
| 反模式总数 | 13 | 11 |
| 引用 ≥2 个章节的条数 | 4 | 3 |
| 跨章占比 | 4/13 = 0.3077 | 3/11 = 0.2727 |
| 被引用章节分布 | chapter2:7, chapter4:3, chapter1:2, chapter5:2, chapter9:2, chapter7:1, chapter6:1 | chapter2:5, chapter1:2, chapter4:2, chapter5:2, chapter9:2, chapter7:1, chapter6:1 |
| `CROSS_CHAPTER_CLAIM_UNSUPPORTED`（抄取冒充综合的检出点） | **0** | **0** |

**这个「分布」目前读不出东西，原因必须写明**：两次判定之间，同一批对象的总数从 13 变 11、跨章数从 4 变 3。差异**完全落在判定者的噪声带内**（12.5% 逐条翻转），与「这批反模式实际跨不跨章」无关。因此：

> **卡 06 的「不设阈值」在这一轮不只是纪律，是唯一可选项**——n=16 且噪声带 12.5% 的分布不足以支撑任何阈值判断。真实分布须等卡 09 的全书运行。

## 一个被第三次采样救回的结论

本轮我第一次读数据显示：**跨章对象 4/4 全部通过，单章对象 3/12 被拒**。据此我写下「我预判的失效模式没有发生，判定者只看到主锚点这件事在实测中不构成问题」。

**那是第 2 次判定的单一快照。** 第 3 次判定里，`AP-SYNTH-T02-03` 这条**跨章**对象翻转成了拒绝，跨章通过数从 4 掉到 3。

结论必须改成：

> 在三次判定给出的**全部**拒绝理由里，**没有任何一条**是「你引用了多章而我只看到一章」这种形态；稳定被拒的三条理由都是「主张宽于引文」或「方向相反」。这把决策 3 那个预判的可信度压得很低。**但跨章对象的样本只有 4 条**，不足以否证它——该预判是**不可测**，不是**已被否证**。

这是本项目第三次出现同一形态的错误（前两次见 ADR-015）：**结论不是「没查」，是「查得太少却写得像查够了」**。三次的修法都一样——**在没有同条件重复样本之前，不写「没有发生」**。本轮之所以能救回来，纯粹因为第 3 次运行是**免费的**（生产者原始响应已落盘，续跑只重扫判定者）。

## 本轮修掉的缺陷

全部由测试或真实运行暴露，不是预防性编码：

| # | 缺陷 | 后果 | 暴露方式 |
|---|---|---|---|
| 1 | `payload` 展开在最后，把模型自己写的 `evidenceQuote` 覆盖回流水线接线的值 | 判定者看到的引文可能不是主锚点那条引文，而**两句通常一样**，故覆盖看起来什么也没发生 | 新写的测试直接红 |
| 2 | 综合 CLI 把写盘放在**全部主题之后** | 一次崩溃丢掉已付费跑完的整个主题（实测丢了 T02 的 8 条对象与原始响应） | 真实运行的 T12 截断 |
| 3 | 「重复锚点」守卫只看键在不在、不看条目是否相同 | 内容相同的子集索引被报成「给了不同条目」，指向错误的修法 | 新写的测试直接红 |
| 4 | 截断被报成「不是可解析的 JSON」 | 预算问题伪装成解析问题，两者的修法相反 | 真实运行的 T12 截断 |
| 5 | 回执**不落盘逐对象判定明细** | 第一次判定那 5 条**分别是谁、为什么被拒**事后无法查——两次判定之间的差异是本轮唯一能测判定者噪声的样本，就这样没了 | 分析第 2 次结果时发现查不到 |
| 6 | 同一 `runId` 重复运行时**静默覆盖**上一次回执 | 与 #5 叠加，把上一次的记录直接盖掉 | 同上 |
| 7 | 续跑时回执显示「生产者 0 次调用」 | 账本跟着进程走、产出却跨进程，**续跑会让成本账越算越小** | 第 3 次运行的输出 |

缺陷 2 与 5/6 是同一族：**付过钱的东西必须当场落地，而且不得被下一次运行静默盖掉**。修法是三个具体的动作——每完成一个主题当场写原始响应；逐对象判定明细单独落盘；写产物前先把旧产物归档到 `pipeline/registry/history/`。

## 未决项

1. **判定者输入是否该扩成多证据。** 维持现状（决策 3）。重新评估的触发条件：跨章对象累计 ≥30 条时，若「拒绝理由里出现『引用了多章而判定者只看到一章』形态」的比例 >0，则本决策需重议。届时不必重跑生产者——原始响应已落盘，改契约后免费重放。
2. **`chapterRef` 对跨章对象的语义。** 现在取主锚点所在章节，跨章事实由 `sourceRefs` 承载（对象 schema 顶层 `additionalProperties: false`，放不下新字段）。下游若要按「跨章」筛选，读 `sourceRefs` 去重后的 `file` 数，或读回执的 `marks`。
3. **什么是「真实的跨章反模式」尚未定义。** 本轮 4 条跨章对象的跨章性由**模型自选**的支撑锚点决定，而不是由流水线判定。若下游要求「一条反模式必须有 ≥2 章的独立证据」，那是一个**新的判据**，不在卡 06 范围内。
4. **阈值仍不设。** 承卡 06。

```bash

# ③ 跨章综合（本 ADR 的数据来自 --themes T02,T12）

  --model deepseek-v4-pro --base-url https://api.deepseek.com
# 再跑一次是**免费**的：生产者原始响应已落盘，续跑只重扫判定者
```
