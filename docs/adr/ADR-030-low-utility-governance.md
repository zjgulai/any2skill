# ADR-030 · 低效用治理：降级 = 如实披露；重测 = 有因才能重测

- 状态：已接受（2026-10-15）
- 决策者：用户（在三选项中拍板「A+C：披露 + 重测协议」）
- 关联：ADR-006（「标记低效用（不拒绝，但降级）」——**降级动作本 ADR 才被定义**）、
  ADR-027（门禁三判定口径）、`docs/tickets/25-low-utility-governance.md`（证据来源）、
  `docs/specs/03-second-source-report.md` §4（H1 相关实测）

## 背景

四波之后发布区 30 个 skill 里 **18 个 low-utility**。ADR-006 写下「降级」二字，但**从未定义
它是什么**——于是 18 个 skill 带着一个没有动作的标签挂着。卡 25 先做了两件事：

1. **形状分析**：18 个 low-utility 的任务 ≈87% 双过（基座无 skill 也过）、其余双败；
   passed 靠 1–2 个「无臂败、有臂过」任务区分。**头差是稀缺品。**
2. **头差探针**（v2 更难任务生成，2.4 个 skill × K=6 A/B）：v2 确实把任务加难了
   （双败率 0–3 → 1–3），但 17 个任务对里 **0 个改进**——难度没有转化为有臂优势。

由此两个竞争解释里 **H1（源内容在模型训练分布内，常规任务无头差）得到偏支持**，
H2（任务生成器太温和）未获支持。这决定了治理的基调：**不是「再测测看」，而是「把
测得出的与测不出的都如实标出来，并规定下一次测量何时值得花钱」。**

## 决策

**一、降级 = 如实披露（不是移出、不是删除、不是改正文）。**

- 发布物分层记录 `pipeline/registry/tiers.json`（**派生文件**：从各源门禁三报告生成，
  不手改；含每 skill 的 tier、计数与报告出处哈希）。
- README 的发布物区块明示：low-utility = **在本测量设计下未测出效用增量**（无改进也
  无确认退化）——不是「无用」的同义词，也不是「没测过」；rejected 与 low-utility 是两种
  处置（前者下架并留 REJECTION.md，后者留区挂牌）。
- skill 留在发布区、正文与描述**不动**——披露的载体是 registry 与 README，不是产品文件本身。

**二、重测协议（有因才能重测）。**

- **允许重测的触发**（三者之一）：① 该 skill 正文修订（修订必须说明针对什么问题）；
  ② 测量仪器升级并**按 ADR 立版**（如任务生成器 v2 转正——提示词指纹换代、全量重测）；
  ③ 用户显式要求。
- **禁止**：以「换任务样本直到测出改进」为目的的重复采样。同一 skill、同一正文、
  同一仪器下的重测，**必须报告全部批次**（含未测出增量的批次），不得只报最好的一批。
- 判定口径不变（ADR-027）：复跑制、K=6、无效任务可见、退化复现即拒。
- 记录：每批次走既有归档机制（`archiveIfExists` 的 history 积累），tiers.json 随最新批次更新。

**三、测量设计本身的记录义务。**

03 报告的 §4 规律与卡 25 的探针结论（H1 偏支持）是本 ADR 的事实底座；将来若引入
**新的效用轴**（如一致性/方差、长任务链上的保持率），须先立 ADR 并说明它与「能力提升」
轴的关系——**不允许把未测的轴写得像测过**。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| B：low-utility 移出主区（`skills-provisional/`） | 「发布区=实测有效」语义更强，但要动 18 个在售物的冻结面/引用/README，且 low-utility 与 harmful（rejected 已有独立路径）是两种性质——用同一个动作处理会混淆；真需要更严语义时可再来一张卡升级 |
| 暂缓治理（维持无动作的标签） | 18 个标签没有动作就是**没写全的决策**；探针已给出足以定基调的证据 |

## 后果

**正面**

- 「降级」从两个字变成：一份机器可读的 tier 记录 + 一段 README 披露 + 一条重测门槛。
- 「换样本直到过」这类科研失德在协议里被点名禁止，重测只准以「正文/仪器/用户」为由。
- H1 结论（这类源在本测量下测不出增量）进入 ADR 级记录——将来做第三本书时，
  **选择是否期望效用增量**有了先例可循。

**代价 / 限制**

- low-utility 的技能与 passed 的技能在发布区外观相同（只有 registry/README 可区分）。
  这是披露路线的固有代价，接受。
- H1 的样本仍小（2.4 skill / 17 任务对 + ch10-03 部分样本）；探针工具链的一次工具层
  拦截如实记在卡 25。
