# ADR-027 · 门禁三首版：自包含可验证任务、声明式检查单、单次退化复跑制

- 状态：已接受（2026-10-13）
- 决策者：用户（三处拍板；推荐出自卡 14 的设计；另有一处实现级收紧见决策 2）
- 关联：ADR-006（门禁三定义与三条硬约束）、ADR-021（高风险路由：风险标记的第一个真实下游）、ADR-022（未决 1 的噪声底纪律）、ADR-026（同模型不同上下文如实记录的先例）、卡 14

## 背景

门禁一是「合不合规」、门禁二是「找不找得到」；「有没有用、会不会有害」只有门禁三能答，
而它此前不存在。两个已发布 skill（`chapter4-tool-design-principles` 8 对象、
`chapter4-single-tool-design` 20 对象）的契约都带 `PITFALL_COVERAGE_BELOW_ADVISORY`——
ADR-021 把这枚风险标记路由到「门禁三的抽样重点」，路由至今空转。MVP 验收第 3 条要求
门禁三至少检出或排除一次 negative transfer。

## 决策

**1. 任务形态：自包含可验证任务。**

- **任务生成器**（独立上下文、可见 skill 内容）为每个被测 skill 产出 K=6 个任务；
- 任务 = `task.md`（用户口吻的可执行请求）+ 夹具文件 + **声明式检查单**（见决策 2）；
- **消费者**（被测臂）产出结构化产物 `{"files": {路径: 内容}}`，由台架**物化**进临时沙箱目录；
- **评分 = 检查单求值结果（通过/失败），不靠主观打分**。

**2. 检查单是声明式的——**不执行任何模型生成的代码。（实现级**收紧**：卡 14 初稿与
用户拍板时写的是「生成 `checker.mjs`」；落地前评估认定「把生成代码跑在本机」是新引入的
执行面，而 v1 的检查需求用声明式已够。此项**不作为拍板项回退**，理由与替代口径如下，
若用户认为需要生成式检查器可再议。）

```
checker.json 例：{"checks": [
  {"type": "file_exists", "path": "..."},
  {"type": "contains",    "path": "...", "patterns": ["..."]},
  {"type": "not_contains","path": "...", "patterns": ["..."]},
  {"type": "regex",       "path": "...", "pattern": "..."},
  {"type": "json_field",  "path": "...", "pointer": "/a/b", "equals": ...}
]}
```

求值器是本仓的固定代码（纯函数、可测），模型只提供**内容约束**，不提供可执行逻辑。
检查器对两臂**一视同仁**——即使某条检查写得偏，配对比较仍然公平。

**3. 判定规则：一次退化事件 → 复跑确认 → 复现即拒。**

- **退化事件** = 同一任务、同一夹具下「无 skill 臂通过 ∧ 有 skill 臂失败」；
- 事件出现 → **该任务对整对复跑一次**（两臂都可能重新采样）→ 复现即
  **拒绝（negative transfer，ADR-006 的硬约束）**；不复现 → 记**噪声**并如实入报告。
- 复跑这一步是 ADR-022 未决 1 的噪声底纪律落到机制上：单次翻转在实测噪声带内
  不构成结论（判定者同档 13.5% 翻转率的既有教训）。
- 两臂都通过 → 通过；两臂都失败 → 记「任务无效」（检查器或任务本身有问题的信号），
  不计入效用判定但必须可见。

**4. 抽样：v1 = 两个已发布 skill × K=6 × 2 臂。**

约 24 次执行 + 12 次任务生成 ≈ **36 次调用**；小样本、快、可复跑。门禁三测**已发布物**，
未发布的合并候选不进。

**5. 独立性如实记录**：任务生成、两臂执行、判分是三个独立上下文；判分是确定性求值器
（无模型）。生成与执行同模型不同上下文——与 ADR-026 同一条如实口径，不作更强声明。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 执行模型生成的 `checker.mjs` | 把「执行生成代码」这一新风险面引进本机；v1 的检查需求声明式已够。需要生成式检查器时再立决策 |
| 真实仓库任务 | 环境重、成本高、首版风险大；自包含任务已能测「有/无 skill 的差异」这个待测问题 |
| 门禁二场景直接当任务 | 场景是触发描述而非可执行请求；扩写后与决策 1 实为同一方案 |
| ≥2 退化事件直接拒 | 把单次噪声当信号；与 ADR-022 的噪声底教训相抵 |
| 只记录不拒 | 与 ADR-006「negative transfer 必须拒绝」直接冲突 |
| 主观评分（LLM judge 打分） | 评分要可复核、可复跑；配对比较下确定性检查已足够回答「更差了吗」 |

## 后果

**正面**

- 三道门禁全部建成后，「不合规 / 找不到 / 有害」各有对应检出机制；ADR-021 的风险标记
  第一次有真实下游。
- 判定规则把噪声底纪律写进了机制——「A 比 B 差」的结论自带复跑复核。

**负面 / 代价**

- 自包含任务与真实使用有距离：任务短、环境干净，它测的是**方向上**的效用差异，
  不是真实场景的绝对表现——如实写进报告口径。
- 检查单的表达力有限（没有语义判断）；两臂同受限，配对比较不受影响。

**必须遵守的约束**

- **构建者不得参与任何一臂的评分**；判分只有确定性求值器一条路径。
- 有 skill 臂注入的是**发布产物的 SKILL.md 原文**——不得改写、不得摘要。
- 无 skill 臂的上下文**不得**出现 skill 正文的任何片段（有可失败的反证测试）。
- negative transfer 复现即**必须拒绝**，不得仅标注。
- 全程不读 `benchmark/`。

## 未决

1. **K 与任务的代表性**：v1 K=6 是预算折中；首跑后看「任务无效」（两臂都失败）的比例再评估。
2. **效用还能怎么测**：自包含任务测方向；「低效用」（无差异）的降级动作（references/？合并？）
   未定义——按 ADR-006 只要求「标记为低效用（不拒绝，但降级）」，降级形态留给后续。
3. **生成式检查器**是否需要（表达力上限）：等出现「声明式测不出的效用差异」实例再议。
