# ADR-014 · 运行身份包含门禁完成度

- 状态：已接受
- 日期：2026-10-08
- 决策者：用户（在「门禁完成度纳入 runId / 覆盖前归档到 history / 维持现状」三选项中拍板第一项）
- 关联：ADR-006（三道门禁）、ADR-010（判定者设计）、ADR-013（提示词漂移）；规格 `docs/specs/01-pipeline-spec.md` 的 D7
- 落地任务卡：`docs/tickets/05-verifier-independence.md`

## 背景

`runId` 此前由「源哈希 + 模型标识 + 对象集合指纹 + 流水线版本」算出。**它不含门禁完成度。**

于是同一批对象、同一版本下的两次运行——一次只跑确定性判据、一次连判定者也跑——
算出**同一个 `runId`**，后写的那份回执**把先写的那份顶掉**。

**而且被顶掉的不是子集。** 两者记的 `counts` 不同：确定性-only 判它通过的，全覆盖可能判它
不通过。即「同一批对象在两组判据下各自的结论」这本该并存的记录，丢了一份。

这个缺陷是修另一个缺陷时暴露的：为了让 `--judge` 不被一份没扫过判定者的回执挡住，
回放前加了门禁比对；测试随即证明两份回执会撞名。**修一个「静默吞掉显式指令」的缺陷，
牵出了「两份不同陈述共用一个身份」的缺陷。**

## 决策

**把门禁完成度纳入 `runRunId` 的指纹。**

```
runId = sha256( 源哈希 ‖ 模型标识 ‖ 对象集合指纹 ‖ pipeline:v{N} ‖ gate:{full|deterministic-only} )[0:12]
```

理由与 `pipelineVersion` 进指纹是同一条：**运行身份必须覆盖「这次运行实际做了哪些事」**。
但门禁完成度与版本号有一点关键区别——版本号是**流水线的属性**（改代码的人负责递增），
门禁完成度是**每次运行各自的选择**（`--judge` / `--no-judge` / 复用路径的缺省）。
因此它无法借版本号表达：两份门禁不同的回执**本来就是两次不同的运行**，
给它们同一个 id 是身份建模本身的错，不是命名冲突。

### 回放规则随之明确

同一批对象可能有至多两份现行回执。回放时：

1. **优先回放「做过判定者」的那份**——它对同一批对象做的事更多，是更好的记录；
2. 只在它不存在时才退回确定性-only 那份；
3. 调用方**显式要求**判定者（`--judge`）而只有确定性-only 那份时，**不回放**，重扫判定者。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 覆盖前把旧的那份归档到 `pipeline/registry/history/` | 与项目里「新旧对象产出并存」同一套手法，零语义变更、零 id 流失，直接解决「不要丢掉仍然成立的运行事实」这个症状。但 `runId` 仍然指代两件事：一个普通复用运行会找到全覆盖那份并回放它，而按身份它「应该」找到确定性-only 那份——**回放路径仍然会迷路，根因留着**。 |
| 维持现状（覆盖，但 stderr 指名告知） | 已确认会丢记录且只在运行时刻告知。本项目一贯的审计纪律是不静默覆盖，而这里是**已知会丢**。 |

## 后果

**正面**
- 两份门禁不同的回执**各有其名、并存**，都可以按 id 单独查到。
- 回放路径不再迷路：要什么完成度就找什么完成度的那份。
- 修的是身份模型，不是给症状打补丁。

**负面 / 代价（一次性 + 长期）**
- **一次性代价**：现行回执的 id 是不含门禁算出来的，因此在新规则下**全部失效**，
  需要重判一次才能收敛。实测：一次普通运行（**0 次模型调用**）写出门禁为
  deterministic-only 的新回执即完成收敛；若要把「做过判定者」的那份也重建，
  需传 `--judge`（该章 33 次判定调用）。
  旧回执原样留在 registry 里（它们是历次运行的事实），只是不再被按 id 查到。
- **长期代价**：`runId` 的计算多了一个必须与落盘时一致的输入。任何新增调用点都必须
  传对 `judgeApplied`，否则回执会落到错误的 id 上。目前只有两处调用点，且都在同一函数内。

**必须遵守的约束**
- `judgeApplied` 必须是**本次运行实际**有没有跑判定者，不是「配置说要不要跑」——
  两者在复用与重判路径上会分叉。
- 新增 `computeRunId` 调用点时，必须同时确认它传的 `judgeApplied` 与该次运行写盘时的值一致。
- 不得为了「让旧 id 还能查到」而在回放路径上加兼容分支——那会把一次性的迁移代价变成永久的双规则。
