# ADR-028 · 体积阈值对齐信息源的实测上限：12,288 → 16,568 字节

- 状态：已接受（2026-10-13）
- 决策者：用户（在四个方案中拍板「对齐原书上限 16,568B」）
- 关联：ADR-004（骨架与 12KB 阈值原文）、ADR-021（判据修订的先例）、ADR-019/卡 16（溢出阀实现）、`docs/specs/02-benchmark-report.md`（本决策的证据来源）

## 背景

ADR-004 决策 2 定阈值为 12,288 字节，依据是「原书中位约 10.9 KB 偏上」——一个**推估**。
2026-10-13 的基准比对报告给出了对照物的**事实**：原书 22 个 skill 中
**5/22 超过 12 KB**，最大 **16,568 字节**、中位 10.9 KB。

同一天，卡 16 的实测把问题压到台面上：重切后的 10 个合并候选，在「配套代码来源补齐 +
溢出阀已实现」之后，仍有 6 个被 12 KB 拒绝——其中 `chapter2-s3`（16,286 B）**比原书最大的
那个 skill 还小**。阈值严于信息源自身的实践，而它唯一的依据是一个比事实更保守的推估。

## 决策

**`SIZE_LIMIT_BYTES` = 16,568**（= 原书 22 个实测最大值），溢出阀（ADR-004 决策 2，同日首次实现）
保持在阈值之前起作用——先溢出、再判限。

**数字的可追溯性**：16,568 不是新拍的偏好值，它是 `benchmark/upstream-skills/` 里
`agent-evaluation/SKILL.md` 的实测字节数（`MIRROR-MANIFEST.md` 第 42 行哈希在册）。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 维持 12,288 | 严于信息源自身实践，且依据只是「中位偏上」的推估；被它拒绝的候选里有比原书最大者还小的 |
| 只加二段溢出（理由段→references、深度阅读折叠为按文件），不动阈值 | 改渲染而不改判据，看似稳妥；但 `chapter7-s1`（21,914 B 溢出后）估计仍超限，收益不确定，且两次改动的面更大 |
| 阈值 + 二段溢出全上 | 一次改两个变量，分不清哪一个在起作用——与卡 13 拒绝「一次改两件事」同一条纪律 |
| 不发新的，只落袋 3 个 | 把已量化、已归因的发布面留在桌上；且对比对报告的主归因（发布门径）不做回应 |

## 后果

**正面**

- 发布面从 3/10 扩到 **6/10**（预期；以重建实测为准），且扩大的依据来自对照物事实。
- 「比信息源更严」这一无依据的自我限制被移除；阈值从此有单一可复算来源。

**负面 / 代价**

- 「一屏内看全」的优势在最大档弱化——但对照物原书本就有 5/22 这么大，这不是新引入的形态。
- 已发布的 `chapter4-tool-design-principles`（5,923 B）与 `chapter4-single-tool-design`（9,538 B）
  都在两版阈值之内，本次修订**不动任何既有发布物**。

**必须遵守的约束**

- 阈值数字必须可追溯到对照物实测（当前：`MIRROR-MANIFEST.md` 的哈希清单）；再改需**新证据**，
  不得凭偏好调整（承 ADR-021 的同款纪律）。
- 溢出阀保持在阈值判定**之前**——「超出即拒」与「先溢出再看」是两种语义，后者是 ADR-004 的原意。

## 未决

1. `chapter7-s1`（21,914 B 溢出后）与 `chapter10-s1`（17,531 B）仍超限——二段溢出
   （理由段→references、深度阅读折叠为按文件）是候选下一步；也提示「68 个对象的合并是否
   本来就超出了骨架的表达容量」这个粒度问题（回到卡 13 的合并粒度议题）。
2. `chapter1-s2` / `chapter9-s3` 的拒因是 `SECTION_EMPTY@常见陷阱`（内容缺口，非体积）——
   需要跨章反模式池或进一步合并来补，不属本 ADR 范围。
