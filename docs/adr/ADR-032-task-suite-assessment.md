# ADR-032 · 任务套件评测口径：门禁二目录模式 + 门禁三对新骨架全量一轮

- 状态：已接受（2026-10-15）
- 决策者：用户（拍板「新套件全量评测（推荐）」）
- 关联：ADR-031（重组的证据边界：unassessed，重测由用户显式发起且先立口径——**本 ADR 即该口径**）、
  ADR-026（门禁二形态）、ADR-027（门禁三形态与复跑制）、ADR-006（有害必拒）、
  ADR-030（重测协议）、`docs/tickets/27-task-suite-assessment.md`（执行记录）

## 背景

19 个任务技能已发布（结构合规），效用与有害性未测。重组把两个确认有害的旧技能
（chapter3-s1、ch13-02-iterators-s1）排除在外，但新正文（任务骨架 + 编写步骤）从未被
门禁三见过——「发布了一批隐性危害未知的 skill」是当前最大风险口。同时，用户重组的
初衷之一是可发现性（名字/描述），而门禁二的盲测恰好直接测它。于是本轮评测的两问：

1. **触发面**：新名称+新描述是否让候选可区分（旧套件的历史形状：40 候选 / 96 冲突组、
   弥散共认领）？
2. **效用面**：新正文是否有可测头差；有没有隐性危害？

## 决策

**一、门禁二新增「套件目录模式」（`--suite`）**。候选目录不再来自 clusters 的候选表，
而是来自 `pipeline/curation/task-skill-suite.v1.json` 经任务装配器装载的 19 个成员：
盲测题面 = **新标题 + 新描述**（与发布物 frontmatter 逐字一致的 description），
场景生成输入 = 成员 owned 对象的类型+摘要。**其余一律不动**：三场景 + 20 无关场景、
list/strict 两读数、稳定对对照、动作清单不执行——判据与读数机制沿用 ADR-026，
本 ADR 只换候选目录的来源。产物按源命名空间走既有助手，套件用 `task-suite` 键
（`gate2-report.task-suite.json` 等），旧套件的历史读数不受影响。

**二、门禁三照旧对新发布面跑一轮全量（按源两次：第一源 8 + rust 11）**。
被测物 = `skills/` 现役发布物（enumeratePublishedSkills 通用）；任务生成输入为
新正文（任务骨架六段）；K=6、复跑制、退化复现即拒——判据不变（ADR-027）。
旧报告按既有机制先归档再写新（`archiveIfExists`），历史不丢。
**风险标记**：任务套件的 riskFlags 为空（旧骨架的建议值体系不套用，ADR-031），
本轮不因「PITFALL_COVERAGE_LOW」路由——高风险路由按门禁二读数（误触发/争抢）走。

**三、结果落盘与状态更新**。评测结果写入 `pipeline/registry/task-suite-assessment.v1.json`
（逐成员的触发读数 + 门禁三判定 + 报告引用哈希）；`task-suite-status.v1.json` 的
`triggerAssessment/utilityAssessment` 由该文件承载的结论更新（仍**不聚合**旧套件判定）。
`registry/rejected/` 路径仍为有害下架的唯一去处（先例：chapter3-s1）。

**四、判定与处置口径**：
- 门禁三 confirmed negative transfer → 下架（ADR-006），REJECTION.md 全证据；
- 稳定共认领对（strict≥2 且两读数都存）→ 按卡 13 既定规则出**合并建议**；
  对任务套件的合并 = 编辑清单归属 + 重建 + 重新发布（不走 apply-resplit——那是
  章节划分的事务日志）。本 ADR 不预设合并一定发生；发生则在本卡内执行并全量重测。
- low-utility → 如实标记（ADR-030 披露路线）。

**五、两读数之间不新增付费轮次**：若出现合并，合并后集合**重跑两读数**（卡 21 先例：
目录哈希变化 → 全量重答），代价如实计入本卡。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 沿用 clusters 候选表跑门禁二 | 候选表是章节划分的产物；重组后的发布面由清单定义——被测对象必须等于发布对象 |
| 只跑门禁三、跳过门禁二 | 用户的核心诉求之一就是可发现性；且门禁二读数是不执行合并与高风险路由的输入 |
| 为任务骨架重写门禁二/三判定 | 判据一字不动是本项目的纪律（ADR-026/027 只被替换的候选目录来源波及） |

## 后果

**正面**

- `unassessed-after-recomposition` 状态由本轮终结：19 个成员各自拿到触发读数与效用判定。
- 门禁二的稳定对分析第一次作用在「任务命名 + 精确描述」的目录上——重组是否收敛
  触发面，有可直接读的表。

**代价 / 限制**

- 约 450 次模型调用（两读数 ≈200 + 门禁三 ≈250）；若触发合并，另计一轮重读数。
- 门禁二报告的动作清单仍是**建议**；本卡执行与否按既定规则（strict≥2 稳定边）机械定，
  非规则内的弥散共认领只记录不处置（第一源先例）。
