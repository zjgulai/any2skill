# ADR-013 · 提示词漂移：告警后复用，不硬拒

- 状态：已接受
- 日期：2026-10-08
- 决策者：用户（在「告警后复用 / 硬拒要求 --rerun / 维持只记不比」三选项中拍板第一项）
- 关联：ADR-004（模型路由不硬编码）、ADR-008（「换了模型却没人察觉」是明确反对的失败模式）；规格 `docs/specs/01-pipeline-spec.md` 的 D9
- 落地任务卡：`docs/tickets/05-verifier-independence.md`

## 背景

`promptFingerprint`（第 2 层提示词的哈希）早已进回执，但**复用路径不拿它做任何判断**。
实测：冻结复用只由 `checkFrozenFreshness`（源版本哈希）把关，提示词指纹**只记不比**。

后果：**改了第 2 层提示词之后，一次普通重跑会静默复用旧提示词产出的对象。**
严格说回执没撒谎（它记的是产出者那次的指纹），但读到它的人不会去比对——
于是「拿到的是旧提示词的产出」这件事在实践中不可见。

这与 ADR-008 批评过的「硬编码一个模型会让『换了模型却没人察觉』变成默认行为」是同型问题。

**触发场景是真实的**：ADR-011 的修复正好改了第 2 层提示词，本次改动就是被那件事逼出来的。

### 关键区分：提示词变了 ≠ 源版本变了

| | 源版本变了 | 提示词变了 |
|---|---|---|
| 对象是否仍然有效 | **否**——`sourceRefs.contentHash` 指不到东西了 | **是**，只是旧了 |
| 现有处置 | 拒绝复用（`checkFrozenFreshness`） | 本次决策 |
| 正确性的性质 | **失效**（对象已经错了） | **陈旧**（对象没错，只是不再是当前提示词会产出的东西） |

把两者当成同一类问题、用同一种手段（硬拒）处理，是把代价花在了不必要的地方。

## 决策

**检出漂移时：告警 + 复用。**

1. 复用前把产出者回执的 `promptFingerprint` 与当前提示词指纹比对。
2. 不一致 → 在 stderr 上打 `[提示词漂移]` 告警，**并排列出两个指纹**，并给出出路（`--rerun`）。
3. 观察结果进回执：`reuseObservation: { detected, producerPromptFingerprint, currentPromptFingerprint, note }`。

### 一处必须写清的实现边界：观察写在哪份回执上

- **纯回放路径**（对象与版本都没变）：**不写盘**。观察只加在返回给调用方的对象上
  （`--json` 输出里能看到）。
  理由：盘上那份回执是**产出者**的记录，它的内容不该随「谁在什么时候读了一遍」而改变——
  把本次观察写回去，会让同一份文件在不同时刻显示不同的东西，那正是「回执是运行事实的凭证」
  这条约束要挡的。
  **代价**：审计平面上看不到这次漂移观察，只有运行者会看到 stderr 告警。
- **重判与生产路径**（本次运行自己写回执）：观察**写进这份回执**。它有主，写进去不污染别人的记录。

让漂移在审计平面上也被看见，需要先给「运行身份」定清楚（门禁完成度是否进 `runId`
等问题会一起动），因此不在此处顺手改，见工单的待定项。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 硬拒：指纹不一致即拒绝复用，要求 `--rerun` | 一致性最好（与源版本变了的处置同口径），但**把陈旧的代价按失效来收**：任何提示词微调——哪怕改一个错别字——都会让所有已落盘对象失效，强制全章重跑（每章 20 次调用、实测单章输出 8–12 万 token）。提示词在现阶段还会反复调，这个代价会反复交。 |
| 维持现状（只记不比） | 等于没有机制：默认行为静默给出旧货，读回执的人得自己想到去比对两个指纹。这正是 ADR-008 明确反对的失败模式。 |

## 后果

**正面**
- 默认行为不再静默给旧货：**每一次**复用运行都会在 stderr 上说明产出它的提示词是不是当前这一版。
- 不花任何额外调用，也不强制重跑。
- 观察结果与结论（两个指纹）并排出现，审计者不必自己算哈希。

**负面 / 代价**
- 纯回放路径下，漂移观察**不在盘面上**（只有 stderr 与 `--json`）。这是本决策明确接受的代价，
  理由见上；不要把它当成缺陷，也不要为了「顺手补全」而往产出者的回执里写字段。
- 告警是**每次运行都出现**的（只要漂移还在）。这是有意的：静默一次之后就再也想不起来。

**必须遵守的约束**
- 漂移**不得**导致硬拒——那与「源版本变了」的处置混为一谈。
- 漂移观察**不得**被写进产出者的回执。
- 引用本决策时须注意：它只解决「用户运行时能看见」，**不**解决「审计平面上能看见」。
