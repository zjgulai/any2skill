# ADR-029 · 「配套代码」段改为源条件骨架：无来源时渲染来源说明

- 状态：已接受（2026-10-14）
- 决策者：用户（在三个方案中拍板「源条件骨架」）
- 关联：ADR-004（6 段骨架原文，§5.2 有同日追加记录）、ADR-020（第一源代码镜像——本段第一次有来源）、ADR-021（判据修订先例）、卡 19（`docs/tickets/19-second-source-materials.md`，本决策的证据来源）

## 背景

第二源（rust-book-cn）验证把「配套代码」段的一个**隐含假设**揭穿了。

卡 18 段③：ownership 切片的 3 个候选全部被门禁一拒，拒因之一就是该段为空（`SECTION_EMPTY`）。
卡 19 补上反模式章后，6 个 rust 候选里 **3 个的唯一剩余拒因就是这一段**——其余骨架段全部达标。

调查发现拒因是**双重**的：

1. **来源侧**：rust 书的示例代码在上游另一仓库（`rust-lang/book` 的 listings），本源
   `sources/rust-book-cn/code/` 不存在；且其代码是**行内清单**（listing），不是目录化项目。
2. **骨架侧**：该段要求「仓库相对路径 + 每个目录一句话说明」，而**对象模型没有任何字段
   承载代码指针**（门禁一同时报 `SECTION_NO_SOURCE`：「本段在信息源中没有对应字段」）。
   第一源能过，是它的 `code/chapterN/` 轻镜像恰好吻合 `collectCodePointers` 的
   「目录+README」约定——**是巧合，不是机制**。

也就是说：该段的真实要求是「**源提供目录形态的配套代码**」，而这件事从未写进骨架——
它对所有源都硬要内容，不管源里有没有。

此前「留空」的口径（`skill-builder.test.mjs` 旧用例原话：「留空的段落里不得出现任何替代性
文字——『看似完整』比『看起来缺』更危险」）在本案里失效了：空段读起来像**忘写**，
而事实是**源里就没有**——读者无法区分这两件事。

## 决策

**「配套代码」段标记为源条件段（`sourceCondition: 'codeDir'`），其内容按源的状态二态渲染：**

| 状态 | 渲染 | 缺口记录 | 门禁一 |
|---|---|---|---|
| 源提供可消费的代码目录（`collectCodePointers` 非空） | 真指针（现状不变） | `SECTION_SOURCE_GRANULARITY_COARSE`（章级列举留痕，现状不变） | 非空即过（不变） |
| 源未提供 | **来源说明**（一行引用块 `>`，常量 `CODE_SECTION_ABSENT_NOTE`） | `SECTION_SOURCE_ABSENT`（新缺口码，非拒因） | 非空即过——说明即是该状态下正确的内容 |

**契约补机器可读面**：`skill-contract` 增加 `codeSource: { available, note }`
（schema 的封闭字段集同步扩充）——契约必须能回答「本段为什么是说明而不是指针」，
否则审计者只能从正文措辞猜。

**说明是引用块而不是列表项**：条目计数口径里「配套代码的条目」= 代码指针；说明不是指针，
记成条目会让契约的段计数撒谎。渲染为 `>` 行：段非空（过门禁一的非空下限）且计数为 0（不撒谎）。

**门禁一的判据不变**：硬下限仍只有「非空」。本决策改的是**该段装什么算内容**，
不是加新的判定轴——与 ADR-021/025 同一条纪律：改的是口径来源，不是判据松紧。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 补第二源代码镜像（镜像 `rust-lang/book` listings + 「行内清单→目录化」转换层） | 成本的大头是转换规则本身（一章的多个 listing 怎么拆成「一章一目录」是新设计面），且解决不了骨架侧问题——下个源若是别的形态，还得再猜一次 |
| 对象模型加代码指针字段（如 `CodePointer` 对象类型） | 动的是第 2 层提示词与判据、以及已冻结的九类对象模型——为一段的形态假设付全链改动的代价，收益与成本不成比例；若将来的源真的提供对象化代码信息，可再立卡 |

## 后果

**正面**

- rust 的 3 个候选（ch12-03-s1/s2、ch17-03-s1）在干跑中**唯一拒因消失**，门禁一放行——
  「第二源的发布门径」不再被一段形态假设挡路。
- 「空」与「无」在产物里长得不一样了：读者看到说明知道为什么没有，审计者在契约里
  看到 `codeSource.available:false` 知道这不是提取故障。
- 第一源零影响：有代码目录的章走老路径，逐字节行为不变（`npm test` 560/0 钉住）。

**负面 / 代价**

- 门禁一失去「这一段为空即拒」对**第一源镜像被误删**的兜底——但该镜像在 git 里
  （ADR-020 的 MIRROR-MANIFEST 在册），误删会被 git 而非门禁抓到；这个交换是在明面上做的。
- 来源说明的措辞进正文（含「请勿读成『源里有代码但没写』」）——正文从此承担一点元信息，
  与「产物自包含」的精神相符（读者不需要读 ADR 就能理解这段为什么长这样）。
