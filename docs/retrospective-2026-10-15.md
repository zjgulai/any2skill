# 复盘 · any2skills 全项目（2026-10-08 ～ 2026-10-15）

**复盘人视角：**以联想复盘四步法（回顾目标 → 评估结果 → 分析原因 → 总结规律）
对全项目做一次从结果出发的推演。**方法上的两条自我约束**（联想的经典要求）：
**做出成绩时多找客观原因**（防止把平台当本事）；**出现不足时多找主观原因**（防止推给环境）。
本复盘的全部事实来自盘上产物（25 张卡 / 30 篇 ADR / 2 份规格报告 / 2 份交接 / 冻结清单 /
账本 / `pipeline/registry/rejected/`），无一处凭印象——**这本身也是被复盘对象的一部分**。

---

## 一、回顾目标（当初要什么）

**大目标：**把中文技术书变成**可执行、可溯源、经质量门禁验证的 Agent Skills**——
口号化是「任何书 → skills」（the "any"）。立项时的隐含赌注：书的**结构化提取**能被
机器判据（而不是人工感觉）验证，且验证成本可控到能反复跑。

**MVP 五条验收（`docs/specs/00-mvp-plan.md` §10 原文）：**

1. 链路完整：正文 → 成品每一跳落盘、可复现；
2. 可溯源：任取成品任取一条规则，反查到书的具体位置；
3. 门禁有效：门禁一全量；门禁二有争抢/零命中实测记录；**门禁三至少检出或排除一次 negative transfer**；
4. 差异可解释：与 benchmark 22 个对照，差异有专项归因；
5. 隔离可验证：能证明生成链路未读 `benchmark/`。

**中期追加目标（MVP 达成后）：**

- **「any」的第二本书验证**（不是再跑一遍，是找一本书去**证伪**管线里的单源假设）；
- **发布质量**：门禁覆盖全部在售物，负迁移零容忍；
- **治理**：把「低效用」这个 ADR-006 写了却没定义的动作定义掉。

**目标的隐含约束（立项即立的文化）：**不静默近似、判据改动必须留痕（ADR + 追加记录）、
付过的钱不重复付（partial 复用）、任何真实运行可被账本审计。

## 二、评估结果（实际发生了什么）

### 2.1 对照五条验收——全部达成，且两条超额

| # | 标准 | 结果 | 最硬的一件证据 |
|---|---|---|---|
| 1 | 链路完整 | 达成（第一源 13 章全量 + 第二源 34/105 文件的已抽取面） | 每跳产物 + `registry/build/*` 暂存/契约/回执 |
| 2 | 可溯源 | 达成 | 每个在售契约的 `sourceRefs`（锚点+行号）逐条可解析 |
| 3 | 门禁有效 | **超额**：不是一次，是两次确认负迁移（chapter3-s1、ch13-02-iterators-s1），且第二个来自第二源 | `registry/rejected/*/REJECTION.md`（含复跑复现证据） |
| 4 | 差异可解释 | 达成：正向覆盖 22/22 + 专项归因 | `docs/specs/02-benchmark-report.md`（独立子代理执行） |
| 5 | 隔离可验证 | 达成：全程账本，**基准目录外访问 0** | 各阶段 ledger + `--verify-isolation` |

**终局数字（全部可复算）：**25 张卡、30 篇 ADR、**564 项测试 0 失败**、
发布区 **30 个 skill**（分层：**12 passed / 18 low-utility**，另有 2 个确认负迁移已下架）、
冻结面 **152 文件** + 第一源基线 45 文件（全程零漂移）、两个信息源（13 章级 + 105 节级）。

### 2.2 做得好的三件事（不谦虚，但有出处）

**① 「any」是真验证过的，不是口号的。** 第二源不是「再跑一遍」——它依次**揭穿并修复**
了管线里的单源假设：产物固定路径（5 处，见 2.3/三）、骨架对源形态的隐含假设
（配套代码段 → ADR-029 源条件骨架）、合成链对第一源主题目录的硬绑定（卡 22）。
判据（门禁口径、对象模型、ADR-004 骨架）**一条没为第二源改**——改动全部落在机制面。
第二本的书型（节级 105 文件）与第一本（章级 13 文件）差异足够真实，这个验证是有效的。

**② 门禁三的「最硬声明」兑现了两次。** 门禁三自称能检出**有害**的 skill——
chapter3-s1（词汇体系改写任务显式要求）与 ch13-02-iterators-s1（合并体、代码片段字面漂移）
两次都走了**退化→复跑→复现→下架**的完整路径。判据机器抓到了真实危害，
这是「evaluation 工具链」类项目最容易落空、而本项目真拿到了的东西。

**③ 诚实机器（冻结/账本/回执/追加记录）在赚钱而不是在耗钱。** 它反复抓到真缺陷：
5 处固定路径漏网、环 1 只落盘 16/105 的缺口、`antipattern-verdict-report` 的虚假陈述
（且有一条测试把错误文本钉成了回归）、跨章合成后 4 个在售物**陈旧**（字节一致性复查抓出）。
如果没有这套机器，这些都会变成「看起来对」的产物。

### 2.3 不足与意外（不回避，这是复盘的重点区）

| # | 事实 | 性质 |
|---|---|---|
| 1 | **效用增量稀缺**：30 个在售物 18 个 low-utility；探针（v2 更难任务）17 个任务对 0 改进 | 价值密度低于隐含期望 |
| 2 | **固定路径漏网 ×5**：clusters/candidates、跨章反模式池、门禁二/三产物、门禁二候选清单、主题三件套——同一根因，被撞到才修 | 系统性排查滞后 |
| 3 | **环 1 落盘缺口**：rust 锚点索引只落盘 16/105——「跑通过」被当成了「落盘齐」 | 清点纪律缺口 |
| 4 | **口径虚假陈述**：verdict-report 写「被拒对象不在文件里」（假），且有测试钉住 | 文档与测试互相背书错误的典型 |
| 5 | **两次误发布**：卡 19 一条核验命令漏带 `--dry-run` 实际发布（撤回）；此后重建类操作都改走显式流程 | 操作肌肉记忆 |
| 6 | **过程事故若干**：传输层断连、空内容瞬停（×N）、API 深夜整体退化、`--require` 路径解析、工具层分类器噪声拦截 | 环境噪声与工具边角 |
| 7 | **未解清单**：ch10-03 探针缺完整样本、在售物合并边（ch04-03↔ch08-02）无撤回语义、4 个未发布候选（四种缺口类）无处置、第一源 backlog 若干项 | 仍在桌面上的事 |

### 2.4 差距分析（与目标的距离）

- **对五条验收：零距离**（全达成，两条超额）。
- **对「任何书 → skills」**：已证到「第二本书全链、判据不动」——超出 MVP 设定。
- **对隐含期望「发出来的东西有用」**：**有距离，且已量化**。差距不在管线
  （准入不缺：两源共 30 个在售 + 2 个曾过门禁一后被拒），在**测量面上测不出价值增量**。
  探针把差距的解释钉在两个假设上：**H1 源内容在训练分布内**（偏支持）vs H2 仪器太温和
  （未获支持）。这个差距是**结果本身**，不是失败——但四波快跑之前，没有人问过它。

## 三、分析原因

### 3.1 成功的原因——先找客观（联想口径）

- **客观：用户的持续投入是最大的外因。** 门禁二/三、独立比对、四波抽取、合成与探针——
  这些「验证性支出」没有一次被削减。硬结论（两次负迁移、准入≠效用）全部是**真金白银
  换来的数据**，不是设计出来的。换一个预算收紧的语境，这个项目会得出漂亮但空洞的结论。
- **客观：架构让验证的边际成本低。** 机器可验证 IR + 回执 + 冻结 + partial 复用，
  使得「多跑一次验证」的成本主要只是模型调用费；换任何一个人来执行，这套机器都会同样工作。
- **客观：源与模型的时间窗口。** 强模型对两本书的内容覆盖度很高——这既是 low-utility 的
  成因，也让「提取质量」的检查（判据在抓什么）异常干净。
- **主观（承认，但不放大）：口径文化被真的执行了。**「不静默近似」「追加记录不改写原文」
  「付过的钱不重复付」写在文档里容易，25 张卡里每次有机会偷懒时都选了更贵的做法——
  这是执行纪律，是人做的选择，不是环境给的。

### 3.2 不足的原因——多找主观（联想口径）

- **固定路径漏网 ×5（最大的一个）**：根因在单源期埋下——「默认路径即唯一路径」是当时
  **合理**的简化。但真正的问题是**发现第一处（卡 19）之后没有立即做全量排查**：
  第二处到第五处都是「撞到才修」。主观改进：当时应当写一张「全部按源清点」的清单
  （把 `pipeline/` 下所有硬编码路径过一遍），一次修完；实际拖了三张卡、五处。
- **环 1 落盘缺口**：「跑通一次」≠「落盘齐备」——当时把前者的成功报告当成了后者的证据。
  主观改进：凡声称「全量 N 个」，就**清点 N**（数盘上文件），不引用跑通的日志。
- **口径虚假陈述（假陈述 + 测试钉错）**：写它的时候没有人对着产物数一遍；
  测试作者把注释的断言当成了判据来源。主观改进：**文档里的可数事实也应当可被测试检验**，
  而不是只检查文本存在性（那条测试的失败形态正是「检查了一个句子」而不是「检查了一件事」）。
- **两次误发布 + 操作事故**：对「命令的副作用」的注意力依赖流程记忆而不是**命令设计**
  （dry-run 默认化、危险命令显式确认）。卡 19 之后重建都走了显式流程——教训学得快，
  但代价是一次真实的发布-撤回。
- **低效用问题悬置过久**：卡 14 首次见到低效用（3 个），卡 25 才定义治理——中间间隔了
  两个源的证据积累。**攒证据本身合理**（3 个样本不足以定策略），但「ADR-006 写了『降级』
  却没定义」这个**已知的未完成决策**应当更早变成显式决策点（哪怕决定「先不定义」），
  而不是作为一个 backlog 项躺着。主观改进：凡 ADR 里出现未定义的动作词（「降级」
  「抽样重点」），立项时就该挂一张命名卡。

### 3.3 深层规律（两源共同验证过的）

1. **准入 ≠ 效用**。门禁一过 = 装得出来；门禁三才回答有没有用。30 个准入里 18 个
   测不出增量——把「发布数」当 KPI 的管线会在这一步静默失真。
2. **陷阱门槛 = 源的性质**。教科书式小节不在章内供给反面教材；跨章合成（ADR-016）
   是设计内正解，且在第三波被证实（门禁一 18/22 vs 第二波 5/11）。
3. **共认领不是等价关系**。稳定边只应做不相交配对，且「换目录哈希 = 全量重答」
   是机制固有的代价（规律 3，报告 §4）。
4. **测量仪器也是被测对象**。任务生成器决定「什么叫测得出的效用」；仪器要立版
   （指纹）、要探针（H1/H2 实验）、转正要走 ADR——不然测出来的只是仪器的偏好。

## 四、总结规律（固化什么，谁来做）

### 4.1 已经固化的（不用再动）

| 规律 | 固化位置 |
|---|---|
| 判据改动必须留痕、追加不重写 | ADR-021/025/028/029/030 与各自撤销的先例 |
| 付过的钱不重复付 | partial 复用 + 身份指纹（ADR-013/014） |
| 有害必下架、全证据留档 | `registry/rejected/*/REJECTION.md`（2 例） |
| 降级 = 如实披露；重测须有因 | ADR-030 + `registry/tiers.json` + README 披露块 |
| 骨架对源的隐含假设要显式化 | ADR-029（源条件骨架） |
| 产物按源命名空间 | 卡 19–22 的五处修复 + 回归测试 |

### 4.2 待固化的行动（按优先级）

1. **「固定路径审计」清单化**——教训已发生五次；立一张小卡：全仓扫硬编码
   `pipeline/` 路径，逐处标明「按源 or 显式单源」，并把检查做成能失败的东西（测试或脚本）。
   **为什么不是现在就做**：它需要设计「什么算固定路径」的判据，草率修补会制造第六种变体。
2. **在售物合并边专项**（ch04-03↔ch08-02）：需要定义「撤回语义」（下架吸收物、
   重建吸收者、审计面如何改写）——合并规则目前只覆盖发布前候选。
3. **四个未发布候选处置**（四类缺口各一）与 **ch10-03 探针补样**（单行命令在卡 25）。
4. **仪器 v2 立项与否**：探针说 H2（温和）不是问题——若继续抽章节，v1 仪器够用；
   若要让「效用轴」本身变强（一致性/长链保持率），须先立 ADR，不允许未测的轴写得像测过。
5. **剩余章节的边际决策**：报告 §8 已给口径（准入不缺、效用稀缺）——继续抽取应在
   「为发布数」还是「为验证机制」之间先做选择，别再默认「多抽就是好」。

### 4.3 复盘自身的可信度（自设的审计面）

- 本复盘依赖盘上记录；**记录缺一项，复盘就少一块**——已知缺口：两次误发布中卡 19 的那次
  只在会话里撤回、没有独立的事故文件（本复盘据会话与提交历史补记）。
- 后见之明偏差：如 3.2 对「固定路径应一次修完」的批评，在卡 19 当时第二处
  （跨章池）是同一时间发现、第三处以后才有证据知道它成规律——「早该」二字要打折读。
- 联想方法本身的要求「集思广益」在单人+Agent 的语境里只能部分满足：本复盘没有第三方
  视角；最接近的是 benchmark 的独立子代理（只覆盖比对环节）。
