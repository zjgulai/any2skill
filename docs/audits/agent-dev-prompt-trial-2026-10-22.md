# Agent 开发提示词包 · 模块 01→02 真实交互试用（2026-10-22）

## 结论

模块 01「定义边界与骨架」→ 模块 02「上下文工程」的真实交互链已跑通。

- **v1.1 核心行为成立**：先落盘，再把不确定项写进「待定」，不按默认值猜测。
- **跨模块交接成立**：模块 02 读取并继承模块 01 的边界规格，保持 `DESIGN_ONLY` 和失败关闭语义。
- **同会话续跑成立**：模块 02 提出一个边界问题后，收到答复，只对两份文档做最小增量修改，没有整份重写，也没有启用任何运行能力。
- **需要 v1.2 收敛**：提示词驱动得足够强，但可能在信息不足的空项目中提前设计过多实现细节；独立复核确认 4 个必须修、5 个建议修。本轮按证据修改通用提示词，不把试用项目的具体架构复制回模板。

这验证了完整链路：**先落盘 → 问一个问题 → 用户答复 → 原会话按最小 diff 续跑 → 自查闭环。**

## 环境与测量混杂

本轮是定性试用，不是严格 A/B，不能据此断言 v1.1 比 v1.0 省多少成本或提升多少质量。

1. 两个模块的 CLI 版本、reasoning effort 与自动路由状态不同；成本口径含 `unknown`。
2. 两次运行都自动加载了全局 skills（`brainstorming`、`tech-doc-style-chinese`、`verification-before-completion`、`claude-api`）。
3. Ultracode 指令要求 substantive task 使用 Workflow；01/02 各尝试一次 Workflow，但均被权限层以 `Review dynamic workflow before running` 拒绝，**没有实际子代理执行，也没有多代理成本**。工具调用数不能读成执行数。
4. `--allowedTools` 是预批准列表，不是完整工具隐藏机制；实际 init 仍暴露更多工具。
5. 模块 01 的原始临时产物跨日丢失，虽由转录事件逐步重建并钉了 hash，但严格试验仍应把产物、渲染后提示词与环境 manifest 写到耐久目录。
6. APFS 文件视图存在已知 4096 字节差：BSD `stat -f %z` 比真实内容字节多 4096；报告统一使用 `readFileSync().length` / `wc -c`，不用 BSD total size。

## 独立复核

两轮 Workflow 复核：

- 第一轮：3 个 reviewer + 1 synthesis，确认模块 01 交付完整，并指出内部状态机一致性与试验方法缺口。
- 第二轮：3 个 reviewer → 37 个候选问题逐条反证 → 1 synthesis，保留有文件证据的问题，输出 4 个 must + 5 个 should + 3 个 defer。

复核明确否定了「文档长就应删除」的粗糙结论。目录树、伪代码、测试清单与发布流程在实现阶段具有价值；v1.2 只处理已证实的通用提示词缺陷。

## v1.2 修订

### 10 模块统一

效率约定收紧为：设计、复核、验证均不并行扇出、不做多阶段汇总；最多一个单阶段、单只读代理；宿主强制 Workflow 时先说明冲突并限制为单阶段单代理；用户明确要求多代理时服从用户。

### 模块 01

1. 代码沙盒改为**条件式**：工具隔离与具体上限始终需要；仅在项目确需模型执行代码时才设计代码沙盒，否则明确「本版不提供代码执行」。
2. 强制人工步骤若改变正常产品节奏，必须单列「对产品行为的影响」，写清人工负担与无人可用后果，并标待确认。
3. 每个升级触发点必须写具体角色；归属不明要有明确兜底。
4. 配置基线必须覆盖正文点名的强制落点并失败关闭；否则明确标为「部分示例」。

### 模块 02

1. 原始输出先扫描凭据、审批令牌、真实目标 ID、Authorization/Cookie/Webhook 头与未清洗日志，确认安全后再进入运行制品存储；命中时写受限隔离存储并升级，不生成 `[COMPRESSED]`。
2. 状态栏每个键必须映射到上游观察允许清单；无行动价值的 token/窗口字段留在框架内部；未获批准的字段写成「待定：状态栏边界修订」。
3. 生成的系统提示词必须镜像上游指令优先级：版本化策略 / `PolicySnapshot` > `RunEnvelope` > 工具结构化结果 > 外部内容；系统提示词只是说明，不是更高权威。
4. 原始外部响应/错误详情与规范化正文分流：前者只进受限诊断存储，后者按允许通道进入上下文并标不可信。
