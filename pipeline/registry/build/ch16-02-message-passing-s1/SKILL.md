# 线程间消息传递通道实现

## 何时使用

- 当尝试在 `send` 发送值之后再次使用该值时。
- 需要从通道接收并处理多个值时。

## 核心原则

**`send` 函数获取其参数的所有权并移动这个值归接收者所有；这可以防止在发送后再次意外地使用这个值。**

所有权系统检查一切是否合乎规则，使并发错误表现为编译时错误。

**通道接收端 rx 可以被当作迭代器使用；当通道关闭时，迭代器结束。**

不再显式调用 recv 函数，而是逐个接收并打印每个接收到的值。

## 实践模式

**通道**

编程中的通道由发送者和接收者两部分组成；发送者位于上游，接收者位于下游；代码中的一部分调用发送者的方法以及希望发送的数据，另一部分则检查接收端收到的消息；当发送者或接收者任一被丢弃时，通道关闭。

- 发送者位于上游位置，在这里可以将橡皮鸭放入河中，接收者则位于下游，橡皮鸭最终会漂流至此。

**mpsc**

mpsc 是多个生产者，单个消费者的缩写；Rust 标准库实现通道的方式意味着一个通道可以有多个发送端，但只能有一个接收端。

- 多条小河小溪最终汇聚成大河，所有通过小河发出的东西最后都会来到下游的大河。

**mpsc 多生产者单消费者通道**

mpsc 是 multiple producer, single consumer 的缩写，表示通道可以有多个发送端和一个接收端，可用于创建向同一接收者发送值的多个线程。

- 示例 16-11 中的代码通过克隆通道发送端创建多个线程，向同一接收者发送值

**克隆发送者以创建多个生产者**

在创建新线程之前调用通道发送端的 clone 方法，得到可传递给第一个新建线程的发送端句柄，再把原始通道发送端传递给第二个新建线程，从而让两个线程都能向同一接收端发送不同的消息。

- 示例 16-11 在两个线程中分别通过克隆发送端和原始发送端向同一个接收端发送不同的消息

## 常见陷阱

- **在值被移动（赋值给其他变量、插入哈希 map、发送到通道、移入拥有所有权的数据结构）之后，继续访问或使用原始绑定。**
  - 后果：编译器会以 `use of moved value`（E0382）拒绝代码，防止潜在的双重释放、无效变量以及并发线程对已发送值的后续修改或丢弃导致的数据不一致。
  - 纠正：移动后不再使用原绑定；如果多个位置需要共享同一数据，在单线程场景改用 `Rc<T>` 的引用计数共享，并用 `Rc::clone` 增加计数，而不是将所有权移入单一所有者。
- **通过通道 `send` 将值发送给另一个线程后，还在当前线程继续读取或使用该值。**
  - 后果：接收线程可能先修改或丢弃该值，导致当前线程读到不一致或不存在的数据，产生错误或意外结果。
  - 纠正：接受 `send` 的所有权转移语义：发送后不再使用该值。如果确实需要保留，应在发送前克隆出独立副本。
