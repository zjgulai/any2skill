# 用模式匹配处理 Rust 变体与可反驳模式

## 何时使用

- 为枚举写分发逻辑、需要保证不漏分支时
- 只关心一个或少数变体、需要决定用 match 还是 if let 时
- 编译器报「refutable pattern」位置错误、需要定位规则时
- 评审模式匹配代码的穷举性与通配分支行为时

## 输入与前置条件

- 枚举定义与全部变体清单
- 每个分支需要执行的逻辑
- 是否需要绑定变体携带的数据

## 执行步骤

1. 开工前抄录任务的字面要求清单（文件名、命名、签名、输出格式与指定片段），实现与说明以该清单为准；技能用于判断与结构，不用于改写任务指定的表面形式。
2. 为需要完全分发的场景写穷举 match：列出全部变体，让编译器保证新变体加入时报错而非静默漏掉。
3. 需要通配分支时放在最后；确认通配不绑定数据、不吞掉需要精处理的变体。
4. 只需要匹配单个变体时用 if let（或 let else）替代整段 match，减少嵌套。
5. 核对模式位置规则：let、函数参数、for 循环只接受不可反驳模式；if let 与 while let 接受可反驳模式。
6. 解构携带数据的变体时，显式绑定需要的字段；用下划线显式忽略其余字段。
7. 编译确认穷举性与位置规则错误全部消除。

## 交付物

- 匹配代码（分支完整、顺序正确）
- match 与 if let 的选择说明
- 位置规则相关的修复记录

## 检查、停止与回滚

- 任务给定的命名与输出格式逐字保留（与字面要求清单逐项核对）。
- 新增一个变体时编译器能报出未覆盖分支（穷举性来自编译器而非人工检查）
- 通配分支位于最后且未绑定数据
- let/for/参数位置的模式均为不可反驳；可反驳模式只出现在 if let/while let
- 解构字段全部被显式使用或显式忽略
- 停止条件：穷举分析时发现枚举变体语义重叠、无法区分分支时，回到类型设计而不是加守卫硬凑
- 停止条件：遇到守卫表达式（match guard）等未覆盖语法时，暂停并说明超出范围
- 回滚：已定义。保留修改前分支结构；回滚即恢复原匹配并重新检查穷举性。

## 依据与边界

**来源规则**

- 每个 match 分支相关联的代码是一个表达式，其表达式的结果值将作为整个 match 表达式的返回值。
- 模式 `Some(i)` 与值 `Some(5)` 匹配时，变量 `i` 被绑定为 `Some` 中包含的值 `5`。
- 当某个分支的模式匹配成功时，程序会返回该分支 `=>` 右侧的值，且其他分支将不再比较。
- 在 Rust 中，匹配必须是穷举式的：必须穷举到最后的可能性来使代码有效。
- 在 match 表达式中，最后一个通配模式会匹配所有未被特殊列出的值，从而满足 match 必须穷尽的要求；通配分支必须放在最后，否则在它之后添加的其他分支永远不会被匹配到，并会触发 Rust 警告。
- 程序遇到一个使用 match 表达起来过于啰嗦的逻辑。——建议：考虑使用 if let 来简化表达。
- 当枚举值包含数据，且需要获取并使用这些值时——建议：根据你需要处理的情况数量，选择使用 `match` 或 `if let` 来获取并使用枚举值
- 函数参数、`let` 语句和 `for` 循环只能接受不可反驳的模式；`if let` 和 `while let` 表达式只能接受可反驳的模式。

**来源陷阱**

- 把 `Option<T>` 当作普通的 `T` 使用，或假设它一定有值，不处理 `None` 分支。
  - 后果：可能把空值当成有效值进行运算，造成空值错误；Rust 会因 `Option<T>` 与 `T` 类型不同而拒绝直接运算，迫使显式处理缺失情况。
  - 纠正：先用 `match` 等结构显式处理 `Some(T)` 和 `None`，取出 `T` 后再进行普通运算。
- 在 `match` 表达式中只列出部分模式，不覆盖所有可能的值。
  - 后果：编译器会拒绝编译并指出遗漏的模式；不穷尽意味着存在未处理的值。
  - 纠正：补齐所有枚举成员或可能值分支；对剩余值用捕获所有的通配模式兜底。
- 在逻辑上需要覆盖多种情况时使用 `if let` 并省略 `else`，以此替代 `match`。
  - 后果：失去 `match` 强制要求的穷尽性检查，编译器不会在遗漏情况下发出警告，可能留下未处理的逻辑分支。
  - 纠正：只有只关心一个模式并可以忽略其余值时使用 `if let`；需要穷尽检查或覆盖多个分支时使用 `match`，并为 `if let` 的其他情况添加 `else`。
- 在 `let`、函数参数或 `for` 循环中使用可能失败的可反驳模式，或者在 `if let`/`while let` 中使用总会匹配的不可反驳模式。
  - 后果：前者因无法处理不匹配的值而不能编译；后者条件永远为真、毫无意义并触发编译器警告。
  - 纠正：在 `let`、函数参数、`for` 中只使用能匹配任何值的不可反驳模式；把可反驳模式放到 `if let`/`while let` 中以处理失败可能。

**适用边界**

- 技能术语与任务字面冲突时，以任务字面为准。
- 不覆盖模式语法的完整参考（切片模式、引用模式等细节按语言文档）
- 不覆盖枚举类型本身的定义设计（见 model-rust-domain-types）
- 不覆盖 match guard 与绑定模式的高级用法
