# 诊断 Rust 借用、切片与生命周期错误

## 何时使用

- 编译器报借用冲突或悬垂引用、需要定位违反了哪条规则时
- 函数返回引用却报缺少生命周期标注、需要决定标注还是改签名时
- 设计返回字符串/切片引用的函数签名时
- 评审热点路径中的借用与切片使用、担心隐含 panic 或越界时

## 输入与前置条件

- 完整编译错误输出（含错误码与指向的行）
- 相关函数签名与数据结构定义
- 该段逻辑对「谁拥有数据、借用持续多久」的预期

## 执行步骤

1. 读完整错误：先确认错误码与最小复现段，不凭印象改代码。
2. 判定违反的规则：同一作用域多个可变借用、可变借用期间存在不可变借用、借用超出被借值的存活范围，还是返回引用缺标注。
3. 优先缩小借用跨度：用块作用域/提前 drop 收窄可变借用的生命期，让冲突自然消失，而不是到处 clone。
4. 需要跨函数返回引用时，先套用生命周期省略三规则；省略不成立时给函数或结构体补最小标注，或改成返回拥有所有权的值。
5. 切片边界检查：字符串切片按字符边界切、数组切片先验证范围，避免运行期 panic。
6. 修复后复编并在原报错场景复跑，确认错误消失且无新警告。

## 交付物

- 违反规则说明（对应错误码与规则）
- 最小修改 diff（优先缩跨度、其次补标注、最后才改所有权结构）
- 复查点清单（相邻借用、边界切片）

## 检查、停止与回滚

- 修改后原错误码消失且未引入新的借用错误
- 没有用无谓 clone 绕过冲突而未说明理由
- 所有字符串切片路径均按字符边界而非字节下标
- 返回引用的函数：省略规则适用或标注完整，二选一有明确依据
- 停止条件：修复需要改变公开 API 签名或内存布局时，暂停并确认调用方影响
- 停止条件：最小复现无法构造、错误无法稳定复现时停止，补证据再诊断
- 回滚：已定义。保留修改前版本；回滚即恢复原实现并重新评估标注方案。

## 依据与边界

**来源规则**

- 默认情况下引用是不可变的，无法通过引用修改其指向的内容。
- 不能在同一时间多次将同一数据作为可变变量借用。
- 在 Rust 中编译器确保引用永远也不会变成悬垂状态。
- 在任意给定时间，要么只能有一个可变引用，要么只能有多个不可变引用。
- 引用必须总是有效的。
- 字符串 slice range 的索引必须位于有效的 UTF-8 字符边界内
- 当拥有某值的不可变引用时，就不能再获取一个可变引用
- 当函数需要接受字符串 slice 或 `String` 值时——建议：把函数参数类型定义为字符串 slice（`&str`），而不是 `String` 引用，以使 API 更通用且不丢失功能
- Rust 中的每一个引用都有其生命周期，也就是引用保持有效的作用域。
- 当引用的生命周期以一些不同方式相关联时，Rust 需要我们使用泛型生命周期参数来注明它们的关系。
- 如果引用所指向的值在引用被使用之前离开作用域，代码不能编译。
- 在 Rust 中，如果被引用的对象比它的引用者存在的时间更短，程序会被拒绝编译。
- 当编译器不知道返回引用来自哪个输入引用时，需要为返回值添加泛型生命周期参数。
- 生命周期参数名称必须以撇号（`'`）开头；生命周期参数标注位于引用的 `&` 之后，并有一个空格将引用类型与生命周期标注分隔开。
- 当函数签名中参数和返回值使用相同的生命周期参数标注时，返回引用的生命周期必须与传入参数中较小者的生命周期一致。
- 当从函数返回一个引用，返回值的生命周期参数需要与一个参数的生命周期参数相匹配。
- 在包含引用的结构体定义中，必须在结构体名称后面的尖括号中声明泛型生命周期参数，以便在结构体定义中使用生命周期参数。
- 生命周期省略规则不提供完整推断；编译器采用三条规则来判断引用何时不需要明确的标注，并且如果检查完这三条规则后仍有引用没有计算出生命周期，编译器会停止并生成错误。这些规则适用于 fn 定义以及 impl 块。
- 如果方法有多个输入生命周期参数且其中一个参数是 &self 或 &mut self，那么所有输出生命周期参数被赋予 self 的生命周期。
- 实现方法时，结构体字段的生命周期必须总是在 `impl` 关键字之后声明并在结构体名称之后被使用。
- 当错误信息建议使用 'static 生命周期，或准备将引用指定为 'static 时——建议：先思考该引用是否真的会在整个程序生命周期内都有效，并考虑是否希望它存在这么久；大部分情况下应解决悬垂引用或生命周期不匹配问题，而不是指定 'static 生命周期。
- 在 Rust 中，生命周期参数和泛型类型参数位于函数名后的同一尖括号列表中。
- 当泛型参数会在函数比较字符串 slice 的长度之前被打印时，需要为该泛型参数指定 `Display` trait bound。
- 使用泛型类型参数、trait 和 trait bounds 以及生命周期标注所指定的引用生命周期关系时，这些机制在编译时处理，不增加运行时开销；生命周期标注保证灵活多变的代码不会出现悬垂引用。

**来源陷阱**

- 用多个与底层数据状态无关的索引变量来跟踪字符串位置
  - 后果：索引与数据可能不同步，维护起来啰嗦且易出错
  - 纠正：使用字符串 slice 解决该问题
- 尝试从函数返回 `result` 的引用，而 `result` 在函数的结尾会离开作用域并被清理。
  - 后果：产生悬垂引用；Rust 不允许创建一个悬垂引用。
  - 纠正：返回一个有所有权的数据类型而不是一个引用，由函数调用者负责清理。
- 试图通过不可变引用修改其指向的内容，或在不可变变量上创建可变引用。
  - 后果：编译器拒绝编译，防止程序在不可变语义下意外改变数据。
  - 纠正：当确需修改值时，将变量声明为 `mut` 并使用 `&mut` 可变引用；若只想读取，则保持不可变引用。
- 在同一个作用域内同时持有对同一数据的多个可变引用，或在持有不可变引用的同时创建可变引用。
  - 后果：可能造成数据竞争或未定义行为，编译器以借用冲突错误拒绝代码，避免难以追踪的运行时并发/别名 bug。
  - 纠正：用大括号块将不同借用限制在不同作用域中，或让不可变引用的最后一次使用在可变引用创建之前结束（利用 NLL），保证同一时间只有一种借用存在。
- 从函数返回指向函数内部创建值的引用，让调用方得到指向已释放内存的悬垂引用。
  - 后果：引用失效导致内存安全问题；编译器/借用检查器拒绝编译，防止悬垂引用。
  - 纠正：返回拥有所有权的数据类型（如 `String`），或让返回值生命周期与某个输入参数相关联，而不是返回局部变量的引用。
- 从集合/字符串中提取独立的数字索引（如 `usize`）作为查找结果的表示，而不是返回与底层数据绑定的引用或 slice。
  - 后果：索引与数据状态无关，在数据被修改（如 `clear`）后索引失效，造成逻辑 bug；这些 bug 通常不会立即暴露，编译器无法在编译期发现。
  - 纠正：返回字符串 slice（`&str`）或数组/集合 slice（`&[T]`），把结果的起始位置和长度与底层数据生命周期绑定，由编译器保证引用在修改/清空时失效。
- 在遇到生命周期不匹配或悬垂引用错误时，通过给引用标注 `'static` 生命周期来让代码编译通过。
  - 后果：掩盖真正的悬垂引用或生命周期不匹配问题，可能不合理地要求引用存活整个程序期间，而不是修复错误。
  - 纠正：先确认该引用是否真的必须存活整个程序；否则应修复参数与返回值之间的生命周期关系，或返回拥有所有权的数据类型，而不是使用 `'static` 绕过错误。
- 在函数返回多个输入引用之一时，省略必要的生命周期标注（例如 `fn longest(x: &str, y: &str) -> &str`）。
  - 后果：编译器报错 `missing lifetime specifier`，因为借用检查器无法确定返回值与输入引用之间的生命周期关系，从而无法保证返回引用有效。
  - 纠正：添加泛型生命周期参数 `'a`，在函数签名中标注参数和返回值，如 `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`，明确返回值与输入参数的关联。

**适用边界**

- 不覆盖 unsafe 手工管理内存的场景
- 不覆盖并发借用（Send/Sync 约束见 coordinate-rust-threads）
- 标注语义的进阶用法（高阶生命周期约束等）超出本任务范围
