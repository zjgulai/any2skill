# 控制测试运行方式

## 何时使用

- 未通过命令行参数改变 `cargo test` 的默认行为时。
- 需要将一部分命令行参数传递给 `cargo test`，而将另一部分传递给生成的测试二进制文件时。
- 运行多个测试时（Rust 默认并行运行）。
- 不希望测试并行运行，或想要更精确控制线程数量，或存在共享状态时。
- 使用 `cargo test` 运行测试，并希望查看通过测试的打印值时。
- 当负责特定位置的代码并希望只运行相关测试时。
- 需要只运行某一个测试时。
- 需要运行名称中包含 `add` 的测试，同时排除名称为 `one_hundred` 的测试时。
- 需要运行某个模块中的所有测试时。
- 当测试非常耗费时间，且希望在大多数 `cargo test` 运行中排除它时。
- 当只希望运行被忽略的测试时。

## 核心原则

**`cargo test` 生成的测试二进制文件的默认行为是并行运行所有测试，并截获测试运行过程中产生的输出，阻止它们显示出来。**

使得阅读测试结果相关的内容变得更容易。

**当需要将命令行参数分别传给 `cargo test` 和生成的测试二进制文件时，必须先列出传给 `cargo test` 的参数，接着使用分隔符 `--`，再之后列出传给测试二进制文件的参数。**

为了分隔这两种参数。

**当运行多个测试时，Rust 默认使用线程并行运行；测试不应相互依赖或依赖任何共享状态，包括当前工作目录或环境变量。**

并行运行测试更快完成、可以更快得到代码能否工作的反馈；测试同时运行时，若相互依赖或共享状态，则可能相互干扰。

**如果不希望测试并行运行，或者想要更精确控制线程数量，可向测试二进制文件传递 `--test-threads` 参数和希望使用的线程数量；例如 `--test-threads=1`。**

将测试线程设置为 `1` 告诉程序不要使用任何并行机制；虽然比并行运行花费更多时间，但在有共享状态时测试不会潜在相互干扰。

**如果希望看到通过测试中打印的值，可以在 cargo test 命令末尾增加 `--show-output` 参数来显示通过测试的输出。**

因为测试通过时这些输出会被截获，所以需要显式告知 Rust 显示通过测试的输出。

**可以通过向 cargo test 传递测试名称参数来选择运行哪些测试。**

有时运行整个测试集会耗费很长时间；负责特定位置的代码时，可能希望只运行与这些代码相关的测试。

**可以向 cargo test 传递任意测试的名称来只运行这个测试。**

cargo test 会按名称过滤测试，只运行名称匹配的测试。

**所有名字中带有 `add` 的测试会被运行，名为 `one_hundred` 的测试会被过滤掉。**

测试输出明确显示，名字中带有 `add` 的测试被运行，而 `one_hundred` 被过滤掉。

**测试所在的模块是测试名称的一部分，因此可以通过模块名来运行该模块中的所有测试。**

因为模块名是测试名称的一部分，所以模块名可以作为过滤条件来匹配并运行整个模块的测试。

**耗时的测试可以使用 `ignore` 属性来标记，以便在运行测试时排除它们。**

某些特定测试执行起来非常耗费时间，大多数运行 `cargo test` 的时候希望排除它们。

**只希望运行被忽略的测试时，使用 `cargo test -- --ignored`。**

`expensive_test` 被列为 `ignored`，因此要运行被忽略的测试需要使用 `-- --ignored`。

## 实践模式

**测试输出截获**

默认情况下，当测试通过时，Rust 的测试库会截获打印到标准输出的所有内容；通过测试中的 println! 输出不会显示，失败时则会显示所有标准输出和其他错误信息。

- 测试中调用 `println!` 且测试通过时，终端不会看到 `println!` 的输出，只会看到说明测试通过的提示行
- 测试失败时会看到所有标准输出和其他错误信息

## 常见陷阱

- **同时向 cargo test 指定多个测试名称。**
  - 后果：只有第一个值会被使用，后续测试名称被忽略。
  - 纠正：改用其他可运行多个测试的方法。
- **在默认并行运行测试时，让测试相互依赖或依赖共享状态（如共享文件、当前工作目录、环境变量）。**
  - 后果：测试并行运行时相互干扰，可能因为其他测试修改了共享状态而偶发失败，让人误判为代码错误。
  - 纠正：确保测试不依赖共享可变状态；如果必须使用共享资源，让每个测试读写独立文件或资源，或用 cargo test -- --test-threads=1 串行运行。
