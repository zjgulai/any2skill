# 用独立证据判定任务完成

## 何时使用

- 为 Agent 任务循环设计完成判定与收尾条件时
- 设计或评审提案者-审核者（生成与审查分离）流程时
- 完成声明频繁失真、需要引入独立验证时
- 多源意见需要判断是否相互独立时

## 输入与前置条件

- 任务的完成判据（可检验的验收条件）
- 可用证据通道（测试、数据来源、执行结果）及其与产出方的关系
- 验证者与审核者角色定义（谁验、谁的产出不能自证）

## 执行步骤

1. 把完成判据写成可检验的条件，明确什么证据能证明每一条。
2. 建立独立证据通道：证据来源独立于产出方（独立数据、独立执行），不仅要求「独立模型」。
3. 约定审核者约束：审核者不得修改测试、证据采集器或发布门槛；产出与评判由不共享上下文的角色承担。
4. 对多源意见做独立性抽检：同一模型、相似上下文生成的多个意见不能自动视为相互独立证据。
5. 把验证嵌入循环：发现下一件事、执行、验证、记录进度；模型可以提出完成，但批准完成的是验证器。
6. 留存验证记录：判据、证据、结论与未决项。

## 交付物

- 完成判据清单（每条对应可采信的证据）
- 验证者/审核者职责与约束定义
- 验证记录（证据、结论、未决项）

## 检查、停止与回滚

- 任何完成声明都能追溯到独立于产出方的证据
- 审核者无修改测试/门槛的权限
- 多源意见的独立性有抽检记录，同源意见未被计为多份证据
- 验证失败的下一步动作明确（修复、回退或转人工）
- 停止条件：完成判据不可检验或证据不可得时，不得宣布完成，转人工确认
- 停止条件：验证发现产出与判据系统性冲突、超出修复范围时暂停
- 回滚：不适用。本任务产出验证机制与记录；机制上线后如需回退按各自部署流程，不在本流程内定义。

## 依据与边界

**来源规则**

- 模型可以提出“完成”，但不能批准自己的“完成”。
- 审核者不能修改测试、证据采集器或发布门槛。

**来源陷阱**

- 同一模型、相似上下文生成的多个审核意见，不能自动视为相互独立的证据
  - 后果：相同决策同时冲击共享资源
  - 纠正：有意识地引入模型、上下文和数据来源的差异，并使用命名空间、资源配额和速率限制

**适用边界**

- 不含多 Agent 之间谁做验证者的拓扑选型（见 coordinate-agent-work）
- 不含安全护栏指标（见 secure-agent-actions）
- 不评估具体测试框架的用法
