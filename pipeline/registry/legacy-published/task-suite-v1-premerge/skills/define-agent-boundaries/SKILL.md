# 定义 Agent 观察、动作与职责边界

## 何时使用

- 设计新 Agent 系统、需要先划清可观察与可执行的边界时
- 评审已有系统：某项能力缺失，是提示问题、上下文问题还是工具问题
- 决定一个操作是走通用工具还是封装专用工具时
- 用「Agent = Model + Harness」口径向团队解释或重构职责分层时

## 输入与前置条件

- 任务清单与期望能力（Agent 要完成什么）
- 现有或计划中的观察通道（哪些信息进入上下文）与动作接口（哪些操作被允许）
- 运行环境与权限约束（沙盒、网络、文件范围）

## 执行步骤

1. 列出观察通道：逐项确认哪些信息真正进入上下文，未进入的信息要显式标记为不可见。
2. 列出动作接口：逐项确认哪些操作被允许，未开放的操作用户不能依赖 Agent 完成。
3. 按「没有进入上下文的等于不存在、没被动作接口允许的等于做不到」检查能力清单的缺口。
4. 把职责分到层：上下文构造、工具接口、循环与状态维护分别归 Harness 的哪一部分。
5. 对多工具场景做整合优先的粒度决策；需要专用工具时按安全权限、参数复杂度、使用频率、平台差异四类例外做取舍。
6. 把边界决策（含被排除的能力）写成记录，供后续评审对照。

## 交付物

- 观察/动作边界清单（含被显式排除的能力）
- 职责分层表（上下文、工具、循环、状态各归哪层）
- 边界决策记录（每项取舍的理由）

## 检查、停止与回滚

- 每个期望能力都能在观察通道或动作接口上找到对应入口，否则记入缺口
- 专用工具的取舍理由落在四类例外之内
- 边界之外的预期行为已显式列为非目标，而不是默认省略
- 停止条件：期望能力与运行环境约束冲突、无法在边界内实现时，暂停并交由人工裁决
- 停止条件：关键输入（任务清单或环境约束）缺失且无法从上下文推断时停止
- 回滚：不适用。本任务产出设计文档，不改动运行系统；如需废弃直接弃用记录并重新评审。

## 依据与边界

**来源规则**

- 没有通过观察通道进入上下文的信息，对模型来说就像不存在；没有被动作接口允许的操作，模型即使知道该怎么做，也只能停留在文字建议上。
- 通用基础能力用于组合与探索；专用工具用于约束高风险和强业务规则操作。
- 基于 LLM 的 Agent 应在结构化的知识体系上展开，而不是盲目随机探索。
- 当构建生产级 Agent 系统时——建议：将工程重心放在约束、验证与纠正上，确保工具调用安全、上下文得到管理、错误可纠正。
- 当需要理解 Agent = LLM + 上下文 + 工具 与 Agent = Model + Harness 的关系时，不应把后者当作与前一个公式并列的另一套划分，也不应把它当作覆盖全书十章的目录；它是同一事物在生产形态下的展开，将上下文和工具细分为上下文管理、工具接口、约束、验证、纠正五项职责，是构建部分内部的一个观察视角。

**适用边界**

- 不含具体模型选型与提示词撰写
- 不含多 Agent 协作的拓扑与冲突处理（见 coordinate-agent-work）
- 不含安全防护的具体实施（见 secure-agent-actions）
