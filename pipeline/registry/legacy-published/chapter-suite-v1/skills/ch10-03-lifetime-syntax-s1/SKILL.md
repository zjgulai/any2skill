# 生命周期标注与诊断

## 何时使用

- 任何 Rust 引用。
- 引用的生命周期以一些不同方式相关联时。
- 引用所指向的值在引用被使用之前离开作用域。
- 当 Rust 编译器在编译时比较两个生命周期的大小时。
- 函数返回引用，且返回值可能来自多个输入引用（例如 `if`/`else` 分支分别返回不同参数）。
- 在 Rust 中标注生命周期参数时。
- 函数签名中用相同生命周期参数标注多个引用参数和返回值时。
- 从函数返回一个引用时。
- 当结构体定义中包含引用字段（例如存放字符串 slice 的 `part` 字段）时。
- 适用于 fn 定义以及 impl 块。
- 当方法有多个输入生命周期参数且其中一个参数是 &self 或 &mut self 时。
- 当为带有生命周期字段的结构体实现方法时。
- 在同一个函数中同时指定生命周期参数和泛型类型参数时。
- 函数接收泛型类型参数，并在比较字符串 slice 的长度之前打印该参数时。
- 当代码使用泛型类型参数、trait 和 trait bounds 以及生命周期标注来编写既适用于多种场景又不重复的代码时。
- 当错误信息建议使用 'static 生命周期，或准备将引用指定为 'static 时

## 核心原则

**Rust 中的每一个引用都有其生命周期，也就是引用保持有效的作用域。**

生命周期被定义为引用保持有效的作用域，因此每个引用都有生命周期。

**当引用的生命周期以一些不同方式相关联时，Rust 需要我们使用泛型生命周期参数来注明它们的关系。**

这样就能确保运行时实际使用的引用绝对是有效的。

**如果引用所指向的值在引用被使用之前离开作用域，代码不能编译。**

`r` 引用的值在尝试使用之前就离开了作用域。

**在 Rust 中，如果被引用的对象比它的引用者存在的时间更短，程序会被拒绝编译。**

被引用的对象比它的引用者存在的时间更短，因此编译器拒绝编译。

**当编译器不知道返回引用来自哪个输入引用时，需要为返回值添加泛型生命周期参数。**

编译器不知道将要返回的引用是指向 `x` 还是 `y`；函数体中 `if` 块返回 `x` 的引用，`else` 块返回 `y` 的引用，因此返回值来源不确定。

**生命周期参数名称必须以撇号（`'`）开头；生命周期参数标注位于引用的 `&` 之后，并有一个空格将引用类型与生命周期标注分隔开。**

生命周期标注有着一个不太常见的语法；该语法要求将引用类型与生命周期标注分隔开。

**当函数签名中参数和返回值使用相同的生命周期参数标注时，返回引用的生命周期必须与传入参数中较小者的生命周期一致。**

返回引用的生命周期与传入参数中较小者的生命周期一致，这是由共享同一生命周期参数所表达的约束。

**当从函数返回一个引用，返回值的生命周期参数需要与一个参数的生命周期参数相匹配。**

如果返回的引用没有指向任何一个参数，那么唯一的可能就是它指向一个函数内部创建的值，它将会是一个悬垂引用，因为它将会在函数结束时离开作用域。

**在包含引用的结构体定义中，必须在结构体名称后面的尖括号中声明泛型生命周期参数，以便在结构体定义中使用生命周期参数。**

该生命周期标注意味着结构体实例不能比其引用字段存在得更久。

**生命周期省略规则不提供完整推断；编译器采用三条规则来判断引用何时不需要明确的标注，并且如果检查完这三条规则后仍有引用没有计算出生命周期，编译器会停止并生成错误。这些规则适用于 fn 定义以及 impl 块。**

省略规则并不提供完整的推断，编译器不会猜测剩余引用的生命周期，而是给出错误，这可以通过增加对应引用之间相联系的生命周期标注来解决。

**如果方法有多个输入生命周期参数且其中一个参数是 &self 或 &mut self，那么所有输出生命周期参数被赋予 self 的生命周期。**

第三条规则使得方法更容易读写，因为只需更少的符号。

**实现方法时，结构体字段的生命周期必须总是在 `impl` 关键字之后声明并在结构体名称之后被使用。**

因为这些生命周期是结构体类型的一部分。

**在 Rust 中，生命周期参数和泛型类型参数位于函数名后的同一尖括号列表中。**

生命周期也是一种泛型。

**当泛型参数会在函数比较字符串 slice 的长度之前被打印时，需要为该泛型参数指定 `Display` trait bound。**

该泛型参数会在函数比较字符串 slice 的长度之前被打印出来。

**使用泛型类型参数、trait 和 trait bounds 以及生命周期标注所指定的引用生命周期关系时，这些机制在编译时处理，不增加运行时开销；生命周期标注保证灵活多变的代码不会出现悬垂引用。**

泛型类型参数使代码适用于不同类型；trait 和 trait bounds 保证即使类型是泛型的也拥有所需行为；生命周期标注指定引用生命周期之间的关系，保证灵活多变的代码不会出现悬垂引用。

## 实践模式

**借用检查器**

借用检查器是 Rust 中决定这类代码是否被允许的机制。

- 借用检查器决定文中这段代码不被允许。

**生命周期标注**

生命周期标注告诉 Rust 多个引用的泛型生命周期参数如何相互联系；单个生命周期标注本身没有多少意义。

- 函数参数 `first` 和 `second` 都标注为 `'a`，意味着它们必须与该泛型生命周期存在得一样久。

**生命周期参数**

在函数签名中声明于函数名和参数列表间尖括号内的泛型参数，用于标注参数与返回值中引用的生命周期，以要求它们拥有相同的生命周期。

- 在示例 10-22 的 `longest` 函数中，参数与返回值中的每个引用都加上了 `'a`。

**'static 生命周期**

一种能够存活于整个程序期间的特殊生命周期；所有字符串字面量都拥有该生命周期，因为字符串文本被直接储存在程序的二进制文件中，而该文件总是可用。

- let s: &'static str = "I have a static lifetime.";

## 常见陷阱

- **尝试从函数返回 `result` 的引用，而 `result` 在函数的结尾会离开作用域并被清理。**
  - 后果：产生悬垂引用；Rust 不允许创建一个悬垂引用。
  - 纠正：返回一个有所有权的数据类型而不是一个引用，由函数调用者负责清理。
- **从函数返回指向函数内部创建值的引用，让调用方得到指向已释放内存的悬垂引用。**
  - 后果：引用失效导致内存安全问题；编译器/借用检查器拒绝编译，防止悬垂引用。
  - 纠正：返回拥有所有权的数据类型（如 `String`），或让返回值生命周期与某个输入参数相关联，而不是返回局部变量的引用。
- **在遇到生命周期不匹配或悬垂引用错误时，通过给引用标注 `'static` 生命周期来让代码编译通过。**
  - 后果：掩盖真正的悬垂引用或生命周期不匹配问题，可能不合理地要求引用存活整个程序期间，而不是修复错误。
  - 纠正：先确认该引用是否真的必须存活整个程序；否则应修复参数与返回值之间的生命周期关系，或返回拥有所有权的数据类型，而不是使用 `'static` 绕过错误。
- **在函数返回多个输入引用之一时，省略必要的生命周期标注（例如 `fn longest(x: &str, y: &str) -> &str`）。**
  - 后果：编译器报错 `missing lifetime specifier`，因为借用检查器无法确定返回值与输入引用之间的生命周期关系，从而无法保证返回引用有效。
  - 纠正：添加泛型生命周期参数 `'a`，在函数签名中标注参数和返回值，如 `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`，明确返回值与输入参数的关联。
