# Drop 清理机制

## 何时使用

- 需要在值离开作用域之前强制清理值。

## 核心原则

**当需要在值离开作用域之前强制清理值时，应使用 `std::mem::drop` 函数，而不能显式调用 `drop`。**

当值离开作用域时会自动插入 `drop` 且无法禁用，同时显式调用 `drop` 不被允许。

## 实践模式

**Drop trait**

Drop trait 允许在值离开作用域时执行一些代码，可以为任何类型提供实现；所指定的代码常用于释放文件或网络连接等资源，并且在智能指针上下文中几乎总是用于实现智能指针。

- Box<T> 自定义了 Drop 用来释放 box 所指向的堆空间。

**std::mem::drop**

用于在值离开作用域之前强制丢弃值的函数；它不同于 `Drop` trait 中的 `drop` 方法，位于 prelude。

- 示例 15-16 展示修改 `main` 来调用 `drop` 函数，并传入希望提早强制丢弃的值。

## 常见陷阱

- **在其他一些语言中，每次使用完智能指针实例后必须手动调用清理内存或资源的代码。**
  - 后果：如果忘记手动调用清理代码，运行代码的系统可能会因为负荷过重而崩溃。
  - 纠正：在 Rust 中指定每当值离开作用域时被执行的代码，由编译器自动插入这些代码，从而无需在程序中到处编写清理代码，也不会泄漏资源。
- **显式调用实现 `Drop` trait 值的 `drop` 方法。**
  - 后果：编译错误 explicit destructor calls not allowed；如果允许会导致 double free。
  - 纠正：使用 `std::mem::drop` 函数在需要时提早丢弃值。
