# 闭包创建与调用控制

## 何时使用

- 当代码存在多余的连续多次调用，或可能在完全无需其结果时调用函数时。
- 定义闭包并需要指定参数时。
- 当闭包已被第一次调用，其参数和返回值类型被锁定后。

## 核心原则

**对于一个计算函数，在同一次流程中应只调用一次，并且仅在需要其结果时才调用。**

简化后续更新步骤，并避免多余重复调用。

**闭包定义以一对竖线（|）开始，在竖线中指定闭包的参数；如果有多于一个参数，可以使用逗号分隔。**

之所以选择这个语法是因为它与 Smalltalk 和 Ruby 的闭包定义类似。

**闭包参数和返回值的类型在第一次调用时被推断并锁定；对同一闭包后续使用不同类型会导致类型错误。**

编译器在第一次调用时推断 x 和闭包返回值的类型为 String。

## 实践模式

**闭包**

Rust 中可以保存进变量或作为参数传递给其他函数的匿名函数；闭包可以在一个地方创建，然后在不同的上下文中执行，并且不同于函数，允许捕获调用者作用域中的值。

- 保存进变量
- 作为参数传递给其他函数
- 捕获调用者作用域中的值

## 常见陷阱

- **在存在部分分支不需要结果时，将昂贵计算提前统一执行，而不是按需延迟执行。**
  - 后果：所有情况都需要调用函数并等待结果，包括完全不需要该结果的分支。
  - 纠正：使用闭包将代码在程序的一个位置指定，并只在程序某处真正需要结果时执行。
- **在 `if` 块中重复调用闭包两次**
  - 后果：调用慢计算代码两次而使得用户需要多等待一倍的时间
  - 纠正：在 `if` 块中创建一个本地变量存放闭包调用的结果来解决这个问题
- **将昂贵计算的结果无条件地提前计算，或在不同分支中重复调用昂贵计算函数/闭包。**
  - 后果：不需要结果的路径也要等待，或需要的路径被重复计算，导致等待时间成倍增加。
  - 纠正：使用闭包惰性求值，并用类似 `Cacher` 的缓存结构在需要结果时最多执行一次。
