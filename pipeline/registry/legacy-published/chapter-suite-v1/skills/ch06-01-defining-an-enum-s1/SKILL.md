# 定义与使用枚举

## 何时使用

- 当需要对 `Option<T>` 类型的值执行 `T` 的运算时。
- 判断一个值是否可能为空时，且该值不是 `Option<T>` 类型。

## 核心原则

**对 `Option<T>` 进行 `T` 的运算之前，必须先将其转换为 `T`。**

这样可以捕获空值最常见的问题之一：假设某值不为空但实际上为空。

**只要一个值不是 `Option<T>` 类型，就可以安全地认定它的值不为空。**

这是 Rust 经过深思熟虑的设计决策，通过限制空值的泛滥来增加代码安全性。

## 实践模式

**枚举**

枚举用于在代码中表现某个概念，并列出可能的类型成员；这些列出的可能值称为成员。

- IpAddrKind 枚举通过列出 V4 和 V6 两个成员来表示 IP 地址类型。

**枚举成员**

枚举中列出的可能类型或值；例如 IpAddrKind 枚举中的 V4 和 V6 就是成员，英文称为 variants。

- IpAddrKind 枚举的成员包括 V4 和 V6。

**枚举成员关联数据**

枚举成员可以直接携带数据，将数据放进每个枚举成员而不依赖额外的结构体。

- `IpAddr::V4(String::from("127.0.0.1"))`
- `IpAddr::V6(String::from("::1"))`

**枚举成员处理不同类型和数量的数据**

枚举的每个成员可以处理不同类型和数量的数据，这是结构体无法做到的。

- `enum IpAddr { V4(u8, u8, u8, u8), V6(String) }`
- `let home = IpAddr::V4(127, 0, 0, 1);`

## 常见陷阱

- **把 `Option<T>` 当作普通的 `T` 使用，或假设它一定有值，不处理 `None` 分支。**
  - 后果：可能把空值当成有效值进行运算，造成空值错误；Rust 会因 `Option<T>` 与 `T` 类型不同而拒绝直接运算，迫使显式处理缺失情况。
  - 纠正：先用 `match` 等结构显式处理 `Some(T)` 和 `None`，取出 `T` 后再进行普通运算。
