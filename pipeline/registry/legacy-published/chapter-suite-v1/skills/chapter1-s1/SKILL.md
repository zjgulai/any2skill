# Agent基础与边界设计

## 何时使用

- 当 Agent 依赖观察通道感知信息、依赖动作接口执行操作时
- 当任务升级为读取表格、清洗缺失值、计算统计量并绘图时。
- 当存在支付、删除数据、发送邮件和生产部署等高风险或强业务约束操作时。
- 适用于基于 LLM 的 Agent。
- 当模型自主决策的空间越大时。
- 评估护栏时
- 执行层护栏在模型动作真正生效之前对工具操作进行验证时。
- 在执行层对模型动作进行复核时。
- Agent 超过失败阈值，或涉及敏感、不可逆或高风险操作时，尤其在部署早期或团队对 Agent 可靠性建立足够信心之前。
- 当读者需要区分全书结构骨架与 Agent = Model + Harness 的关系时
- 从第一行代码开始
- 当构建生产级 Agent 系统时

## 核心原则

**没有通过观察通道进入上下文的信息，对模型来说就像不存在；没有被动作接口允许的操作，模型即使知道该怎么做，也只能停留在文字建议上。**

观察通道与动作接口共同构成 Agent 与外部环境之间的边界，观察被转换为模型可处理的上下文，行动被转换为对环境的工具调用。

**代码必须在隔离沙盒中运行，默认不能访问网络，也不能读取授权工作目录以外的文件，并对执行时间、CPU、内存和输出大小设置上限。**

通用性会扩大出错和攻击面。

**通用基础能力用于组合与探索；专用工具用于约束高风险和强业务规则操作。**

通用工具并不总是优于专用工具；支付、删除数据、发送邮件和生产部署等高风险或强业务约束操作，应封装为参数明确、权限受限且全程可审计的专用工具。

**基于 LLM 的 Agent 应在结构化的知识体系上展开，而不是盲目随机探索。**

LLM 在推演时遵循预训练阶段沉淀的人类知识逻辑规则，如数学定律、因果关系、问题分解策略等。

**模型自主决策的空间越大，出错时的影响面也越大，因此需要更精细的约束、验证和纠正机制来确保可靠性。**

因为模型自主决策的空间越大，出错时的影响面也越大。

**护栏评估不能只测试应当拒绝的请求是否被拦截，还要测试明确允许的请求是否能够正常完成。**

护栏存在误拒绝失败：为降低危险请求被放行的概率，模型可能同时拒绝一部分合法但形式敏感的任务。

**高风险操作需额外审查或人工确认。**

工具风险评级根据操作是否可逆、权限等级、财务影响为每个工具标注低/中/高风险等级。

**执行层护栏的复核必须由上下文之外的机制完成。**

否则复核机制会和被注入的 Agent 一起沦陷。

**当 Agent 超过重试次数或操作次数的上限时，应升级到人工干预；涉及敏感、不可逆或高风险操作时，应触发人工监督，至少在团队对 Agent 可靠性建立起足够信心之前。**

人工干预是关键的保护措施，能够在不损害用户体验的情况下提升实际性能，并在部署早期帮助识别失败模式、发现边缘情况和建立健壮的评估周期。

**当需要理解 Agent = LLM + 上下文 + 工具 与 Agent = Model + Harness 的关系时，不应把后者当作与前一个公式并列的另一套划分，也不应把它当作覆盖全书十章的目录；它是同一事物在生产形态下的展开，将上下文和工具细分为上下文管理、工具接口、约束、验证、纠正五项职责，是构建部分内部的一个观察视角。**

全书的结构骨架只有一个，引言和后记反复使用的公式是 Agent = LLM + 上下文 + 工具；要避免读者记住两套骨架。

**安全问题从第一行代码就要考虑，而不是上线前打补丁。**

安全是架构问题，护栏按被绕过的难度分为上下文层、执行层与数据层三层，后续各章的安全讨论都挂在这个骨架上。

## 实践模式

**AI Agent**

AI Agent 是一种智能系统，它不再是“你问一句、它答一句”的被动对话，而是能够自主规划执行步骤、调用各种工具完成任务，并根据结果不断调整策略。

- Cursor 搜索代码库、编辑多个文件、运行测试直到通过
- Deep Research 反复搜索、阅读并总结出完整报告
- Manus 操控浏览器完成在线任务
- 豆包手机助手在手机上订票、发消息
- Pine AI 打电话给运营商协商降低账单

**Harness**

Harness 是 Agent 边界内环绕模型的运行与治理层，负责构造上下文、暴露工具接口、维护循环和状态，并实施权限、验证与纠正；它可以创建、隔离或代理一个环境，却不因此包含环境自身的状态与转移规律。

- 构造上下文
- 暴露工具接口
- 维护循环和状态
- 实施权限、验证与纠正
- 创建、隔离或代理一个环境

**上下文**

上下文是 Agent 在每个决策点收到并保留的信息表示，包括来自环境的观察、用户记忆、领域知识、自身状态和任务进展。

- 来自环境的观察
- 用户记忆
- 领域知识
- 自身状态
- 任务进展

**观察空间与动作空间**

观察通道与动作接口共同构成 Agent 与外部环境的边界；在底层模型固定时，提升任务表现的主要系统工程手段往往是重新定义或扩展观察空间与动作空间，即扩展上下文和工具。

- 把任务所需的数据纳入上下文
- 把完成任务所需的操作封装成工具

**大语言模型**

大语言模型是 Agent 的决策核心，收到用户请求后需要解析真实意图、将模糊或复杂任务拆解成可执行步骤，并在执行过程中持续判断下一步行动、工具调用和参数。

- 判断下一步该做什么
- 判断要不要调用工具、调哪个工具、传什么参数

**Harness**

在 Agent 语境中，Harness 是把模型能力引导成可靠任务执行的工程外壳，包括上下文管理、工具接口、安全约束、验证与纠正等基础设施。

- 上下文管理
- 工具接口
- 安全约束
- 验证与纠正

**上下文**

上下文由系统提示词与工具定义组成的静态前缀，以及由用户消息、模型回复与工具执行结果组成的动态消息历史共同构成，是 LLM 每次推理时的上下文。

- 系统提示词与工具定义构成静态前缀
- 用户消息、模型回复与工具执行结果构成动态消息历史

**ReAct 循环**

Agent 执行任务的核心模式，实际循环包含三个环节：模型先思考当前应该做什么，然后调用工具行动，再观察工具返回的结果并继续思考下一步，这个“想→做→看”循环不断重复直到任务完成。

- 多币种收入汇总任务

**轨迹**

Agent 在执行任务过程中不断积累的消息历史，包括用户消息、模型回复（包括思考过程和工具调用）和工具执行结果。

- 多币种收入汇总任务的轨迹

**Harness**

Harness 是 Agent 边界内、模型之外的运行与治理层，负责协调 Model 与 Environment 的交互，但不包括与之交互的环境本身。

- 工具定义
- 调用适配器
- 沙箱的权限与重置机制

**上下文工程**

第二波——人们认识到单纯优化提示词还不够，需要系统性地管理模型能看到的所有信息（系统指令、工具定义、对话历史、外部知识）。

- 系统指令
- 工具定义
- 对话历史
- 外部知识

**Harness 工程**

第三波——它将视野从“模型能看到什么”进一步扩展到“Agent 如何组织模型运行并与环境交互”，涵盖上下文与工具接口、约束机制、验证手段、反馈循环和错误恢复等 Agent 边界内、模型之外的运行与治理机制。

- 上下文与工具接口
- 约束机制
- 验证手段
- 反馈循环
- 错误恢复

**ACI（Agent-Computer Interface）**

从 Agent 视角设计工具接口，让 Agent 容易理解和使用，而非传统 API 从程序员视角设计接口。

- SIM 卡的缺角让卡片只能从一个方向插进卡槽，避免了用户插反的错误
- 微波炉门没关好就绝不加热，避免了用户开门加热的危险行为

**防呆（Poka-yoke）**

一种“用设计消除错误”的思路，在制造业中称为防呆，源自丰田生产体系。

- SIM 卡的缺角让卡片只能从一个方向插进卡槽，避免了用户插反的错误
- 微波炉门没关好就绝不加热，避免了用户开门加热的危险行为

**护栏**

保障 Agent 行为安全可控的分层防线，可用于管理数据隐私风险或声誉风险。

- 防止系统提示泄露
- 确保模型行为与品牌形象一致

**人工干预**

关键的保护措施，让 Agent 在不损害用户体验的情况下提升实际性能；实施后可让 Agent 在无法完成任务时平稳移交控制权。

- 在客户服务中，将问题升级到人工客服
- 对于 Coding Agent，将控制权交还给开发者

**提议者—审核者**

产出与评判由两个不共享上下文的角色分别承担，评判方看到的是产物本身而不是产出方的推理过程；它成立的前提是自审不可靠。

- 第三章用它更新知识
- 第四章用它做工具调用的事前审批与事后验证（Sidecar 是它的一个只读变体）
- 第五章的 PPT、视频与日志三个实验以它为骨架
- 第七章用它评估 UI
- 第九章用它审核更新提案
- 第十章讨论它在对等协作中的形态，以及为什么不能让同一个 Agent 自审

**Agent = 大脑 + 眼睛 + 手脚**

LLM 是大脑（决策核心），上下文是眼睛（决定它能看到什么），工具是手脚（决定它能做什么），三者缺一不可。

- Manus 和 OpenClaw 的演进说明通用性很大程度上来自接口边界的扩大

## 常见陷阱

- **过度依赖上下文层的提示注入防御（输入清洗、来源标记、指令数据分离），认为这些措施能提供可靠保证。**
  - 后果：上下文层只能降低攻击成功率，无法彻底阻止注入；攻击者成功注入后，Agent可能执行不可逆操作，泄露数据。
  - 纠正：把上下文层作为第一道防线，同时部署执行层工具权限控制、独立审查、沙盒隔离和数据层行级安全等分层护栏，确保即使注入成功也无法执行危险动作。

## 配套代码

- `sources/ai-agent-book-zh/code/chapter1/context/` —— 假设模型刚用计算器得到一个结果，下一轮却看不到这条工具消息。它还能可靠地继续计算吗？本实验用同一任务的不同上下文版本，帮助你理解模型的行为为什么取决于它实际收到的信息。
- `sources/ai-agent-book-zh/code/chapter1/image-gen-workflow/` —— 用户说“画一张耳机海报”，与明确指定画面、风格和文案，是两种不同的任务。本实验比较直接生成图片和先改写提示词再生成图片，学习如何判断一个工作流步骤是否真正有帮助。
- `sources/ai-agent-book-zh/code/chapter1/learning-from-experience/` —— 面对规则不完全公开的寻宝游戏，Agent 必须从行动后果中学习。本项目把表格型 Q-learning 与 LLM 的上下文学习放在同一游戏中，帮助你区分“更新参数”和“把经验留在输入中”。
- `sources/ai-agent-book-zh/code/chapter1/search-codegen/` —— “两个城市相距多远”同时包含事实查询和数值计算。只让模型凭记忆作答，难以核对数据来源；只运行程序，又缺少输入数据。本实验把搜索与代码执行串起来，观察 Agent 怎样完成这类复合任务。
- `sources/ai-agent-book-zh/code/chapter1/web-search-agent/` —— 回答一个需要新信息的问题时，模型往往不能一步结束：它先决定查什么，读到结果后再决定是否继续查。本实验用一条可见的搜索轨迹，解释“思考、行动、观察”怎样组成 Agent 循环。
