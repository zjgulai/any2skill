# RefCell内部可变性实践

## 何时使用

- 当代码使用 RefCell<T> 时。
- 当使用 `RefCell<T>` 实现内部可变性时
- 实现 trait 方法时，方法签名被 trait 定义为 `&self`，但实现中需要修改 `self` 的某个内部字段。
- 使用 `RefCell<T>` 进行借用时。
- 需要一个值有多个所有者，并且需要修改该值

## 核心原则

**RefCell<T> 只能用于单线程场景。**

RefCell<T> 与 Rc<T> 类似，同样受单线程限制。

**`RefCell<T>` 获得内部可变性时并没有完全绕开借用规则；编译器中的借用检查器允许内部可变性并相应地在运行时检查借用规则，违反这些规则会导致 panic 而不是编译错误。**

内部可变性的使用场景是让值在方法内部修改自身，而在其他代码中仍视为不可变，值方法外部的代码不能修改其值。

**当实现一个 trait 的方法时必须保持 `&self` 签名，而该方法又需要修改其内部字段时，应使用 `RefCell` 来存储该字段，以获得内部可变性并在不可变借用下修改内部值。**

因为 `send` 方法获取 `self` 的不可变引用，不能直接修改字段；也不能改用 `&mut self`，否则不符合 `Messenger` trait 定义中的签名。`RefCell` 提供内部可变性，允许在外部值被认为不可变时修改内部值。

**`RefCell<T>` 在任何时候只允许有多个不可变借用或一个可变借用。**

该约束与编译时借用规则一致，并由 `RefCell<T>` 在运行时强制执行；违反时会出现 panic。

## 实践模式

**内部可变性**

Rust 中的一种设计模式：允许在持有不可变引用时改变数据；该模式在数据结构中使用 `unsafe` 代码来模糊通常的可变性和借用规则，当能确保运行时遵守借用规则而编译器不能保证时可选用，且 `unsafe` 代码被封入安全 API，外部类型仍不可变。

- `RefCell<T>` 类型（遵循内部可变性模式）

**mock 对象**

mock 对象是特定类型的测试替身，它们记录测试过程中发生了什么以便可以断言操作是正确的。

- 在 Rust 中创建一个与 mock 对象有着相同功能的结构体

**内部可变性**

内部可变性允许在表面上不可变的值中，在需要时修改内部数据，并通过运行时借用规则检查提供保护。

- `RefCell<T>` 允许拥有一个表面上不可变的 `List`，并在需要时修改数据。

## 常见陷阱

- **对不可变局部变量 `x` 进行可变借用（`let y = &mut x;`）**
  - 后果：编译失败，编译器报错 E0596：不能将不可变局部变量 `x` 作为可变借用
  - 纠正：按编译器提示将 `x` 改为可变绑定 `mut x`
- **在同一作用域中连续调用 `borrow_mut` 创建两个可变借用。**
  - 后果：违反 `RefCell<T>` 的运行时借用规则，代码能编译通过但测试失败。
  - 纠正：不要在相同作用域同时创建两个可变借用。
- **试图通过不可变引用修改其指向的内容，或在不可变变量上创建可变引用。**
  - 后果：编译器拒绝编译，防止程序在不可变语义下意外改变数据。
  - 纠正：当确需修改值时，将变量声明为 `mut` 并使用 `&mut` 可变引用；若只想读取，则保持不可变引用。
- **在同一个作用域内同时持有对同一数据的多个可变引用，或在持有不可变引用的同时创建可变引用。**
  - 后果：可能造成数据竞争或未定义行为，编译器以借用冲突错误拒绝代码，避免难以追踪的运行时并发/别名 bug。
  - 纠正：用大括号块将不同借用限制在不同作用域中，或让不可变引用的最后一次使用在可变引用创建之前结束（利用 NLL），保证同一时间只有一种借用存在。
- **在相同作用域内通过 `RefCell<T>` 创建两个活跃的可变借用（调用两次 `borrow_mut`）。**
  - 后果：程序运行时 panic，出现 `BorrowMutError` 而不是编译错误。
  - 纠正：遵守借用规则，同一时间只允许一个可变借用或多个不可变借用，用作用域控制活动借用生命周期。
- **在 mock 对象中，当 trait 方法签名要求 `&self` 时，试图直接修改普通 `Vec` 等字段来记录调用，或把方法签名改成 `&mut self`。**
  - 后果：产生借用检查错误（如 E0596），或改变 trait 实现签名导致不符合接口，mock 无法记录消息，测试无法断言行为。
  - 纠正：使用 `RefCell<T>` 包装需要修改的内部状态，在 `&self` 方法中通过 `borrow_mut` 修改、通过 `borrow` 读取，保持 trait 签名不变。
