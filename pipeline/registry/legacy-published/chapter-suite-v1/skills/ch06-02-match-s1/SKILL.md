# match 控制流与穷举模式匹配

## 何时使用

- 当 match 表达式执行并匹配某个分支时。
- 当将枚举值 `Some(5)` 与模式 `Some(i)` 进行比较时。
- 当某个分支的模式与当前值匹配成功时。
- 编写或编译 Rust 中的 match 表达式时。
- 当 match 需要为未显式列出的值提供默认处理时。
- 程序遇到一个使用 match 表达起来过于啰嗦的逻辑。
- 当枚举值包含数据，且需要获取并使用这些值时

## 核心原则

**每个 match 分支相关联的代码是一个表达式，其表达式的结果值将作为整个 match 表达式的返回值。**

分支代码是表达式，因此其结果值可以直接作为整个 match 表达式的返回值。

**模式 `Some(i)` 与值 `Some(5)` 匹配时，变量 `i` 被绑定为 `Some` 中包含的值 `5`。**

因为 `Some(5)` 与 `Some(i)` 是相同的枚举成员，所以模式变量 `i` 绑定对应位置的值。

**当某个分支的模式匹配成功时，程序会返回该分支 `=>` 右侧的值，且其他分支将不再比较。**

因为第一个分支就匹配到了，后续分支没有继续比较的必要。

**在 Rust 中，匹配必须是穷举式的：必须穷举到最后的可能性来使代码有效。**

Rust 知道未覆盖的所有可能情况和被忘记的模式；在 Option<T> 上，这防止忘记处理 None，避免假设值实际为空，从而使这类错误不可能发生。

**在 match 表达式中，最后一个通配模式会匹配所有未被特殊列出的值，从而满足 match 必须穷尽的要求；通配分支必须放在最后，否则在它之后添加的其他分支永远不会被匹配到，并会触发 Rust 警告。**

模式是按顺序匹配的，因此最后一个通配模式可以兜底所有未列出的值；如果它不在最后，后续分支就永远没有机会被匹配。

## 实践模式

**match 控制流运算符**

Rust 中把一个值与一系列模式相比较，并按第一个匹配的模式执行对应代码的控制流运算符；编译器检查确保所有可能的情况都得到处理。

- 硬币分类器类比：值通过 match 的每一个模式，遇到第一个符合的模式时进入相关联的代码块。

**绑定值的模式**

在匹配表达式的匹配分支模式中增加变量；当匹配到 Coin::Quarter 时，变量 state 会绑定 25 美分硬币所对应州的值，之后可在该分支代码中使用该绑定。

- 在匹配 Coin::Quarter 成员的分支模式中增加 state 变量；匹配到 Coin::Quarter 时，state 绑定 25 美分硬币所对应州的值，并在分支代码中使用 state。

**枚举成员携带数据**

Rust 枚举成员可以存放数据；例如 Coin 枚举的 Quarter 成员可以包含一个 State 值。

- 修改 Coin 枚举，使 Quarter 成员包含一个 State 值。

**匹配 Option<T>**

使用 match 表达式处理 Option<T> 的成员，可以从 Some 中取出内部的 T 值；例如在获取 Option<i32> 的函数中，有值则加一，没有值则返回 None 且不执行操作。

- 编写一个获取 Option<i32> 的函数：如果其中含有一个值，将其加一；如果其中没有值，则返回 None 值，而不尝试执行任何操作。

**`_` 占位符**

`_` 是 Rust 提供的特殊模式，可以匹配任意值而不绑定到该值；它用于当我们不想使用通配模式获取的值时，告诉 Rust 我们不会使用这个值，从而不会触发未使用变量警告。

- 当掷出的值不是 3 或 7 时必须再次掷出，且不需要使用匹配值时，用 `_` 替代变量 `other`。

**if let**

if let 语法让我们以一种不那么冗长的方式结合 if 和 let，来处理只匹配一个模式的值而忽略其他模式的情况。

- if let Some(3) = some_u8_value { println!("three"); }

## 常见陷阱

- **把 `Option<T>` 当作普通的 `T` 使用，或假设它一定有值，不处理 `None` 分支。**
  - 后果：可能把空值当成有效值进行运算，造成空值错误；Rust 会因 `Option<T>` 与 `T` 类型不同而拒绝直接运算，迫使显式处理缺失情况。
  - 纠正：先用 `match` 等结构显式处理 `Some(T)` 和 `None`，取出 `T` 后再进行普通运算。
- **在 `match` 表达式中只列出部分模式，不覆盖所有可能的值。**
  - 后果：编译器会拒绝编译并指出遗漏的模式；不穷尽意味着存在未处理的值。
  - 纠正：补齐所有枚举成员或可能值分支；对剩余值用捕获所有的通配模式兜底。
- **在逻辑上需要覆盖多种情况时使用 `if let` 并省略 `else`，以此替代 `match`。**
  - 后果：失去 `match` 强制要求的穷尽性检查，编译器不会在遗漏情况下发出警告，可能留下未处理的逻辑分支。
  - 纠正：只有只关心一个模式并可以忽略其余值时使用 `if let`；需要穷尽检查或覆盖多个分支时使用 `match`，并为 `if let` 的其他情况添加 `else`。
