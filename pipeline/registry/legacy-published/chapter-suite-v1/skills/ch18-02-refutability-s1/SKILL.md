# 判断模式可反驳性与语法位置

## 何时使用

- 在 Rust 中为函数参数、`let` 语句、`for` 循环、`if let` 或 `while let` 表达式选择模式时。

## 核心原则

**函数参数、`let` 语句和 `for` 循环只能接受不可反驳的模式；`if let` 和 `while let` 表达式只能接受可反驳的模式。**

`let`、函数参数和 `for` 循环通过不匹配的值无法进行有意义的工作；`if let` 和 `while let` 根据定义意在处理可能的失败，需要根据成功或失败执行不同的操作。

## 实践模式

**可反驳模式（refutable）**

对某些可能的值进行匹配会失败的模式被称为可反驳模式。

- `if let Some(x) = a_value` 表达式中的 `Some(x)`；如果变量 `a_value` 中的值是 `None` 而不是 `Some`，那么 `Some(x)` 模式不能匹配。

## 常见陷阱

- **在 `let`、函数参数或 `for` 循环中使用可能失败的可反驳模式，或者在 `if let`/`while let` 中使用总会匹配的不可反驳模式。**
  - 后果：前者因无法处理不匹配的值而不能编译；后者条件永远为真、毫无意义并触发编译器警告。
  - 纠正：在 `let`、函数参数、`for` 中只使用能匹配任何值的不可反驳模式；把可反驳模式放到 `if let`/`while let` 中以处理失败可能。
