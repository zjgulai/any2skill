# 工具设计的通用原则

## 何时使用

- 当设计面向 Agent 使用的工具时。
- 当确实需要专用工具，且多个工具在功能相似性或使用场景上存在重叠时。
- 当确实需要对输入进行规范化处理（如统一编码格式）时，必须在工具描述中加以说明，并在工具返回中明确告知模型。
- 当工具描述缺少反例说明、LLM 可能自行猜测时
- 当 Agent 频繁选错工具时

## 核心原则

**工具应该对应 Agent 的目标，而不是底层的 API 操作。**

把每个 API 端点包成一个工具会导致粒度过细，Agent 往往要协调好几个工具才能完成一个目标。

**即使确实需要专用工具，粒度也应偏向整合而非细分。**

粒度过细会导致工具数量激增，增加 LLM 的选择负担；根据功能相似性和使用场景重叠度整合工具，可以降低认知负担、使描述更清晰并便于扩展。

**工具的参数传递必须保持透明，不得在模型不知情的情况下修改输入或输出。**

模型感知到的世界与工具操作的世界之间不能存在系统性偏差；否则工具的“智能修正”会制造模型无法自行诊断的系统性故障。

## 实践模式

**Skill**

Skill 是用自然语言编写的操作流程文档，Agent 通过终端或代码解释器逐步执行；它只需少量通用工具即可覆盖大量场景，目录条目只占几十个 token，正文用到时才读取。

- 部署应用 Skill 文档：1. 运行 npm run build 构建项目；2. 运行 docker build -t app:latest . 打包镜像；3. 运行 kubectl apply -f deploy.yaml 部署到集群，由 Agent 通过 bash 工具逐步执行。

**静默参数注入**

静默参数注入是一种保真性违规：工具在模型不知情的情况下向命令追加额外的参数。

- 某 IDE 的 bash 工具在执行所有 git commit 命令时自动附加一个额外参数，用于标记这次提交是由 AI 生成的。

## 常见陷阱

- **把每个 API 端点包成一个工具，粒度过细。**
  - 后果：Agent 往往要协调好几个工具才能完成一个目标。
  - 纠正：工具应该对应 Agent 的目标，而不是底层的 API 操作。
- **工具描述只说明“能做什么”，不说明“什么时候用/不用”、不列出边界和反例，参数也只给抽象规范而非具体示例。**
  - 后果：模型会自行猜测边界，导致工具选择错误、传参错误和输出解析错误；移除描述性文本的消融实验中工具调用错误率增加45%。
  - 纠正：为每个工具写清使用时机、边界条件（做不到什么、不接受什么输入），参数描述提供具体格式示例，并补充1-5个真实调用示例；当模型频繁选错工具时优先检查工具描述。
- **工具在参数传递层静默转换模型输入/输出，或静默注入额外参数，而不是保持透明。**
  - 后果：模型看到的内容与实际操作不一致，反复尝试却总是失败，又无法根据可见信息诊断原因，陷入困惑。
  - 纠正：参数传递必须透明：不修改模型不知情的输入输出；若必须规范化（如统一编码），应在工具描述中声明并在返回中告知模型。

## 配套代码

- `sources/ai-agent-book-zh/code/chapter4/active-tool-discovery/` —— 把全部工具说明一次塞进上下文，既占空间，也增加选择难度。本实验比较全量提供、检索预筛选和主动发现，学习如何让 Agent 在需要时找到合适的能力。
- `sources/ai-agent-book-zh/code/chapter4/active-tool-selection/` —— 随着工具数量增加，模型不仅要理解任务，还要从许多相似说明中选出合适工具。本项目让你在同一目录上比较不同选择策略，理解节省上下文可能付出的代价。
- `sources/ai-agent-book-zh/code/chapter4/collaboration-tools/` —— 有些任务需要另一个 Agent，有些需要用户作出决定，还有些只是等待外部事件。本实验把这些协作方式作为工具，学习主 Agent 怎样交出任务并接收结果。
- `sources/ai-agent-book-zh/code/chapter4/execution-tools/` —— Agent 生成一条命令，并不代表命令已经成功执行。本实验围绕执行工具学习完整动作链：接收参数、检查条件、执行操作，再把结果交回模型。
- `sources/ai-agent-book-zh/code/chapter4/multimodal-agent/` —— 回答图表问题时，模型可以直接读取图像，也可以先通过工具提取文字和数据。本实验比较几种输入路径，学习选择方式时需要考虑哪些信息可能丢失。
- `sources/ai-agent-book-zh/code/chapter4/perception-tools/` —— 模型要读取文件或查询资料，需要把现实中的数据变成结构化工具结果。本实验从 MCP 感知工具出发，学习客户端怎样发现工具、调用工具并理解返回值。
