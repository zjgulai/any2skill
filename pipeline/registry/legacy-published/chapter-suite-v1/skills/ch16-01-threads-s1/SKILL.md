# Rust 多线程任务管理

## 何时使用

- 使用 Rust 标准库提供的线程模型时。
- 当多个线程并发运行且它们的执行顺序会影响程序行为或输出时。
- 当需要修复新建线程未执行或未完整执行的问题，并确保其在 main 退出前结束运行时。
- 当主线程理论上可能使新建线程的引用无效时。

## 核心原则

**Rust 标准库只提供 1:1 线程模型实现。**

绿色线程的 M:N 模型需要更大的语言运行时来管理这些线程。

**多个线程可能轮流运行，但并不保证如此；实际调度顺序依赖操作系统如何调度线程。**

线程调度由操作系统决定，因此无法保证轮流运行。

**保存 thread::spawn 返回的 JoinHandle 并调用其 join 方法，能确保新建线程在 main 退出前结束运行。**

JoinHandle 是一个拥有所有权的值，调用 join 方法时会等待其线程结束。

**当 Rust 默认保守地只为线程借用主线程数据时，应通过 `move` 关键字将值的所有权移动到新建线程，向 Rust 保证主线程不会再使用该值；`move` 关键字覆盖 Rust 默认保守的借用，但不允许违反所有权规则。**

Rust 默认保守地只为线程借用 `v`，主线程理论上可能使新建线程的引用无效；通过将 `v` 的所有权移动到新建线程，向 Rust 保证主线程不会再使用 `v`。

## 实践模式

**线程**

运行程序内部多个同时运行的独立部分的功能。

- 将程序中的计算拆分进多个线程，以同时进行多个任务并改善性能。

**thread::spawn**

创建一个新线程需要调用 thread::spawn 函数并传递一个闭包，在闭包中包含希望在新线程运行的代码。

- 示例 16-1：主线程打印一些文本，新线程通过 thread::spawn 的闭包打印另一些文本。

**JoinHandle**

thread::spawn 的返回值类型；一个拥有所有权的值，调用其 join 方法时会等待其线程结束。

- 示例 16-2 保存 thread::spawn 的返回值 JoinHandle 并调用 join，以确保新建线程在 main 退出前结束运行。

**move 闭包**

在参数列表前使用 `move` 关键字强制闭包获取其使用的环境值的所有权，这个技巧在创建新线程将值的所有权从一个线程移动到另一个线程时最为实用。

- 创建新线程将值的所有权从一个线程移动到另一个线程时使用 `move` 闭包

## 常见陷阱

- **创建线程后不保存 `thread::spawn` 返回的 `JoinHandle`，也从不调用 `join` 等待线程完成。**
  - 后果：主线程结束时新建线程会被提前终止，甚至可能完全没有被执行；线程是否运行和运行到哪里取决于调度，无法保证。
  - 纠正：将 `thread::spawn` 的返回值存入变量，并在合适位置调用 `join` 方法阻塞当前线程，直到该线程执行完毕。
- **在 `thread::spawn` 的闭包中借用主线程的局部变量，却不同时使用 `move` 取得其所有权。**
  - 后果：新线程可能被调度到后台尚未执行，而主线程已经丢弃该值，使线程中的引用在执行时无效。
  - 纠正：对闭包使用 `move` 强制获取所用值的所有权，将值从主线程移动到新线程，避免借用失效。
- **在 `thread::spawn` 闭包中直接使用主线程数据而没有使用 `move`，依赖编译器的默认借用捕获。**
  - 后果：闭包只借用主线程数据，而新线程执行时长未知，引用可能在主线程 drop 后失效，导致编译错误或潜在悬垂。
  - 纠正：需要把数据所有权转移到新线程时，在闭包前加 `move` 关键字；注意 move 后主线程不能再使用该值。
