# 筛选、串行并观察 Rust 测试

## 何时使用

- 测试失败、需要只运行子集快速定位时
- 多个测试共享文件/端口/全局状态、并行运行时互相干扰时
- 需要临时排除慢测试或已知未完成测试时
- 测试输出看不到（被截获）需要打开可见性时

## 输入与前置条件

- 测试套件现状（用例组织与共享资源情况）
- 失败用例名称或模块路径
- 团队对并行运行与排除标记的约定

## 执行步骤

1. 全量运行一遍了解基线：默认并行执行、通过用例输出被截获，只显示失败项。
2. 定位失败：按名称精确筛选（cargo test 名称参数），必要时按模块路径收敛范围。
3. 处理共享状态：对依赖同一资源（文件、端口、环境变量）的测试用 --test-threads=1 串行运行，或在用例内自建隔离资源。
4. 标记慢/未完成用例：用 #[ignore] 标记，日常运行默认跳过，需要时用 --ignored 单独跑。
5. 向测试程序传递参数时用 -- 分隔 cargo 与测试自身参数，避免参数被 cargo 吞掉。
6. 确认结论：把失败的筛选命令、串行化结果与排除清单记入结论。

## 交付物

- 定位失败所用的筛选命令与结果
- 共享状态测试的串行运行说明
- 忽略标记清单（及恢复运行方式）

## 检查、停止与回滚

- 失败复现使用的是可复制的筛选命令，而不是「重启后碰巧过了」
- 串行化只用于确需共享资源的用例，范围最小
- 被 #[ignore] 的用例有说明与恢复运行方式，未静默弃用
- 结论记录了并行/串行与排除状态，避免误读通过率
- 停止条件：失败在串行与并行下表现不一致、怀疑测试间存在隐藏依赖时，暂停并先消除依赖
- 停止条件：套件不可运行（编译失败、环境缺失）时先修环境，不在其上解读结果
- 回滚：不适用。本任务只改变运行方式与标记，不改业务代码；如需撤销直接恢复运行命令与标记即可。

## 依据与边界

**来源规则**

- `cargo test` 生成的测试二进制文件的默认行为是并行运行所有测试，并截获测试运行过程中产生的输出，阻止它们显示出来。
- 当需要将命令行参数分别传给 `cargo test` 和生成的测试二进制文件时，必须先列出传给 `cargo test` 的参数，接着使用分隔符 `--`，再之后列出传给测试二进制文件的参数。
- 当运行多个测试时，Rust 默认使用线程并行运行；测试不应相互依赖或依赖任何共享状态，包括当前工作目录或环境变量。
- 如果不希望测试并行运行，或者想要更精确控制线程数量，可向测试二进制文件传递 `--test-threads` 参数和希望使用的线程数量；例如 `--test-threads=1`。
- 如果希望看到通过测试中打印的值，可以在 cargo test 命令末尾增加 `--show-output` 参数来显示通过测试的输出。
- 可以通过向 cargo test 传递测试名称参数来选择运行哪些测试。
- 可以向 cargo test 传递任意测试的名称来只运行这个测试。
- 所有名字中带有 `add` 的测试会被运行，名为 `one_hundred` 的测试会被过滤掉。
- 测试所在的模块是测试名称的一部分，因此可以通过模块名来运行该模块中的所有测试。
- 耗时的测试可以使用 `ignore` 属性来标记，以便在运行测试时排除它们。
- 只希望运行被忽略的测试时，使用 `cargo test -- --ignored`。

**来源陷阱**

- 同时向 cargo test 指定多个测试名称。
  - 后果：只有第一个值会被使用，后续测试名称被忽略。
  - 纠正：改用其他可运行多个测试的方法。
- 在默认并行运行测试时，让测试相互依赖或依赖共享状态（如共享文件、当前工作目录、环境变量）。
  - 后果：测试并行运行时相互干扰，可能因为其他测试修改了共享状态而偶发失败，让人误判为代码错误。
  - 纠正：确保测试不依赖共享可变状态；如果必须使用共享资源，让每个测试读写独立文件或资源，或用 cargo test -- --test-threads=1 串行运行。

**适用边界**

- 不教如何编写测试（测试写法超出本任务范围）
- 不覆盖 CI 流水线集成与并行分片
- 不覆盖基准测试运行配置
