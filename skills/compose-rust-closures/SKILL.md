# 创建、约束并缓存 Rust 闭包

## 何时使用

- 把可选或昂贵的计算封装为惰性执行时
- 需要在结构体字段或容器中存回调时
- 实现记忆化/缓存器、避免重复计算时
- 闭包报「类型不匹配」或不满足 Fn trait 约束需要定位捕获方式时

## 输入与前置条件

- 闭包的调用语义（多次调用、可能修改环境、只调用一次）
- 闭包是否需要存储（立即调用还是作为字段/参数传递）
- 函数的定义域与缓存键（做缓存时）

## 执行步骤

1. 按立即调用或存储决定参数与返回类型写法：立即调用的闭包可省略类型标注，首次调用后推断结果会锁定类型。
2. 确定捕获方式：多次只读调用用 Fn；需要修改捕获用 FnMut；消费捕获值一次用 FnOnce。存储闭包时用泛型参数加对应 bound。
3. 把闭包存进结构体：为结构体加泛型 T: Fn(..) -> ..，实例化时传入闭包并调用。
4. 实现惰性求值：用 Option 保存缓存值，首次调用时执行并填充，后续直接返回。
5. 实现带键缓存：改用 HashMap 保存「参数 → 结果」，多次调用同一参数命中缓存；注意存储闭包本身仍需 Fn bound。
6. 核对闭包捕获与生命周期：闭包借用外部变量时，存储或返回需满足其存活范围。

## 交付物

- 闭包定义与调用点（含需要的类型标注）
- 存储结构（泛型 bound 与字段）
- 缓存实现（惰性单值或按键缓存）

## 检查、停止与回滚

- 捕获方式与调用次数匹配：FnOnce 未被多次调用，FnMut 用在可变场景
- 存储闭包的结构体有正确 Fn/FnMut/FnOnce bound，编译通过
- 惰性求值只执行一次；按键缓存的键覆盖全部输入参数
- 闭包借用捕获的存活范围满足使用场景，无悬垂引用
- 停止条件：闭包需要跨线程传递或存储时，转 coordinate-rust-threads 处理并发约束
- 停止条件：需要递归闭包或自引用结构时，暂停并说明超出范围
- 回滚：已定义。保留修改前实现；回滚即恢复原函数结构并重新复跑缓存用例。

## 依据与边界

**来源规则**

- 当强度系数 < 25：输出低强度锻炼计划：建议俯卧撑和仰卧起坐，并调用 simulated_expensive_calculation 两次；当强度系数 >= 25 且 随机数 == 3：输出休息建议：稍做休息并补充水分，不调用 simulated_expensive_calculation；当强度系数 >= 25 且 随机数 != 3：输出高强度跑步计划：建议跑步数分钟，并调用 simulated_expensive_calculation 一次
- 对于一个计算函数，在同一次流程中应只调用一次，并且仅在需要其结果时才调用。
- 闭包定义以一对竖线（|）开始，在竖线中指定闭包的参数；如果有多于一个参数，可以使用逗号分隔。
- 闭包参数和返回值的类型在第一次调用时被推断并锁定；对同一闭包后续使用不同类型会导致类型错误。
- 定义使用闭包的结构体、枚举或函数参数时，需要指定闭包类型并使用泛型和 trait bound。
- 修改 `Cacher` 的缓存实现时，应使用哈希 map 以输入参数 `arg` 作为 key，并将对应 key 调用闭包的结果值作为 value 保存。
- 调整 `Cacher` 的泛型设计时，应引入更多泛型参数来增加灵活性，而不是把闭包限制为只接受 `u32` 输入并返回 `u32`。
- 需要指定一个 Fn 系列 trait bound 的时候——建议：从 Fn 开始，让编译器根据闭包体中的情况告诉你是否需要 FnMut 或 FnOnce

**来源陷阱**

- 在存在部分分支不需要结果时，将昂贵计算提前统一执行，而不是按需延迟执行。
  - 后果：所有情况都需要调用函数并等待结果，包括完全不需要该结果的分支。
  - 纠正：使用闭包将代码在程序的一个位置指定，并只在程序某处真正需要结果时执行。
- 在 `if` 块中重复调用闭包两次
  - 后果：调用慢计算代码两次而使得用户需要多等待一倍的时间
  - 纠正：在 `if` 块中创建一个本地变量存放闭包调用的结果来解决这个问题
- 将昂贵计算的结果无条件地提前计算，或在不同分支中重复调用昂贵计算函数/闭包。
  - 后果：不需要结果的路径也要等待，或需要的路径被重复计算，导致等待时间成倍增加。
  - 纠正：使用闭包惰性求值，并用类似 `Cacher` 的缓存结构在需要结果时最多执行一次。
- 实现缓存时只保存一个结果值，并假设相同参数每次都会返回相同值。
  - 后果：对不同参数调用 `value` 时仍然返回第一个缓存结果，导致错误行为。
  - 纠正：存放一个哈希 map，以传入参数作为 key 缓存对应闭包结果；并引入更多泛型参数以支持不同签名。

**适用边界**

- 不覆盖迭代器适配器链的完整用法
- 不覆盖 async 闭包与 Future 组合
- 缓存淘汰策略（LRU 等）不在范围内，按需另行设计
