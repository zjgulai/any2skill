**代码生成作为通用问题解决手段**

代码生成不只是写程序，而是一种通用的问题解决手段，可用于数学推理求解、固化业务规则、临时补充工具、动态生成解析逻辑等场景。

- 遇到数学推理，写段代码交给求解器算出精确答案
- 需要固化业务规则，用代码替代自然语言描述
- 缺少某个工具时临时写一个
- 数据格式变了动态生成解析逻辑

**元能力**

一种“能创造其他能力”的能力：Agent 用它当场写出新工具、新约束、新表达形式来完成任务，而不必事先把所有能力都预制好。

- 产出新工具（脚本、API 调用序列）
- 产出新约束（断言、校验规则）
- 产出新的表达形态（HTML 表单、PPT、视频帧）

**代码生成**

代码生成是一种元能力，具有精确、可执行、可组合的特性，因此能产出新工具、新约束和新表达形态。

- 产出新工具（脚本、API 调用序列）
- 产出新约束（断言、校验规则）
- 产出新的表达形态（HTML 表单、PPT、视频帧）

**符号计算（Symbolic Computation）**

用数学符号而非近似数值来处理表达式，以保持精确形式。

- 普通计算器会把 $\sqrt{2}$ 算成 1.414，但符号计算系统会保持 $\sqrt{2}$ 的精确形式，只在需要时才转为小数。

**提议者-审核者模式**

生成与审查分离、双模型独立评估的协作模式，即“制造者”与“验证者”分离的子 Agent。

- 本章将其用于内容质量的迭代改进：多轮循环，审核者接触到提议者看不到的新信息（渲染结果）。
- 第四章将其用于不可逆操作的安全审查，审核者对单次操作给出批准或否决。

**代码作为系统适配器**

Agent 面对外部服务没有现成 SDK、接口未必规范时，当场阅读接口文档或直接观察真实响应，即时生成适配代码；代码由此成为连接任意系统的“万能胶”，哪里接不上就现场生成一段胶水补上，属于元能力“系统接口”方向的核心。

- 日志自适应解析：面对不断演化的日志格式，Agent 现场生成解析代码来适配。
- 无 API 系统：Agent 先通过 Computer Use 操作界面，再把成功完成的操作序列用代码固化为 RPA 工具。

**生成式 UI**

一种由 Agent 动态生成表单、交互式图表甚至完整 Web 应用，从而将静态文本对话升级为多模态交互的模式。

- 动态生成表单
- 交互式图表
- 完整的 Web 应用

**代码生成**

代码生成在编程之外的广泛价值包括六个维度：思考工具、业务规则约束、多媒体生成、系统适配器、生成式 UI、Agent 自举。

- 思考工具：借助符号计算和约束求解弥补概率思考的不足
- 业务规则约束：以无歧义方式表达业务规则，在不可逆操作场景中提供确定性安全防线
- 多媒体生成：通过提议者-审核者机制创建 PPT、视频等多模态内容；代码生成与生成模型的选择取决于产物的内在复杂度与精度要求
- 系统适配器：跟随格式演化，自动完成日志解析和问题诊断
- 生成式 UI：动态创建表单、可视化图表甚至完整可定制应用，突破纯文本限制
- Agent 自举：用代码修复和创造同类 Agent，实现能创造 Agent 的 Agent

**Artifact 模式**

一种让 Agent 生成 SQL 或前端代码、由数据库和浏览器直接执行、绕过 LLM 处理大量数据的模式。

- 生成 SQL 由数据库直接执行
- 生成前端代码由浏览器直接执行

**代码即规则**

将业务规则编码为工具内部基于数据库真值的校验，并用参数设计引导模型在调用前核对政策条件，从而用代码结构约束 Agent 行为。

- 工具内部基于数据库真值的校验
- 用参数设计引导模型在调用前核对政策条件

**预算感知机制**

每一步都向提示词注入总预算与剩余预算，按照剩余预算的比例动态调整探索与利用的权重。

- 小预算（30 步）下，跳过规划和审查，直接实现核心功能并进行基本验证；大预算（300 步）下，先规划、再实现、再测试、再审查改进，并按里程碑设置检查点以评估进展，防止浅层饱和。
