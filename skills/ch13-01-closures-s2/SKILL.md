# 闭包存储与缓存实现

## 何时使用

- 当结构体、枚举或函数参数需要存放或接收闭包时。
- 当需要让 `Cacher` 按 `arg` 查找并保存闭包结果，而不是只存单独一个值时。
- 当需要让 `Cacher` 能够缓存不同签名的闭包，例如获取字符串 slice 并返回 `usize` 值的闭包时。
- 需要指定一个 Fn 系列 trait bound 的时候

## 核心原则

**定义使用闭包的结构体、枚举或函数参数时，需要指定闭包类型并使用泛型和 trait bound。**

每个闭包实例有其自己独有的匿名类型，即使签名相同类型也可能不同，因此必须通过 trait bound 来约束闭包类型。

**修改 `Cacher` 的缓存实现时，应使用哈希 map 以输入参数 `arg` 作为 key，并将对应 key 调用闭包的结果值作为 value 保存。**

相比之前检查 `self.value` 直接是 `Some` 还是 `None` 值，现在 `value` 函数会在哈希 map 中寻找 `arg`；如果不存在，`Cacher` 会调用闭包并将结果值保存在哈希 map 对应 `arg` 值的位置。

**调整 `Cacher` 的泛型设计时，应引入更多泛型参数来增加灵活性，而不是把闭包限制为只接受 `u32` 输入并返回 `u32`。**

当前实现被限制为只接受获取一个 `u32` 值并返回一个 `u32` 值的闭包，无法缓存例如获取字符串 slice 并返回 `usize` 值的闭包结果。

## 实践模式

**闭包捕获环境**

闭包可以通过三种方式捕获其环境：获取所有权、可变借用和不可变借用，分别对应 FnOnce、FnMut、Fn。FnOnce 获取所有权并消费捕获的变量，FnMut 获取可变借用，Fn 获取不可变借用。

- FnOnce 消费从周围作用域捕获的变量，必须获取其所有权，因此只能被调用一次。
- FnMut 获取可变的借用值所以可以改变其环境。
- Fn 从其环境获取不可变的借用值。

## 常见陷阱

- **实现缓存时只保存一个结果值，并假设相同参数每次都会返回相同值。**
  - 后果：对不同参数调用 `value` 时仍然返回第一个缓存结果，导致错误行为。
  - 纠正：存放一个哈希 map，以传入参数作为 key 缓存对应闭包结果；并引入更多泛型参数以支持不同签名。
