# 递归类型与 cons list 修复

## 何时使用

- 定义递归类型（如 `List`）且其成员直接存放另一个同类型值时。
- 当 Rust 需要知道为非递归枚举值分配多少空间时。
- 当只需要储存像单个 i32 这样的普通值时
- 所需功能仅为间接存储和堆分配，而不需要其他智能指针的特殊功能

## 核心原则

**在 Rust 中，像 `List` 这样的递归类型，如果其成员直接存放另一个相同类型的值，编译器会认为该类型有无限大小，且无法计算存储该类型值所需的空间。**

递归成员直接存放同类型值，使该类型大小无限，Rust 无法计算存储所需空间。

**对于非递归枚举类型，Rust 计算其值所需分配空间时，取存储其最大成员所需的空间大小。**

枚举值只会使用一个成员，因此所需空间只需容纳最大成员。

## 实践模式

**Box<T>**

Box<T> 是最简单直接的智能指针；它允许将一个值放在堆上而不是栈上，只在栈上保留指向堆数据的指针。除数据被储存在堆上而非栈上之外，box 没有性能损失，但也没有很多额外功能。

- 当有一个在编译时未知大小的类型，而又想要在需要确切大小的上下文中使用这个类型值的时候
- 当有大量数据并希望在确保数据不被拷贝的情况下转移所有权的时候
- 当希望拥有一个值并只关心它的类型是否实现了特定 trait 而不是其具体类型的时候

**Box<T>**

Box<T> 是一种通过 Box::new 在堆上储存数据并拥有其所有权的类型：Box 值指向分配在堆上的数据，可以像数据储存在栈上那样访问；当 Box 离开作用域时，会释放 box 本身（位于栈上）和所指向的数据（位于堆上）。

- 使用 let b = Box::new(5); 创建指向堆上 i32 值 5 的 Box，并像访问栈上数据一样访问 b

**递归类型**

一种无法在编译时知道大小的类型，其值的一部分可以是相同类型的另一个值。

- cons list

**cons list**

cons list 通过 `Cons` 枚举递归嵌套构造；储存列表 `1, 2, 3` 时形式为 `Cons(1, Cons(2, Cons(3, Nil)))`，最后一个值为 `Nil` 的 `List` 表示列表结尾。

- Cons(1, Cons(2, Cons(3, Nil)))

**递归类型的大小计算**

当 Rust 编译器检查包含自身的递归类型时，计算其所需内存会因某个成员包含自身类型的大小而无限进行下去。

- 示例 15-2 中的 `List` 枚举

## 常见陷阱

- **在递归类型中直接储存一个值，而不是间接地储存指向值的指针**
  - 后果：编译器无法计算出要为递归类型分配多少空间，从而给出错误
  - 纠正：插入间接存储（例如 Box、Rc 或 &），使递归类型可表示
- **在定义递归类型（如 cons list）时直接存放相同类型的成员而不插入间接层。**
  - 后果：编译器报错 recursive type `List` has infinite size，无法计算内存布局。
  - 纠正：在递归成员中插入 `Box<T>`（或 `Rc<T>`、引用）提供间接存储，使类型具有已知大小。
