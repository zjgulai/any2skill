any2skills · 项目 Playbook

把一本 md 书推进为可执行、可评测、可追溯的 Agent Skills。 本页是唯一入口文档：自动化工作流、能力图谱、已有技能资产与使用场景。

0项目总览

any2skills 是一条「内容 → 技能」流水线。它与「让大模型直接读文档写 skill」 的分界只有一条：中间存在一个机器可判定的 IR——锚点索引、类型化知识对象、 逐字引文、回执，每一步都落盘、可复算、可冻结。

它解决什么

把技术书里的知识，变成带任务骨架、显式边界、来源回链、评测档位的 Agent Skills；并且能证明每个技能为什么可以发布（或为什么是低效用）。

已跑通的两本书

ai-agent-book-zh 13 章正文 + chapter4 配套代码镜像（851 文件逐哈希校验）→ 6 个 Agent 工程技能。
rust-book-cn《Rust 程序设计语言》中文 105 个 .md（节级粒度）→ 11 个 Rust 实现技能。「any」已用第二源实证：环 1–4 零隐藏假设、发布门径全通。

三条硬纪律

① 证据面：任何数字要有盘上出处（回执/账本/冻结/lineage）。
② 诚实披露：passed / low-utility / rejected 三态如实标注，未测的轴不许写得像测过。
③ 安全默认：--layer2 缺省 stub；非 --dry-run 的 build 即发布。

1自动化工作流 · 八阶段主流程

给到一个 md 书目录，按八个阶段推进到发布、评测与披露。每阶段的验收就是它自己的产物。 编排入口：run-new-book.mjs（也可逐条手工执行）。

2环 1/2run-book --source-key锚点、对象、回执、逐文件账本≈2 次/锚点
3环 3propose-clusters --source-keyclusters / candidates≈1 次/章

「高质量」的操作性定义：① 结构合规（门禁一）② 任务化可用（策展层）③ 字面保真（条款默认内置） ④ 效用实测（门禁二三，复跑制）⑤ 全程可复算（回执+账本+冻结+lineage）⑥ 诚实披露（三态如实标注）。

2各阶段操作与陷阱

阶段 1 · 入场

node pipeline/run-new-book.mjs onboard --dir /path/to/book-dir --key <key>
  • 产物：sources/<key>/book/**.md（保留子目录）+ SOURCE-MANIFEST.md（逐文件 sha256）。
  • 约定：每本书一个 sourceKey（小写连字符，如 rust-book-cn）；一切产物按源命名空间。
  • 陷阱：目标已存在时命令拒绝覆盖——换 key 或先人工处置。

阶段 2 · 环 1/2（锚点 + 对象 + 独立判定）

node pipeline/run-new-book.mjs pipeline --key <key> --model <id> --base-url <url>
# 或手工：
node pipeline/run-book.mjs --source-key <key> --layer2 deepseek --llm-model <id> --llm-base-url <url>
  • 验收：每文件回执在盘、失败文件为 0。成本：≈2 次调用/锚点；105 文件 / 500 锚点 ≈ 千次级调用、数小时。
  • 节奏：按波推进（每波 8–10 文件），每波跑完立即可做下游。
  • 陷阱：中途瞬断直接重跑（partial 复用、重复付费为 0）；每文件独立账本路径（共用会互相覆写， 0 条记录 = 方法错误，不是证据）；别把 --layer2 stub 用进真实产物。

阶段 3 · 环 3（聚类 + 候选）

node pipeline/propose-clusters.mjs --source-key <key> --model <id> --base-url <url>
  • 验收：覆盖检查全过（未归类 0 / 未解析 id 0 / 重复归属 0 / 无候选单元 0）。
  • 输入身份一致会 0 调用复用；目录哈希变化会使门禁二全量重答（见阶段 7）。

阶段 4 · 跨章合成（可关，强烈建议）

node pipeline/propose-themes.mjs --source-key <key> --model <id> --base-url <url>
node pipeline/synthesize-antipatterns.mjs --source-key <key> --model <id> --base-url <url>
  • 为什么：教科书章节不在章内供给反面教材——跨章反模式池是「陷阱段」的正解； 实测把门禁一通过率从 5/11 拉到 18/22。
  • 验收：判定表 总/过/拒 三数可查；被拒对象也在文件里（判定表决定谁可用）。

阶段 5 · 门禁一筛查（零成本）

  • 逐候选 build-skill --dry-run 汇总 screening.<key>.json（passed / failed / failAt）。
  • 拒因两类：可修（章内真缺内容——补抽/合成补）与 内容缺口（源里就没有）。 ## 常见陷阱 空 → 找反模式章；## 核心原则 空 → 该簇无规则对象。
  • 陷阱：--dry-run 的 exit 3 是「门禁一拒」的正常信号，别当崩溃。

阶段 6 · 策展（人工面唯一的重头，核对单驱动）

node pipeline/run-new-book.mjs scaffold --key <key>
# → pipeline/curation/<key>/：task-skill-suite.v1.json（草稿）
#                          drafts/<slug>.json（工作流草案，字面保真条款默认内置）
#                          EDITORIAL-CHECKLIST.md（逐项收敛清单）
node pipeline/build-task-suite.mjs --manifest pipeline/curation/<key>/task-skill-suite.v1.json --dry-run
  • 收敛动作：任务式命名 → 步骤改写为可操作动作 → 补全输入/交付物/检查/边界 → 去掉 draft 标记并把工作流移入 workflows/。
  • 硬边界：draft:true 的工作流一律构建失败——草稿与可发布物之间没有静默通道。
  • 合并/拆分随策展进行；每次合并都要重新过「对象并集 = 来源并集、主对象不相交」的断言。

阶段 7 · 发布与评估

node pipeline/build-task-suite.mjs --manifest pipeline/curation/<key>/task-skill-suite.v1.json --publish
node pipeline/run-gate2.mjs --suite --suite-key <key> --suite-manifest pipeline/curation/<key>/task-skill-suite.v1.json --model <id> --base-url <url>
node pipeline/run-gate2.mjs --suite --suite-key <key> --suite-manifest … --blind-mode strict --model …
node pipeline/run-gate2.mjs --suite --suite-key <key> --compare
node pipeline/run-gate3.mjs --source-key <key> --model <id> --base-url <url>
  • 门禁二（触发盲测）：两读数 + 对照。先看 0 误触发 / 0 零命中；再看稳定对—— strict ≥2 且两读数都存的稳定边按「不相交最强配对」出合并建议。合并后集合重跑两读数（如实计成本）。
  • 门禁三（效用 A/B）：K=6、复跑制。三态判定：passed（≥1 改进且无确认退化）/ low-utility（无改进无退化）/ rejected（退化复跑复现——硬拒，移入 registry/rejected/<slug>/ 并写 REJECTION.md 全证据）。
  • 字面保真条款：技法类技能默认保留——「技能词汇改写任务字面」是实测的失效族死因（修订后复评 3/3 去害）。
  • 陷阱：非 --dry-run 的 build 就是发布（先干跑）；--require ./pipeline/tools/fs-ledger.cjs 的 ./ 前缀必须有；别用 shell heredoc 往既有文件追加中文（编码事故——用编辑器）。

阶段 8 · 收束

  • 评测记录：逐成员判定 + 两批次引用写进 task-suite-assessment.v1.json（或按书命名空间）；status / README / 导航同步。
  • 冻结：新书的 curation/清单、lineage、评测记录纳入冻结面，freeze-outputs --verify 逐一致；旧冻结不动（历史语义）。
  • 提交：产物、报告、记录、文档一次提交；提交信息带测试计数。

3三条快路径

① 一键编排（新书默认）

node pipeline/run-new-book.mjs all \
  --dir <书目录> --key <key> \
  --model <id> --base-url <url>

onboard → pipeline → scaffold 串行；策展草稿（含字面保真条款）自动生成， 编辑按核对单收敛后进入阶段 7。

② 替身路径（零凭据 / 零网络）

node pipeline/run.mjs sources/…/chapter4.md
node pipeline/run-book.mjs --layer2 stub

确定性替身产出，判定者不启用（回执写明门禁只完成一半）。只用于烟测与开发，绝不用于真实产物。

③ 单章 / 单技能微循环

node pipeline/build-skill.mjs --cluster <簇id> --dry-run
node pipeline/build-skill.mjs --root-anchor chapter4#h2-2 \
  --slug <slug> --title "<中文标题>" --dry-run

改动一个技能时最短闭环：改 curation → 干跑门禁一 → 重建 →（如需）重测。

4运行纪律（血泪条款）

凭据与路由

生产者 ANY2SKILLS_LLM_API_KEY；判定者 ANY2SKILLS_JUDGE_*（缺省继承生产者）。 值不写进任何文件、不进日志；shell 里用环境变量内联传入。

账本与续跑

每进程独立 DSH_FS_LEDGER；node --require ./pipeline/tools/fs-ledger.cjs。 partial 复用使中断重跑零重复付费；0 条账本记录 = 方法错误。

安全默认（会咬人）

--layer2 缺省 stub：漏写 deepseek 会用替身对象静默覆盖真实产物（可从 history 复原，但先拿到假产出）。 非 dry-run 的 build 即发布。

状态同步

改调度/计数/清单后回头改文档与 status；「文档-实物漂移不崩不空不告警」——靠巡检与冻结校验兜底。

反事实纪律：任何「A 比 B 差 N 条」的结论，先跑同条件重复对照给出噪声带——判定者同档两臂实测 13.5% 判决翻转。

5能力图谱 · 三段式链路

全链只有一个非确定性环节（第 2 层），且它的输出被第 3 层两组同权判据夹住。

第 1 层 · 确定性结构层（无 LLM）
锚点索引：行号区间 + 内容哈希 + 层级/标题。逐字节可复现。
→ pipeline/knowledge/<file>.anchors.json
▼
第 2 层 · LLM 综合层（全链路唯一非确定性环节）
类型化知识对象，强制带 sourceRefs + 逐字 evidenceQuote（引文双用途：防编造 + 语义证据）。
→ pipeline/knowledge/<file>.objects.json
▼
第 3 层 · 机器验证层 = 门禁一（两组判据，同权）
① 确定性判据（无 LLM，逐字节可复现）；② 判定者判据（LLM，独立实例、独立上下文、输入白名单三键）。
→ pipeline/registry/run-<id>.receipt.json ｜ 退出码 0 / 3（有对象被拒）/ 4（运行失败）

判定者（第 3 层的第二组判据）三条要点

  • 同模型、独立实例，路由独立可配；回执记录 sameModelAsProducer——「同模型自审」在审计时可见。
  • 只有「支撑」算通过；不充分与不支撑都拒绝，分两条理由码（两者修法不同）。
  • 输入是构造的，不是删的：只有 claim / quote / anchorText 三键，白名单守卫（多一键即报错）。

理由码（封闭词表，真源在 verifier.mjs）

码含义修复方
REFERENCE_MISSING无 sourceRefs，无豁免第 2 层输出契约
REFERENCE_UNRESOLVED出处解析不到锚点第 1 层锚点索引
SOURCE_VERSION_DRIFT依赖的锚点内容哈希已变重跑第 1 或第 2 层
QUOTE_MISSING对象根本没带引文改输出契约
QUOTE_MISMATCH引文对不上原文改归纳方式（别改写原文）
JUDGE_NOT_SUPPORTED判定者判为不支撑第 2 层引文选错了
JUDGE_INSUFFICIENT判定者判为不充分锚点切分 或 主张写得比证据宽

6环 1–5 与三道门禁

环 1 · 锚点索引
确定性切分，是所有下游引用的坐标系。
▼
环 2 · 对象提取 + 独立判定
逐锚点提取类型化对象（概念/工程规则/启发式/反模式…），判定者同批核验。
▼
环 3 · 语义聚类
章内聚类 → 内容单元 → 技能候选。覆盖检查：未归类 0 / 重复归属 0。
▼
环 4 · 确定性装配
按簇或手工子树装配 SKILL.md + skill-contract.json，装配即跑门禁一（零模型调用）。
▼
环 5 · 三道门禁（发布授权）
门禁一：结构合规（确定性）。门禁二：触发盲测（防误触发/零命中，出合并建议）。 门禁三：效用 A/B（K=6 复跑制，唯一能检出「技能有害」的装置）。

三道门禁一句话对照

门禁一 · 结构门禁二 · 触发门禁三 · 效用
问什么合不合规？该触发的触发了吗？不该触发的误触发吗？用了有没有变好？会不会变坏？
怎么测确定性检查（无 LLM）场景生成 + 盲测两段分离（题面只含 name+description）A/B 对照 + 复跑复现（K=6）
产出gate-receipt / 拒因清单两读数 + 稳定对 + 合并建议passed / low-utility / rejected
成本0≈15 次调用/skill≈13 次调用/skill
negative transfer 是真实存在的。本仓实测检出并拒绝过 2 例 （「技能词汇覆盖任务字面」失效族）——补写字面保真条款后复评全部解除并返区（两例转 low-utility、 同族一例转 passed）。rejected 的内容不随重组复活。

命名空间规则（多源参数化）

  • 缺省源（ai-agent-book-zh）的文件名逐字节不变；其他源加 .<key> 后缀 （如 cluster-input.rust-book-cn.json、antipatterns.rust-book-cn.objects.json）。
