## 三、项目定位：解决什么问题

技术书里的工程知识（怎么做、怎么避坑）很难直接变成 Agent 可用的技能：让大模型直接读书写 skill，产出的规则无法证明「真的来自书里」，也无法证明「装上比不装好」。

any2skills 的解法是在人和模型之间放一层**机器可判定的中间表示（IR）**：

- 每条知识是一个**类型化知识对象**，强制携带来源锚点（文件 + 行号区间）与逐字引文；
- 每个技能可发布或降级，都必须通过**独立于构建者的门禁**，判定留痕、可复算；
- 与「直接让模型写 skill」的分界线就在这里——**每个断言都能反查到书的具体位置**。

总体架构是双平面（ADR-002）：外层 `skills/` 遵守 Claude 技能发布规范，保证即插即用；内层 `pipeline/` 承载 IR、回执、账本与门禁，保证可审计。

## 四、主线成果

### 4.1 一条可复算的生产管线

生产核心是三段式链路，每一层职责单一：

| 层 | 职责 | 特点 |
|---|---|---|
| 第 1 层 | 确定性锚点索引 | 零模型调用，同一输入逐字节可复现 |
| 第 2 层 | LLM 综合层 | 全链唯一非确定性环节；产出强制带 `sourceRefs` + 逐字引文 |
| 第 3 层 | 机器验证（门禁一） | 确定性判据与独立判定者判据同权，全量必过 |

外层工作流分为五环：环 1/2（提取与验证）→ 环 3（章内语义聚类：13 章 → 115 单元 → 40 技能候选，593 个对象全归类）→ 环 4（确定性装配 SKILL.md，零模型调用）→ 环 5（触发盲测 + 效用 A/B）。

新书入场有一条命令推到底的编排器：`node pipeline/run-new-book.mjs all --dir <书目录> --key <sourceKey> …`（onboard → pipeline → scaffold 三段，策展草稿自动生成且带 `draft:true` 硬边界）。

### 4.2 三道质量门禁：全部建成，全部实测

这是项目最有分量的成果——不是设计了三道门禁，而是**三道都跑出了真实数据**：

| 门禁 | 回答的问题 | 实测结果 |
|---|---|---|
| 门禁一 · 契约与证据 | 每条规则真的来自书吗 | 全量必过；理由码封闭词表；逐字引文比对忽略排版差异（实测拒绝率 3.8%，零模型调用） |
| 门禁二 · 触发盲测 | 该触发时会触发吗 | 40 候选 × 120 场景、两口径共 280 次盲测 + 40 次场景生成；87 对稳定共认领 → 执行 11 对合并（候选 40→29），第三读数共认领 78→46，证明合并边际收益到顶 |
| 门禁三 · 效用 A/B | 装上比不装好吗 | K=6 配对任务、复跑制；**两次检出确认负迁移**（chapter3-s1、ch13-02-iterators-s1），均走完「退化 → 复跑复现 → 下架 → REJECTION.md 留档」全流程 |

门禁三的两次下架是项目最硬的声明兑现：「唯一能检出 skill 有害」的机制真的抓到了真实危害——这在评测工具链类项目里最容易落空。

### 4.3 「any」验证：第二本书证伪了所有单源假设

MVP 达成后，项目用《Rust 程序设计语言》中文版（105 个 md、节级粒度，与第一源「一个文件=一章」的形态完全不同）做第二源验证：

- **判据一条没改**：门禁口径、对象模型、技能骨架全部原样；
- **改动全部落在机制面**：产物按源命名空间（修复 5 处固定路径漏网）、配套代码段源条件化（ADR-029）等；
- 发布区经四波从 7 扩到峰值 30（第一源 7 + Rust 23）；Rust 侧门禁三终态 8 passed / 15 low-utility / 0 确认退化。

结论：「任何书 → skills」从口号变成了**验证过的机制**——且第二源还贡献了第二个确认负迁移案例，证明门禁三不是只对第一源有效。

### 4.4 技能资产：17 个在售任务技能

当前发布面经两代形态演进（章节技能六段 → 任务技能六段）与三轮评测收敛：

```
章节套件 30（峰值） → 重组 30→19（ADR-031，逐字节归档旧套件）
```

- **构成**：6 个 Agent 工程技能 + 11 个 Rust 实现技能；统一六段任务骨架（何时使用 / 输入与前置 / 执行步骤 / 交付物 / 检查·停止·回滚 / 依据与边界）；

## 六、诚实边界：尚未完成与技术债

一份成果总结必须同时给出边界，否则会把 MVP 说成完成品：

1. **效用增量稀缺**：17 个在售技能中 10 个 low-utility——门禁口径下测不出价值增量；探针实验（17 个任务对 0 改进）把成因指向「源内容在强模型训练分布内」（H1 偏支持），这是结果本身而非失败；
2. **卡 08 未完成**：回执理由码卡状态 ready-for-agent，10 个验收框全空；另有 40 个复选框未勾（多数属文档记账滞后）；
3. **提示词包 03–10 未真实试用**，v1.2 新条款未做交互回归；
4. **7 个契约字段无来源**（`inputContract`/`tools`/`steps` 等，当前对象模型下无出处）；
5. **4 个 Rust 候选未发布**（四类缺口各有名字），处置待决策；
6. **在售物合并边无撤回语义**（ch04-03↔ch08-02 一条 strict≥2 边，规则只覆盖发布前候选）；
7. **分发成熟度有限**：无 LICENSE、无 CI、`package.json` 为 private——「可克隆运行」已达成，「可安装即插即用」（ADR-002 的 `.claude-plugin/`）尚未落地。

## 七、可迁移的关键规律（项目自己总结的）

1. **准入 ≠ 效用**：门禁一过 = 装得出来，门禁三才回答有没有用。把「发布数」当 KPI 的管线会在这一步静默失真；
2. **陷阱门槛 = 源的性质**：教科书式小节不供给反面教材，跨章综合是设计内正解（实测门禁一通过率 5/11 → 18/22）；
3. **测量仪器也是被测对象**：任务生成器决定「什么叫测得出的效用」，仪器要立版、要探针、转正要走 ADR；
4. **降级 = 如实披露，重测须有因**：不静默近似、判据改动留痕、付过的钱不重复付——这套「诚实机器」反复抓到真缺陷，是在赚钱而不是耗钱。
